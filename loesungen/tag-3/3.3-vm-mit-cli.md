# Lösung 3.3: Dieselbe VM mit der Azure CLI, Webserver von Hand

Beispiel mit Kürzel `mm` und Kursregion `switzerlandnorth`.

## Schritt 1
```bash
az group create --name rg-tag3-cli-mm --location switzerlandnorth --tags kurs=azure-basics tag=3 owner=mm
```

## Schritt 2
```bash
KEY="ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI… mia@LAPTOP-123"
echo $KEY
```
Ausgabe: dieselbe Zeile.

## Schritt 3
```bash
az vm create --resource-group rg-tag3-cli-mm --name vm-web-mm --image Ubuntu2404 --size Standard_B1s --admin-username azureuser --ssh-key-values "$KEY" --public-ip-sku Standard
```

## Schritt 5
Eingabezeile `azureuser@vm-web-mm:~$`.

## Schritt 6
Letzte Zeilen der Installation u. a. `Setting up nginx (1.24.0-2ubuntu7) …`, keine Zeile mit `E:`.

## Schritt 7
```text
azureuser@vm-web-mm:~$ echo "<h1>Hallo von $(hostname)</h1>" | sudo tee /var/www/html/index.html
<h1>Hallo von vm-web-mm</h1>
```

## Schritt 8
```text
azureuser@vm-web-mm:~$ curl localhost
<h1>Hallo von vm-web-mm</h1>
```

## Schritt 9
Timeout im Browser, weil die NSG nur Port 22 erlaubt.

## Schritt 10
`az vm open-port` erstellt in `vm-web-mmNSG` die Regel `open-port-80` (Priorität 900). Danach zeigt `http://20.208.51.90` «Hallo von vm-web-mm».

## Schritt 11
1.

| Befehl | Wo? |
|--------|-----|
| `az vm create …` | C |
| `ssh azureuser@…` | P |
| `sudo apt install -y nginx` | V |
| `az vm open-port …` | C |

2. **Die NSG hat Port 80 blockiert.** (nginx lief schon, `curl localhost` hat funktioniert.)
3. Jeden Server einzeln einrichten wäre viel Arbeit und fehleranfällig. Besser automatisch mit einem Skript bzw. cloud-init (wie in Auftrag 1.5, in Azure an Tag 5).

## Schritt 12
`az group delete … --no-wait` gibt sofort die Eingabezeile zurück. `az group list` zeigt während 2–5 Minuten `Deleting`, danach ist die Gruppe weg.

## Zusatzaufgabe ⭐
```text
Name               ResourceGroup    Priority    SourcePortRanges    SourceAddressPrefixes    Access    Protocol    Direction    DestinationPortRanges
-----------------  ---------------  ----------  ------------------  -----------------------  --------  ----------  -----------  -----------------------
default-allow-ssh  rg-tag3-cli-mm   1000        *                   *                        Allow     Tcp         Inbound      22
open-port-80       rg-tag3-cli-mm   900         *                   *                        Allow     *           Inbound      80
```
Kleinere Zahl = höhere Priorität, die Regel wird zuerst geprüft.

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| `keyData is invalid` | `KEY` leer (Cloud Shell neu gestartet) oder abgeschnitten | Schritt 2 wiederholen |
| `--generate-ssh-keys` statt eigenem Schlüssel verwendet | aus einer Vorlage kopiert | Anmeldung dann nur aus der Cloud Shell möglich; VM löschen und mit `--ssh-key-values "$KEY"` neu erstellen |
| `SkuNotAvailable` | Grösse in der Region nicht verfügbar | `Standard_B2ats_v2` |
| `QuotaExceeded` | VM aus 3.1 noch nicht gelöscht | `rg-tag3-portal-…` löschen, warten, nochmals |
| `Could not get lock /var/lib/dpkg/lock-frontend` | Ubuntu installiert beim ersten Start Updates | 1–2 Minuten warten |
| `sudo: tee: …` / leere Seite | `>` statt `sudo tee` verwendet → keine Rechte | Befehl genau übernehmen |
| Browser zeigt «Welcome to nginx!» | `index.html` nicht geschrieben | Schritt 7 wiederholen |
| Browser versucht `https://` | automatische Umstellung | Adresse mit `http://` eintippen |

## Hinweise für die Kursleitung
- Zwei Fenster gleichzeitig (Cloud Shell und PowerShell) sind für viele neu. Beim Start an der Wandtafel skizzieren: Laptop (PowerShell, privater Schlüssel) → Internet → VM; Browser mit Cloud Shell → Azure Resource Manager.
- Schritt 9 ist absichtlich ein Fehler. Nicht vorwegnehmen.
- Brücke zu Tag 5: «Was ihr in Schritt 6 bis 8 von Hand gemacht habt, macht cloud-init automatisch.»
