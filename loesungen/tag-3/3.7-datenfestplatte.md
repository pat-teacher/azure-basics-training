# Lösung ⭐ 3.7: Daten überleben die VM – mit einer Datenfestplatte

Beispiel mit Kürzel `mm` und Kursregion `switzerlandnorth`.

## Schritt 1
```bash
az group create --name rg-tag3-disk-mm --location switzerlandnorth --tags kurs=azure-basics tag=3 owner=mm
az vm create --resource-group rg-tag3-disk-mm --name vm-a-mm --image Ubuntu2404 --size Standard_B1s --admin-username azureuser --ssh-key-values "$KEY" --public-ip-sku Standard
```
`KEY` enthält den öffentlichen Schlüssel (Public Key) wie in Auftrag 3.3, Schritt 2.

## Schritt 2
```bash
az vm disk attach --resource-group rg-tag3-disk-mm --vm-name vm-a-mm --name disk-daten-mm --new --size-gb 4 --sku Standard_LRS
az disk list --resource-group rg-tag3-disk-mm --output table
```
```text
Name                     ResourceGroup    Location          Zones    Sku           SizeGb  ProvisioningState
-----------------------  ---------------  ----------------  -------  ------------  ------  -----------------
disk-daten-mm            rg-tag3-disk-mm  switzerlandnorth           Standard_LRS  4       Succeeded
vm-a-mm_OsDisk_1_…       rg-tag3-disk-mm  switzerlandnorth           Premium_LRS   30      Succeeded
```
<!-- prüfen: Spalten von az disk list und Standard-SKU des OS-Datenträgers bei Standard_B1s -->

## Schritt 3
```text
$ lsblk
NAME    MAJ:MIN RM  SIZE RO TYPE MOUNTPOINTS
sda       8:0    0   30G  0 disk
├─sda1    8:1    0 29.9G  0 part /
…
sdb       8:16   0    4G  0 disk
└─sdb1    8:17   0    4G  0 part /mnt
sdc       8:32   0    4G  0 disk
```
`sda` = OS-Datenträger (OS Disk), `sdb` = temporärer Datenträger (Temporary Disk) unter `/mnt`, `sdc` = neue Datenfestplatte (Data Disk) ohne Mountpoint. Achtung: Bei `Standard_B1s` sind temporärer Datenträger (Temporary Disk) und Datenfestplatte (Data Disk) beide 4 GB. Unterscheidbar am Mountpoint `/mnt`. <!-- prüfen: Grösse des temporären Datenträgers bei Standard_B1s -->

```bash
sudo mkfs.ext4 /dev/sdc
sudo mkdir /daten
sudo mount /dev/sdc /daten
echo "Bestellung 1001: Citybike, 890 CHF" | sudo tee /daten/bestellungen.txt
echo "Notiz auf dem OS-Datenträger" > ~/notiz.txt
ls /daten      # bestellungen.txt  lost+found
ls ~           # notiz.txt
sudo umount /daten
exit
```

## Schritt 4
```bash
az vm delete --resource-group rg-tag3-disk-mm --name vm-a-mm --yes
az disk list --resource-group rg-tag3-disk-mm --output table
```
```text
Name                     ResourceGroup    Location          Zones    Sku           SizeGb  ProvisioningState
-----------------------  ---------------  ----------------  -------  ------------  ------  -----------------
disk-daten-mm            rg-tag3-disk-mm  switzerlandnorth           Standard_LRS  4       Succeeded
vm-a-mm_OsDisk_1_…       rg-tag3-disk-mm  switzerlandnorth           Premium_LRS   30      Succeeded
```
Beide Datenträger (Disks) sind noch da. `az vm create` setzt ohne `--os-disk-delete-option` keine Löschoption. Dann gilt «Detach»: Beim Löschen der VM werden Datenträger nur abgehängt. Dasselbe gilt für Netzwerkschnittstelle (Network Interface) und öffentliche IP (Public IP) von `vm-a-mm`. Sie bleiben und kosten, bis die Ressourcengruppe (Resource Group) gelöscht ist. <!-- prüfen: az vm show -g rg-tag3-disk-mm -n vm-a-mm --query "{os:storageProfile.osDisk.deleteOption, nic:networkProfile.networkInterfaces[0].deleteOption}" vor dem Löschen -->

## Schritt 5
```bash
az vm create --resource-group rg-tag3-disk-mm --name vm-b-mm --image Ubuntu2404 --size Standard_B1s --admin-username azureuser --ssh-key-values "$KEY" --public-ip-sku Standard --attach-data-disks disk-daten-mm
```
Auch richtig: zuerst die VM ohne Datenträger erstellen, danach `az vm disk attach --resource-group rg-tag3-disk-mm --vm-name vm-b-mm --name disk-daten-mm` (ohne `--new`).

## Schritt 6
```powershell
ssh azureuser@<neue-öffentliche-ip>
```
```text
$ lsblk            # sdc 4G ohne Mountpoint
$ sudo mkdir /daten
$ sudo mount /dev/sdc /daten
$ cat /daten/bestellungen.txt
Bestellung 1001: Citybike, 890 CHF
$ ls ~
$
```
`notiz.txt` fehlt: Die neue VM hat einen frischen OS-Datenträger (OS Disk) aus dem Image.

## Schritt 7
1. `notiz.txt`: ist weg. `bestellungen.txt`: überlebt.
2. Beide Datenträger (Disks): `disk-daten-mm` und der alte OS-Datenträger (OS Disk) von `vm-a-mm`. Datenträger kosten, solange sie existieren, auch ohne VM. Vergessene Datenträger sind eine typische Kostenfalle.
3. Zwei von: Datenfestplatte (Data Disk), Blob-Speicher (Blob Storage), Azure Files, eine Datenbank. Nicht: OS-Datenträger (OS Disk), temporärer Datenträger (Temporary Disk).

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| `QuotaExceeded` | VM aus 3.3 läuft noch | alte Ressourcengruppe (Resource Group) löschen |
| Daten in Schritt 6 weg | in Schritt 6 nochmals `mkfs.ext4` ausgeführt | erklären: `mkfs` formatiert; Auftrag ab Schritt 3 wiederholen |
| `mkfs` auf `sdb` | temporären Datenträger (Temporary Disk) erwischt (gleich gross) | nur ohne Mountpoint wählen; bei `sdb` mit `/mnt` abbrechen |
| `az vm disk attach` meldet, die Disk existiert schon | `--new` beim Wiederanhängen | ohne `--new` |
| ganze Ressourcengruppe (Resource Group) in Schritt 4 gelöscht | `az group delete` statt `az vm delete` | neu beginnen; Lerneffekt nutzen |

## Hinweise für die Kursleitung
- Für Lernstarke, die 3.3 früh fertig haben (L4) oder in L7 statt ⭐ 3.6. Nur starten, wenn keine andere VM läuft. Wer nicht fertig wird, räumt trotzdem am Schluss der Lektion auf (laufende VM kostet) und macht später neu.
- Kosten: zwei kurze VM-Laufzeiten und 4 GB Standard-Datenträger, insgesamt Rappenbeträge, sofern am Schluss aufgeräumt wird.
- Die Verwechslungsgefahr zwischen temporärem Datenträger (Temporary Disk) und Datenfestplatte (Data Disk) (beide 4G bei B1s) ist gewollt eine Denkaufgabe. Im Zweifel `lsblk` gemeinsam anschauen.
- Vorab mit dem eigenen Konto testen: Gerätenamen (`sdc`), Standard-Löschoptionen bei `az vm delete`. <!-- prüfen -->
