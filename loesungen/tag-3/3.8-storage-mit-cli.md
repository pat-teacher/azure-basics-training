# Lösung ⭐ 3.8: Speicherkonto ganz mit der CLI – hochladen, abfragen, retten, teilen

Beispiel mit Kürzel `mm` und Kursregion `switzerlandnorth`.

## Schritt 1
```bash
az group create --name rg-tag3-st-mm --location switzerlandnorth --tags kurs=azure-basics tag=3 owner=mm
az storage account create --resource-group rg-tag3-st-mm --name sttag3climm --sku Standard_LRS --kind StorageV2
```
Die Region muss nicht angegeben werden, sie kommt von der Ressourcengruppe (Resource Group). Mit `--location switzerlandnorth` ist es auch richtig.

## Schritt 2
```bash
ST=sttag3climm
STKEY=$(az storage account keys list --resource-group rg-tag3-st-mm --account-name $ST --query "[0].value" --output tsv)
echo ${#STKEY}
```
Ausgabe: `88`.

## Schritt 3
```bash
az storage container create --name preise --account-name $ST --account-key $STKEY
az storage blob upload-batch --destination preise --source preise --account-name $ST --account-key $STKEY
```
`container create` gibt `{"created": true}` aus. `upload-batch` listet die drei hochgeladenen Dateien.

## Schritt 4
```bash
az storage blob list --container-name preise --account-name $ST --account-key $STKEY --query "[].{Name:name, Bytes:properties.contentLength, Ebene:properties.blobTier}" --output table
```
```text
Name            Bytes    Ebene
--------------  -------  -------
citybike.txt    18       Hot
ebike.txt       17       Hot
kindervelo.txt  20       Hot
```
<!-- prüfen: Zeigt properties.blobTier bei abgeleiteter Ebene «Hot» an oder bleibt das Feld leer? -->

## Schritt 5
```bash
az storage blob set-tier --container-name preise --name ebike.txt --tier Cool --account-name $ST --account-key $STKEY
```
Danach zeigt die Tabelle bei `ebike.txt` **Cool**.

## Schritt 6
```bash
az storage account blob-service-properties update --resource-group rg-tag3-st-mm --account-name $ST --enable-delete-retention true --delete-retention-days 7
az storage blob delete --container-name preise --name citybike.txt --account-name $ST --account-key $STKEY
az storage blob list --container-name preise --account-name $ST --account-key $STKEY --output table
az storage blob list --container-name preise --include d --account-name $ST --account-key $STKEY --query "[].{Name:name, Geloescht:deleted}" --output table
az storage blob undelete --container-name preise --name citybike.txt --account-name $ST --account-key $STKEY
```
Nach dem Löschen fehlt `citybike.txt` in der normalen Liste. Mit `--include d` erscheint sie mit `Geloescht: True`. Nach `undelete` ist sie wieder normal da.
<!-- prüfen: Spaltenname «deleted» in der Ausgabe von az storage blob list --include d -->

## Schritt 7
```bash
ABLAUF=$(date -u -d "+15 minutes" '+%Y-%m-%dT%H:%MZ')
URL=$(az storage blob generate-sas --container-name preise --name citybike.txt --permissions r --expiry $ABLAUF --full-uri --account-name $ST --account-key $STKEY --output tsv)
curl "$URL"
curl "${URL%%\?*}"
```
Erster `curl`: `Citybike: 890 CHF`. Zweiter `curl` (ohne Token): Fehlermeldung in XML, z. B. `PublicAccessNotPermitted` oder `ResourceNotFound`, weil der Container privat ist.

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| Warnung «There are no credentials provided …» | `--account-key` fehlt; nur eine Warnung, die CLI holt den Schlüssel selbst | `--account-name $ST --account-key $STKEY` anhängen |
| `AuthenticationFailed` / `AuthorizationFailure` | `STKEY` leer oder falsch | Schritt 2 wiederholen |
| `--sku Standard` → Fehler | Leistung und Redundanz (Redundancy) gehören zusammen | `Standard_LRS` |
| `upload-batch` lädt `preise/preise/…` | `--source .` statt `preise` | Container leeren oder neu, richtige Quelle |
| `undelete` ohne Wirkung | Soft Delete erst nach dem Löschen eingeschaltet | Reihenfolge: einschalten, dann löschen |
| `date: invalid date` | Befehl in PowerShell statt Cloud Shell | in der Cloud Shell (Bash) ausführen |
| Zugriffsschlüssel (Access Key) im Lernjournal | `echo $STKEY` und kopiert | Schlüssel im Portal neu erzeugen (rotieren), Eintrag löschen |

## Hinweise für die Kursleitung
- Für Lernstarke in L7, die 3.5 fertig haben, als Alternative zu ⭐ 3.6. Kein Portal nötig, keine VM, Kosten im Rappenbereich.
- Bewusst mit `--account-key` statt `--auth-mode login`: Für `login` braucht es die Rolle (Role) «Storage Blob Data Contributor», die auch ein Besitzer (Owner) des Abonnements (Subscription) nicht automatisch hat. Voraussetzung für `--account-key`: Keine Richtlinie (Policy) verbietet den Zugriff per Schlüssel (`allowSharedKeyAccess`). <!-- prüfen: Shared Key im Student-Abo erlaubt -->
- Schritt 7 wiederholt 3.6 mit der CLI. Wer 3.6 nicht gemacht hat, schafft es trotzdem mit den Tipps.
- Gesprächsanlass: Schritt 8, Frage 3 (Generalschlüssel und zeitlich begrenzter Link).
