# Lösung 3.4: Speicherkonto und Blob-Container, Dateien hochladen

Beispiel mit Kürzel `mm` und Kursregion `switzerlandnorth`.

## Schritt 1
```bash
az group create --name rg-tag3-storage-mm --location switzerlandnorth --tags kurs=azure-basics tag=3 owner=mm
```

## Schritt 2
Speicherkonto (Storage Account) `sttag3mm`, Leistung (Performance) **Standard**, Redundanz (Redundancy) **LRS**. Alle anderen Reiter mit Standardwerten. Erstellen dauert ca. 30–60 Sekunden.

## Schritt 3
Blob-Dienst: `https://sttag3mm.blob.core.windows.net/`

## Schritt 4
Container `dateien`, anonymer Zugriff (Anonymous Access) **Privat** (Private). Bei neuen Speicherkonten (Storage Accounts) ist anonymer Zugriff auf Kontoebene ohnehin ausgeschaltet. Andere Optionen sind dann gar nicht wählbar.

## Schritt 5
Blob `preisliste.txt`, ca. 70 B, Zugriffsebene (Access Tier) **Hot** (abgeleitet vom Standard des Speicherkontos).

## Schritt 6
```xml
<Error>
  <Code>PublicAccessNotPermitted</Code>
  <Message>Public access is not permitted on this storage account. …</Message>
</Error>
```
<!-- prüfen: Stand 08.11.2026 – je nach Einstellung auch ResourceNotFound -->

## Schritt 7
Zugriffsebene (Access Tier) **Cool**. Achtung: Cool hat eine Mindestdauer von 30 Tagen. Wer die Datei vorher löscht (beim Aufräumen), zahlt eine Gebühr für vorzeitiges Löschen. Bei 70 Byte sind das Bruchteile eines Rappens.

## Schritt 8
1. Bei LRS speichert Azure **drei** Kopien meiner Daten in **einem** Rechenzentrum.
2.

| Fall | Zugriffsebene (Access Tier) |
|------|------------------------------|
| Bilder im Webshop | Hot |
| Backup vom letzten Monat | Cool |
| Buchhaltung von 2019 | Archive |

3. **Der Container ist privat, nur Berechtigte dürfen lesen.**

## Zusatzaufgabe ⭐
Inhaltstyp z. B. `image/jpeg`. Der Browser erkennt daran, ob er die Datei anzeigen (Bild) oder herunterladen soll.

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| Name «bereits vergeben» | gleiche Initialen wie jemand anderes weltweit | zwei Ziffern anhängen |
| Name «ungültig» | Bindestrich oder Grossbuchstabe | nur `a–z` und `0–9` |
| «Sie haben keine Berechtigung, die Daten aufzulisten» | Portal nutzt Microsoft Entra ID statt Zugriffsschlüssel (Access Key), Rolle (Role) «Storage-Blob-Datenmitwirkender» fehlt | **Zu Zugriffsschlüssel wechseln** (Switch to Access key) |
| Datei heisst `preisliste.txt.txt` | Windows blendet Endungen aus | egal für diesen Auftrag |
| Preisliste im Browser sichtbar | Container öffentlich gemacht | auf **Privat** (Private) zurückstellen |

## Hinweise für die Kursleitung
- Der Name des Speicherkontos (Storage Account) ist der häufigste Stolperstein. Gleich zu Beginn erwähnen, dass er weltweit eindeutig sein muss.
- Schritt 6 ist bewusst ein «Fehler». Er zeigt: Cloud-Speicher ist standardmässig privat. Das ist die Brücke zu 3.5 (öffentlich über `$web`) und ⭐ 3.6 (gezielt teilen mit SAS).
- Das Speicherkonto (Storage Account) wird in 3.5 und 3.6 weiterverwendet. Erst danach aufräumen.
