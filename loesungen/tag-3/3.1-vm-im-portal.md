# Lösung 3.1: Linux-VM im Portal erstellen und per SSH verbinden

Beispiel mit Kürzel `mm` und Kursregion `switzerlandnorth`.

## Schritt 1
```text
PS C:\Users\mia> Get-Content ~\.ssh\id_ed25519.pub
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI… mia@LAPTOP-123
```

## Schritt 2
`rg-tag3-portal-mm` in `switzerlandnorth` mit `kurs=azure-basics`, `tag=3`, `owner=mm`.

## Schritt 4
Felder wie in der Tabelle des Auftrags. Wichtig: **Vorhandenen öffentlichen Schlüssel verwenden** (Use existing public key), sonst erzeugt Azure ein neues Schlüsselpaar (Key Pair) und bietet den privaten Schlüssel (Private Key) zum Download an. Das wollen wir nicht: Der Schlüssel von Tag 1 soll weiterverwendet werden.

## Schritt 5
Preis für `Standard_B1s` etwa 0.01–0.02 USD pro Stunde, je nach Region. Der Assistent zeigt nur die Compute-Kosten, Disk und öffentliche IP (Public IP) kommen dazu. <!-- prüfen: Stand 08.11.2026 – Preis im Portal ablesen -->

## Schritt 6
Status **Wird ausgeführt** (Running), öffentliche IP (Public IP) z. B. `20.208.45.17`.

## Zusatzaufgabe ⭐
Die Sicherheitsregel (Security Rule) `SSH` (Priorität (Priority) 300) erlaubt Port 22 von der Quelle (Source) **Any** (beliebige Adresse). Azure warnt, weil damit jeder im Internet versuchen kann, sich anzumelden. In der Praxis schränkt man die Quelle auf die eigene IP ein (Thema Tag 4). <!-- prüfen: Priorität der vom Portal erstellten Sicherheitsregel -->

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| Schlüssel «ungültig» | Zeile abgeschnitten oder Zeilenumbruch kopiert | ganze Zeile neu kopieren |
| Azure bietet `.pem`-Datei zum Download an | **Neues Schlüsselpaar generieren** (Generate new key pair) gewählt | zurück, **Vorhandenen öffentlichen Schlüssel verwenden** (Use existing public key) |
| `SkuNotAvailable` / Grösse ausgegraut | Kapazität in der Region | `Standard_B2ats_v2` |
| `QuotaExceeded` | noch eine VM aktiv (z. B. aus einem anderen Modul) | alte VM löschen |
| `Permission denied (publickey)` | Benutzer `ubuntu` statt `azureuser` oder anderer Schlüssel | `ssh azureuser@…` |
| `Connection timed out` | Port 22 nicht freigegeben, Schulnetz blockiert ausgehend Port 22 | NSG prüfen; sonst Hotspot oder Kursleitung |

## Hinweise für die Kursleitung
- **Vorab testen:** Lässt das Schulnetz ausgehende Verbindungen auf Port 22 zu? Wenn nicht, ist der ganze Vormittag blockiert. Ausweichmöglichkeit: Mobile-Hotspot, oder SSH aus der Cloud Shell (dann braucht es dort einen Schlüssel, siehe Theorie Kapitel 4, `--generate-ssh-keys`). <!-- prüfen -->
- Lernende ohne Schlüssel von Tag 1: zuerst Auftrag 1.6, Schritt 1–2 nachholen (5 Minuten).
- Der Assistent zeigt viele Felder. Betonen: nur die Felder aus der Tabelle ausfüllen, Rest lassen.
- Am Ende von 3.2 wird die VM gelöscht. Wer 3.2 nicht schafft, muss trotzdem aufräumen (vCPU-Kontingent, Guthaben).
