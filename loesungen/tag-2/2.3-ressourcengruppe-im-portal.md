# Lösung 2.3: Erste Ressourcengruppe im Portal

## Schritt 1 und 2
Ressourcengruppen (Resource Groups) > **+ Erstellen** (+ Create) > Grundeinstellungen: Abonnement (Subscription), Name `rg-tag2-mm`, Region > **Weiter: Tags** (Next: Tags) > drei Tags > **Überprüfen + erstellen** (Review + create) > **Erstellen** (Create).

## Schritt 3
Übersicht der Ressourcengruppe (Beispiel `mm`):
```text
Abonnement   : Azure for Students
Standort     : Switzerland North
Tags         : kurs : azure-basics   tag : 2   owner : mm
Ressourcen   : Keine anzuzeigenden Ressourcen
```

## Schritt 4
Filter **Tag** `owner` = `mm` → nur `rg-tag2-mm` in der Liste.

## Schritt 5
Aktivitätsprotokoll: Eintrag «Update resource group» (Vorgang `Microsoft.Resources/subscriptions/resourceGroups/write`), Status «Erfolgreich», ausgelöst vom eigenen Konto.

## Schritt 6
1. Man kann damit Ressourcen filtern und Kosten zuordnen.
2. … werden **alle Ressourcen** darin ebenfalls gelöscht.

## Schritt 7
Meldung «Ressourcengruppe gelöscht». Liste ohne `rg-tag2-mm`.

## Zusatzaufgabe ⭐
Ja: zweiter Eintrag «Update resource group» bzw. «Tags aktualisieren». Jede Änderung wird aufgezeichnet.

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| `RequestDisallowedByPolicy` oder `RequestDisallowedByAzure` | Region im Abo nicht erlaubt | Kursregion aus 2.2 wählen |
| Tag-Name mit Grossbuchstaben (`Kurs`) | Tippfehler | Bei Tag-Namen wird Gross-/Kleinschreibung nicht unterschieden, bei Werten schon. Für den Kurs trotzdem klein schreiben. |
| Löschen-Schaltfläche bleibt grau | Name in der Bestätigung falsch | Namen genau abtippen |
| Gruppe nach dem Löschen noch sichtbar | Liste nicht aktualisiert | **Aktualisieren** (Refresh) klicken |

## Hinweise für die Kursleitung
- Vor dem Start: Kursregion aus 2.2 abfragen (siehe dort).
- Den Schritt «Aktivitätsprotokoll» kurz im Plenum aufgreifen: Hier sieht man, dass jede Aktion über den Azure Resource Manager läuft – Überleitung zum Input «Werkzeuge».
- Das Löschen in Schritt 7 ist Absicht: In 2.4 entsteht dieselbe Gruppe mit der CLI.
