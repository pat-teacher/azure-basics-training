# Lösung ⭐ 2.8: Drei Umgebungen, ein Befehl – Tags, Abfragen und Sperren

Beispiel mit Kürzel `mm` und Kursregion `switzerlandnorth`.

## Schritt 1
```bash
for umgebung in dev test prod; do az group create --name rg-tag2-$umgebung-mm --location switzerlandnorth --tags kurs=azure-basics tag=2 owner=mm umgebung=$umgebung --output none; done
```
Ohne `--output none` erscheinen drei JSON-Blöcke. Das ist auch richtig.

```text
$ az group list --output table
Name             Location          Status
---------------  ----------------  ---------
rg-tag2-dev-mm   switzerlandnorth  Succeeded
rg-tag2-test-mm  switzerlandnorth  Succeeded
rg-tag2-prod-mm  switzerlandnorth  Succeeded
```

## Schritt 2
```bash
az group list --tag umgebung=prod --output table
```
`--tag` filtert nach genau einem Tag im Format `name=wert`. Auch richtig: `az group list --query "[?tags.umgebung=='prod']" --output table`.

## Schritt 3
```bash
az group list --query "[?tags.owner=='mm'].{Name:name, Umgebung:tags.umgebung}" --output table
```
```text
Name             Umgebung
---------------  --------
rg-tag2-dev-mm   dev
rg-tag2-prod-mm  prod
rg-tag2-test-mm  test
```
Die Spaltennamen vor dem Doppelpunkt sind frei wählbar.

## Schritt 4
Nach `az group update --name rg-tag2-test-mm --tags kostenstelle=velo-it`:
```json
{
  "kostenstelle": "velo-it"
}
```
Satz fürs Lernjournal: `--tags` **ersetzt** alle bisherigen Tags durch die neuen. Die vier alten Tags sind weg.

Wiederherstellen mit allen fünf Tags:
```bash
az group update --name rg-tag2-test-mm --tags kurs=azure-basics tag=2 owner=mm umgebung=test kostenstelle=velo-it
```

Einen Tag ergänzen, ohne die anderen zu verlieren:
```bash
az group update --name rg-tag2-prod-mm --set tags.kostenstelle=velo-it
```
Auch richtig (fügt Tags zusammen, statt sie zu ersetzen):
```bash
az tag update --resource-id $(az group show --name rg-tag2-prod-mm --query id --output tsv) --operation Merge --tags kostenstelle=velo-it
```
Kontrolle `az group show --name rg-tag2-test-mm --query tags` und dasselbe für `rg-tag2-prod-mm`:
```json
{
  "kostenstelle": "velo-it",
  "kurs": "azure-basics",
  "owner": "mm",
  "tag": "2",
  "umgebung": "test"
}
```
Bei der Produktion steht `"umgebung": "prod"`.

## Schritt 5
```bash
az lock create --name nicht-loeschen --lock-type CanNotDelete --resource-group rg-tag2-prod-mm
az lock list --resource-group rg-tag2-prod-mm --output table
```
```text
Level         Name            ResourceGroup
------------  --------------  ---------------
CanNotDelete  nicht-loeschen  rg-tag2-prod-mm
```
<!-- prüfen: Spalten von az lock list --output table -->

Löschversuch mit `az group delete --name rg-tag2-prod-mm --yes`:
```text
(ScopeLocked) The scope '/subscriptions/…/resourcegroups/rg-tag2-prod-mm' cannot perform delete operation because following scope(s) are locked: '/subscriptions/…/resourceGroups/rg-tag2-prod-mm'. Please remove the lock and try again.
```
Im Portal: Ressourcengruppe (Resource Group) > **Einstellungen** (Settings) > **Sperren** (Locks) zeigt `nicht-loeschen` mit Sperrtyp «Löschen».

## Schritt 6

| Situation | Tag | Sperre (Lock) | Richtlinie (Policy) |
|-----------|:---:|:---:|:---:|
| Kosten pro Abteilung | ✓ | | |
| Datenbank nicht aus Versehen löschen | | ✓ | |
| nur Rechenzentren in der Schweiz | | | ✓ |
| alle Testumgebungen finden | ✓ | | |
| Tag `owner` ist Pflicht, sonst abgelehnt | | | ✓ |

Die letzte Zeile ist die schwierigste: Der Tag selbst hilft nicht. Erst eine Richtlinie (Policy) **erzwingt**, dass er vorhanden ist.

Warum kann auch der Besitzer (Owner) nicht löschen? Eine Sperre (Lock) gilt für alle, unabhängig von der Rolle (Role). Sie schützt vor Versehen, nicht vor fehlenden Rechten: Wer löschen will, muss die Sperre (Lock) zuerst bewusst entfernen.

## Aufräumen
```bash
az lock delete --name nicht-loeschen --resource-group rg-tag2-prod-mm
az group list --query "[?tags.umgebung].name" --output tsv
for rg in $(az group list --query "[?tags.umgebung].name" --output tsv); do az group delete --name $rg --yes --no-wait; done
```
Die zweite Zeile ist die Kontrolle vor dem Löschen: Sie zeigt die drei Namen. `--no-wait` ist erlaubt, aber nicht nötig. Ohne `--no-wait` dauert die Schleife einige Minuten, weil eine Gruppe nach der anderen gelöscht wird. Danach ist `az lock list --output table` leer. <!-- prüfen: Dauer beim Löschen leerer Ressourcengruppen -->

Wer die Sperre (Lock) nicht entfernt, erhält für die Produktion `ScopeLocked`. Dev und Test werden trotzdem gelöscht.

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| Bash wartet mit `>` | `; done` oder schliessendes `"` fehlt | `Ctrl` + `C`, Befehl ergänzen |
| Gruppe `rg-tag2--mm` | Variable falsch geschrieben (`$Umgebung`) oder `$(umgebung)` statt `$umgebung` (dann zusätzlich `umgebung: command not found`) | Gruppe löschen, Schleife korrigieren |
| `az group list --tag umgebung prod` liefert Fehler | Gleichheitszeichen fehlt | `--tag umgebung=prod` |
| `--query` liefert leere Liste | doppelte statt einfache Anführungszeichen um `'mm'` innen, oder Backticks verwendet | aussen `"…"`, innen `'…'` |
| In Schritt 4 auch auf `prod` alle Tags gelöscht | `--tags` statt `--set` verwendet | mit allen fünf Tags neu setzen (vier alte plus `kostenstelle=velo-it`) |
| `ScopeLocked` direkt nach `az lock delete` | Änderung braucht wenige Sekunden | kurz warten, nochmals löschen |
| `AuthorizationFailed` bei `az lock create` | Konto hat nicht die Rolle (Role) Besitzer (Owner) | bei Azure for Students normalerweise vorhanden; sonst Schritt 5 auslassen <!-- prüfen --> |

## Hinweise für die Kursleitung
- Für Lernende, die 2.4 und 2.5 sicher und schnell erledigt haben. Ohne Challenge-Lab-Schlüssel, ohne Kosten.
- Die Falle in Schritt 4 ist Absicht: Der Unterschied zwischen Ersetzen und Ergänzen kommt in der Praxis oft vor. Tipp 1 übt genau das: Wer ersetzt, muss alle Tags angeben.
- Schritt 6 verbindet die drei Werkzeuge der Governance. Wer fertig ist, kann es in L8 in zwei Sätzen der Klasse erklären.
- Aufräumkontrolle in L8: Bei diesen Lernenden zusätzlich `az lock list --output table` zeigen lassen. Eine vergessene Sperre (Lock) blockiert sonst das Aufräumen.
- Vorab mit dem eigenen Konto für Azure for Students testen: `az lock create` auf einer Ressourcengruppe (Resource Group) und die Spalten von `az lock list --output table`. <!-- prüfen -->
