# Lösung 1.3: Wie viel CPU und RAM bekommt eine VM?

Stand: 19.10.2026

## Schritt 2

```text
PS> multipass exec klein -- nproc
1
PS> multipass exec klein -- free -h
               total        used        free ...
Mem:           953Mi        ...
PS> multipass exec klein -- df -h /
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       4.8G  1.9G  2.9G  40% /
```

| | VM «klein» |
|---|---|
| Prozessoren | 1 |
| Arbeitsspeicher | knapp 1 GB (z. B. 953Mi) |
| Festplatte | knapp 5 GB (z. B. 4.8G) |

Etwas weniger als zugewiesen ist normal: Ein Teil ist für Kernel und Dateisystem reserviert.

## Schritt 3
1. So viele, wie der Laptop logische Prozessoren hat (z. B. 8).
2. **Die VMs teilen sich die echten Prozessoren abwechselnd. Unter Volllast wird es langsam.** Das nennt man Überbuchung (Overcommitment).

## Zusatzaufgabe ⭐
- Mit Hyper-V verweigert Multipass meist die Zuweisung von mehr vCPUs pro VM, als logische Prozessoren vorhanden sind (Fehlermeldung). Mit VirtualBox ebenfalls.
- Beides (Fehler oder Erfolg) ist ein gültiges Ergebnis. Wichtig ist die Erkenntnis: **Pro VM** gibt es eine Grenze, **über alle VMs zusammen** kann man überbuchen.

## Typische Fehler
| Problem | Ursache | Lösung |
|---------|---------|--------|
| `invalid argument` bei `--memory 1g` | falsche Schreibweise | `1G` (grosses G) verwenden |
| Laptop wird sehr langsam | zu viele VMs gleichzeitig | nicht benötigte VMs löschen |

## Hinweise für die Kursleitung
- Die Theorie zu Zeitscheiben und Swap nur kurz anreissen. Für ICT-Fachleute reicht: «VMs teilen sich die Hardware. Wird es zu viel, wird es langsam.»
