# Lösung 1.4: Deine erste automatische VM mit cloud-init

Stand: 19.10.2026

## Schritt 4

```text
PS> multipass exec auto -- tree --version
tree v2.x.x © 1996 - 20xx by Steve Baker ...

PS> multipass exec auto -- cat /opt/willkommen.txt
Diese Datei hat cloud-init erstellt.
Niemand hat sie von Hand angelegt.
Fertig eingerichtet am Mon Oct 19 09:41:12 UTC 2026

PS> multipass exec auto -- tail -n 5 /var/log/cloud-init-output.log
...
Cloud-init v. 25.x finished at Mon, 19 Oct 2026 09:41:15 +0000. Datasource DataSourceNoCloud ...  Up 52.31 seconds
```

## Schritt 5
1. Zeilen 1 und 2 kommen aus `write_files`. Zeile 3 (mit Datum) kommt aus `runcmd`.
2. «cloud-init läuft nur beim **ersten** Start der VM.»
3. Zum Beispiel:
   - Ein Befehl pro VM statt viele Handgriffe.
   - Alle VMs sind gleich, keine Tippfehler oder vergessenen Schritte.
   - Die Datei ist gleichzeitig die Dokumentation.

## Zusatzaufgabe ⭐ (Beispiel)
```yaml
#cloud-config
package_update: true
packages:
  - tree
  - htop
  - cowsay
write_files:
  - path: /opt/willkommen.txt
    content: |
      Diese Datei hat cloud-init erstellt.
  - path: /opt/team.txt
    content: |
      Testserver der Velo Zürich AG
runcmd:
  - echo "Fertig eingerichtet am $(date)" >> /opt/willkommen.txt
```
Nachweis: `multipass exec auto2 -- /usr/games/cowsay Hallo` und `multipass exec auto2 -- cat /opt/team.txt`.

## Typische Fehler
| Problem | Ursache | Lösung |
|---------|---------|--------|
| `could not read cloud-init file` | falscher Ordner oder Dateiname `.yaml.txt` | `dir` prüfen; Datei mit `notepad cloud-init-tag1.yaml` aus PowerShell anlegen |
| Programme fehlen, Log zeigt YAML-Fehler | Einrückung mit Tab oder falscher Tiefe | genau 2 Leerzeichen; Inhalt neu kopieren |
| Änderung an der Datei wirkt nicht | cloud-init läuft nur beim ersten Start | VM löschen und neu erstellen |

## Hinweise für die Kursleitung
- Die Datei liegt bewusst unter `/opt`: `write_files` läuft, bevor der Benutzer `ubuntu` angelegt wird. Unter `/home/ubuntu` würde der Home-Ordner sonst root gehören.
- Multipass schreibt die Datei intern neu. Experimente wie «erste Zeile weglassen» zeigen lokal oft keinen Unterschied – das klappt erst in Azure zuverlässig (Tag 5).
- An Tag 5 wird genau diese Idee in Azure wiederholt. Darauf hinweisen: «Heute lokal, Freitag in der Cloud.»
