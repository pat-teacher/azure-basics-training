# Lösung 1.4: Snapshot, Klon und Ressourcen

Stand: 19.10.2026

## Schritt 3
Nach `sudo rm -rf /var/www/html` liefert `curl http://localhost` den Fehler **404 Not Found**. nginx läuft noch, findet aber das Verzeichnis nicht mehr.

## Schritt 4d
Nach dem Wiederherstellen ist **nginx gar nicht mehr installiert**. `curl` meldet `Connection refused`.

Der Snapshot setzt die **ganze Disk** auf den Zustand beim Erstellen zurück. Alles, was danach passiert ist, ist weg, auch die gewollten Änderungen (nginx-Installation). Darum macht man in der Praxis einen Snapshot direkt **vor** einer riskanten Änderung.

## Schritt 5
`free -h` zeigt nach der Änderung etwa 0.9 GiB. RAM und CPU lassen sich bei ausgeschalteter VM jederzeit ändern. In Azure heisst das «Grösse ändern» und braucht ebenfalls einen Neustart.

## Schritt 6c
- Der Klon heisst ebenfalls `vm-lokal-<kuerzel>`. Hostname und SSH-Hostschlüssel sind identisch. Im selben Netz verwechselt man die Server leicht, und SSH-Clients können sie nicht unterscheiden.
- Auch `/etc/machine-id` ist identisch. Ubuntu bildet daraus die DHCP-Client-ID. Bei einer Netzwerkbrücke bekommen Original und Klon deshalb oft **dieselbe IP-Adresse**, obwohl VirtualBox eine neue MAC-Adresse vergibt.
- Der Klon erbt die Portweiterleitung `127.0.0.1:2222`. Laufen beide gleichzeitig, kann nur eine VM den Port belegen.
- Ein **verknüpfter Klon** braucht wenig Platz, weil er nur die Unterschiede zur Original-Disk speichert. Ohne das Original funktioniert er nicht.

Praxisbeispiele für Snapshots: vor Updates, vor Konfigurationsänderungen, vor einem Test.

## Zusatzfrage ⭐
- **Dafür:** Ein Snapshot stellt einen früheren Zustand schnell wieder her.
- **Dagegen:** Er liegt auf derselben Disk und demselben Host. Geht die Disk kaputt, sind VM und Snapshot weg. Ein Backup gehört an einen anderen Ort. Lange Snapshot-Ketten machen die VM ausserdem langsamer.

## Typische Fehler
| Problem | Ursache | Lösung |
|---------|---------|--------|
| RAM-Einstellung ist ausgegraut | VM läuft noch | zuerst herunterfahren |
| Neuer Eintrag «Aktueller Zustand» in der Snapshot-Liste | beim Wiederherstellen «Snapshot erzeugen» angeklickt | schadet nicht, Eintrag löschen |
| Klon startet mit NAT-Fehler zur Portweiterleitung | Original läuft und belegt Port 2222 | Original ausschalten oder im Klon einen anderen Host-Port wählen |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` nach dem Wiederherstellen oder Klonen | gleicher Port, anderer Hostschlüssel | `ssh-keygen -R "[127.0.0.1]:2222"` |

## Hinweise für die Kursleitung
- Gute Brücke zu Azure: Auch dort gibt es Snapshots von verwalteten Datenträgern. Für echte Backups ist Azure Backup zuständig.
- Darauf achten, dass alle die VM für Tag 3 behalten.
