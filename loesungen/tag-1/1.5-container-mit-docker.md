# Lösung 1.5 ⭐: Container mit Docker

Stand: 19.10.2026

## Schritt 2
Die vier Schritte laut Ausgabe von `hello-world`:
1. Der Docker-Client kontaktiert den Docker-Daemon.
2. Der Daemon lädt das Image `hello-world` von Docker Hub herunter.
3. Der Daemon erstellt aus dem Image einen Container und führt das Programm darin aus.
4. Der Daemon schickt die Ausgabe an den Client, der sie im Terminal anzeigt.

## Schritt 3
```text
$ docker ps
CONTAINER ID   IMAGE   COMMAND                  ...   PORTS                  NAMES
a1b2c3d4e5f6   nginx   "/docker-entrypoint.…"   ...   0.0.0.0:8080->80/tcp   web
```
`-p 8080:80` leitet Port 8080 der VM auf Port 80 im Container weiter, wie die Portweiterleitung von VirtualBox in Auftrag 1.3.

## Schritt 4

| | VM | Container |
|---|---|---|
| Startzeit | 20–60 Sekunden (Boot des Betriebssystems) | unter 1 Sekunde (`real 0m0.5s` o. ä.), wenn das Image schon geladen ist |
| Grösse | mehrere GB (ganzes Betriebssystem) | `alpine` ca. 8 MB, `nginx` ca. 190 MB |
| Eigener Kernel? | ja | nein, teilt den Kernel der VM bzw. des Hosts |
| Typischer Einsatz | verschiedene Betriebssysteme, starke Isolation, klassische Server | Anwendungen schnell verpacken und starten, Microservices |

<!-- prüfen: Image-Grössen aktuell auf Docker Hub kontrollieren -->

**Wann was?** Eine VM, wenn du ein eigenes Betriebssystem oder starke Trennung brauchst. Einen Container, wenn du eine einzelne Anwendung schnell, klein und überall gleich starten willst.

## Typische Fehler
| Problem | Ursache | Lösung |
|---------|---------|--------|
| `permission denied while trying to connect to the Docker daemon socket` | neu anmelden vergessen nach `usermod` | `exit`, neu per SSH verbinden |
| `port is already allocated` | Container `web` läuft schon | `docker rm -f web` |
| `curl` vom Laptop auf Port 8080 klappt nicht | VirtualBox-NAT leitet 8080 nicht weiter | in curl `localhost` in der VM verwenden oder eine zweite Port-Weiterleitung anlegen |
