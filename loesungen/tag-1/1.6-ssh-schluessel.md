# Lösung 1.6: SSH-Schlüssel für die Cloud vorbereiten

Stand: 26.10.2026

## Schritt 1 und 2
- Dateien: `C:\Users\<name>\.ssh\id_ed25519` (privat) und `id_ed25519.pub` (öffentlich).
- Der öffentliche Schlüssel (Public Key) ist eine Zeile: `ssh-ed25519 AAAAC3Nza… benutzer@LAPTOP`.

## Schritt 3
```text
PS> multipass exec vm1 -- tail -n 1 .ssh/authorized_keys
ssh-ed25519 AAAAC3Nza… benutzer@LAPTOP
PS> ssh ubuntu@172.27.x.x
The authenticity of host '172.27.x.x' can't be established. ... Are you sure you want to continue connecting (yes/no/[fingerprint])? yes
Welcome to Ubuntu ...
ubuntu@vm1:~$ exit
PS C:\Users\benutzer>
```
Entscheidend: Es erscheint **keine** Passwortabfrage.

## Schritt 4

| Aussage | Lösung |
|---------|--------|
| Den öffentlichen Schlüssel darf ich in Azure hochladen. | richtig |
| Den privaten Schlüssel (Private Key) schicke ich per Teams an die Kursleitung. | **falsch** – der private Schlüssel bleibt immer bei dir |
| Wer meinen privaten Schlüssel hat, kann sich als ich anmelden. | richtig |
| Verliere ich den privaten Schlüssel, kann ich ihn aus dem öffentlichen zurückrechnen. | **falsch** – dann hilft nur ein neues Schlüsselpaar (Key Pair) |
| Bei der Anmeldung in Schritt 3 musste ich kein Passwort eingeben, weil vm1 meinen öffentlichen Schlüssel kennt. | richtig – der öffentliche Schlüssel steht in `authorized_keys` |

## Typische Fehler
| Problem | Ursache | Lösung |
|---------|---------|--------|
| `ssh-keygen` nicht gefunden | OpenSSH-Client fehlt (von der Schul-/Firmen-IT entfernt) | Einstellungen > System > Optionale Features > «OpenSSH-Client» hinzufügen, oder PowerShell als Administrator: `Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0`. Danach PowerShell neu öffnen. |
| Schlüssel überschrieben | bei «Overwrite» `y` gewählt | nicht schlimm im Kurs; der neue Schlüssel gilt |
| Passwortabfrage bei `ssh` | Benutzername fehlt (`ssh 172.27.x.x` meldet sich mit dem Windows-Benutzernamen an) oder falsche IP | `ssh ubuntu@<IP>` mit der IP aus `multipass list` |
| `REMOTE HOST IDENTIFICATION HAS CHANGED` | IP früher von einer anderen VM benutzt (z. B. aus Auftrag 1.4 oder 1.5) | `ssh-keygen -R <IP>`, dann neu verbinden |
| `Permission denied (publickey)` | Schlüssel nicht in vm1 angekommen | Befehl wiederholen; prüfen mit `multipass exec vm1 -- cat /home/ubuntu/.ssh/authorized_keys` |

## Hinweise für die Kursleitung
- Fehlt der OpenSSH-Client und haben die Lernenden keine Adminrechte: bis Tag 3 mit der IT des Lehrbetriebs klären. Den Schlüssel nie auf einem fremden Laptop erstellen lassen.
- An Tag 3 wird der öffentliche Schlüssel beim Erstellen der Azure-VM eingefügt. Kurz bestätigen lassen, dass alle die Datei `id_ed25519.pub` haben.
