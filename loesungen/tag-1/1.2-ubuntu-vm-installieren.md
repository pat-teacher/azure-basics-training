## Schritt 4
1. Die `.vdi`-Datei ist nur so gross wie die tatsächlich belegten Daten (nach der Installation etwa 4–6 GB). Bei einer **dynamisch allozierten** Disk wächst die Datei erst, wenn die VM Daten schreibt. Die VM sieht trotzdem 20 GB.
2. Ein Teil des RAM ist für den Kernel und reservierte Bereiche belegt. `free -h` zeigt deshalb etwa 1.9 GiB. Dazu kommt der Unterschied zwischen GB (10⁹ Byte) und GiB (2³⁰ Byte).
3. Bei NAT hat die VM die IP `10.0.2.15`. Windows kann sie **nicht** anpingen. Das NAT-Netz von VirtualBox ist privat und gehört nur der VM. Die Lösung folgt in Auftrag 1.3.

## Typische Fehler
| Problem | Ursache | Lösung |
|---------|---------|--------|
| `VT-x is not available (VERR_VMX_NO_VMX)` | Virtualisierung im BIOS aus | BIOS/UEFI: Intel VT-x bzw. AMD-V aktivieren |
| VM startet sehr langsam, Schildkröten-Symbol | Hyper-V/VBS aktiv | akzeptieren oder Hyper-V als Alternative verwenden |
| Unbeaufsichtigte Installation startet | Häkchen «überspringen» vergessen | VM löschen und neu anlegen |
| Nach dem Neustart startet der Installer wieder | ISO noch eingelegt | **Ändern** > **Massenspeicher** > ISO entfernen |
| Tastatur tippt `z` statt `y` | Layout falsch | `sudo dpkg-reconfigure keyboard-configuration` |

## Hinweise für die Kursleitung
- Die ISO vorab auf USB-Sticks verteilen. 10 Lernende mit je 3 GB im Schul-WLAN dauern sonst zu lange.
- Die Installation dauert 10–20 Minuten. In dieser Zeit eignet sich ein kurzes Gespräch über Auftrag 1.1.
