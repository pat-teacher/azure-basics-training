# Lösung 5.3: Das Netzwerk von Tag 4 als Bicep

Beispiel mit Kürzel `mm`, Region `switzerlandnorth` und Schul-IP `198.51.100.23`.

## Schritt 2
`main.bicep` wie im Auftrag. Geändert gegenüber 5.2: `module network 'network.bicep'`, neuer `param schulIp string`, `schulIp: schulIp` unter `params`, `output vnetName string = network.outputs.vnetName`.

## Schritt 3 und 4
```powershell
az deployment sub what-if --location switzerlandnorth --template-file main.bicep --parameters kuerzel=mm schulIp=198.51.100.23
az deployment sub create --location switzerlandnorth --template-file main.bicep --parameters kuerzel=mm schulIp=198.51.100.23 --query properties.provisioningState
```
what-if, wenn `rg-tag5-mm` aus 5.2 noch existiert: `= Microsoft.Resources/resourceGroups/rg-tag5-mm`, `+ Microsoft.Network/networkSecurityGroups/nsg-web`, `+ Microsoft.Network/virtualNetworks/vnet-tag5-mm`, das Speicherkonto (Storage Account) aus 5.2 mit `* Ignore`. `Resource changes: 2 to create, 1 unchanged, 1 to ignore.` Wurde die Ressourcengruppe (Resource Group) gelöscht: `3 to create`. <!-- prüfen -->

## Schritt 7
1. Nichts ändert sich, die Bereitstellung (Deployment) ist trotzdem erfolgreich.
2. Am Verweis `nsg.id` im VNet: Bicep sieht, dass das VNet die NSG braucht, und erstellt sie zuerst.
3. `network.bicep` bleibt gleich, in `main.bicep` nur der Name der Ressourcengruppe (Resource Group). Genau dafür ist Infrastruktur als Code (Infrastructure as Code) da. ⭐ Noch besser: den Namen als `param` mit Standardwert.

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| Kommas zwischen Listenelementen | Gewohnheit aus JSON | In Bicep jedes Element auf eine eigene Zeile, ohne Komma (neuere Bicep-Versionen erlauben Kommas in einer Zeile) |
| `/32/32` | `schulIp` mit Präfix übergeben | nur die Adresse |
| `snet-admin` ausserhalb der Liste eingefügt | Klammer falsch | Einrückung prüfen, Bicep-Erweiterung zeigt den Fehler |
| what-if zeigt Löschen von `snet-admin` | Datei nicht gespeichert, alte Version bereitgestellt | `Ctrl` + `S` |
| `schulIp` fehlt | in `main.bicep` nicht als `param` oder nicht unter `params` weitergegeben | beide Stellen prüfen |
| `network.bicep` mit `az deployment sub` | `resourceGroup()` gibt es auf Ebene Abonnement (Subscription) nicht | `--template-file main.bicep` |
| `InvalidDeploymentLocation` | andere `--location` als in 5.2, Bereitstellung (Deployment) heisst wieder `main` | dieselbe Region oder `--name main-netz` |

## Hinweise für die Kursleitung
- Die Tabelle «Vergleiche mit Tag 4» kurz an der Wandtafel besprechen: sechs Befehle gegenüber einer Datei.
- Ab hier nur noch `az deployment sub`. Die Ressourcengruppe (Resource Group) muss nicht mehr von 5.2 übrig sein: `main.bicep` erstellt sie bei Bedarf.
- Subnetze (Subnets) stehen hier **im** VNet. Entfernt man ein Subnetz (Subnet) aus der Datei, entfernt Azure es beim nächsten Bereitstellen, sofern es leer ist. Nur erwähnen, wenn jemand fragt.
- Schul-IP an der Wandtafel lassen (von Tag 4). Hat die Schule mehrere Adressen, mit einem Bereich arbeiten und in der Datei `/32` durch den passenden Präfix ersetzen. <!-- prüfen -->
- `main.bicep` und `network.bicep` sind die Grundlage für das Abschlussprojekt.
