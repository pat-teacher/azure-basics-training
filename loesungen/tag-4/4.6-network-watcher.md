# Lösung 4.6 ⭐: Network Watcher – Azure fragen statt ausprobieren

Beispiel mit Kürzel `mm`, Kursregion `switzerlandnorth` und Schul-IP `198.51.100.23`.

## Schritt 1
```text
Location          Name                               ProvisioningState    ResourceGroup
----------------  ---------------------------------  -------------------  ----------------
switzerlandnorth  NetworkWatcher_switzerlandnorth    Succeeded            NetworkWatcherRG
```

## Schritt 2
```bash
az network watcher test-ip-flow --resource-group rg-tag4-mm --vm vm-web-mm --direction Inbound --protocol TCP --local 10.10.1.4:22 --remote 198.51.100.23:50000
```
```json
{
  "access": "Allow",
  "ruleName": "securityRules/allow-ssh"
}
```
<!-- prüfen: Format von ruleName (securityRules/… bzw. defaultSecurityRules/… oder UserRule_…/DefaultRule_…) mit eigenem Konto testen und Tabelle anpassen -->

## Schritt 3
Die Tabelle nennt nur den Namen der Sicherheitsregel (Security Rule). In der Ausgabe kann davor noch ein Präfix stehen.

| | Frage | Ergebnis | Sicherheitsregel (Security Rule) |
|---|-------|----------|----------------------------------|
| a | SSH von `203.0.113.10` | Deny | `DenyAllInBound` |
| b | Website von `203.0.113.10` | Allow | `allow-http` |
| c | RDP von der Schule | Deny | `DenyAllInBound` |
| d | Outbound zu `1.1.1.1:443` | Allow | `AllowInternetOutBound` |

Befehl für d:
```bash
az network watcher test-ip-flow --resource-group rg-tag4-mm --vm vm-web-mm --direction Outbound --protocol TCP --local 10.10.1.4:50000 --remote 1.1.1.1:443
```

## Schritt 4 und 5
Portal zeigt dasselbe wie die CLI. Effektive Sicherheitsregeln (Effective Security Rules): `allow-http`, `allow-ssh` und die sechs Standardsicherheitsregeln (Default Security Rules) aus `nsg-web`, zugeordnet zum Subnetz (Subnet) `snet-web`.

## Schritt 6
Zum Beispiel: «Bei Station 2 und 3 (NSG am Subnetz (Subnet) und an der Netzwerkschnittstelle (Network Interface)) zeigt sie direkt, welche Sicherheitsregel (Security Rule) blockiert, z. B. bei Karte 3. Bei Station 5 (Dienst) hilft sie nicht: Die NSG erlaubt dann alles, nginx läuft aber nicht.»

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| `VM … is not running` oder Fehler zum Agent | VM gestoppt | `az vm start …` |
| `--local` mit öffentlicher IP (Public IP) | Network Watcher prüft auf der Netzwerkschnittstelle (Network Interface), also mit der privaten IP | `10.10.1.4` verwenden |
| Network Watcher fehlt | in der Region nicht aktiviert | Schritt 1, `az network watcher configure …` |

## Hinweise für die Kursleitung
- Nur für Schnelle in L7, braucht die Umgebung aus 4.4/4.5 (nicht aufgeräumt).
- Die IP-Flussüberprüfung (IP Flow Verify) prüft nur die NSG-Sicherheitsregeln (Security Rules), nicht den Dienst in der VM. Gute Ergänzung zur Diskussion nach 4.5.
- Vorab testen: Network Watcher im Student-Abo verfügbar, Ausgabeformat von `ruleName`, Position der effektiven Sicherheitsregeln (Effective Security Rules) im Portal. <!-- prüfen -->
