# Lösung 4.2: VNet mit zwei Subnetzen

Beispiel mit Kürzel `mm` und Kursregion `switzerlandnorth`.

## Schritt 1
```bash
az group create --name rg-tag4-mm --location switzerlandnorth --tags kurs=azure-basics tag=4 owner=mm
```

## Schritt 2
```bash
az network vnet create --resource-group rg-tag4-mm --name vnet-tag4-mm --address-prefixes 10.10.0.0/16 --subnet-name snet-web --subnet-prefixes 10.10.1.0/24
```
Ausschnitt der Ausgabe:
```json
{
  "newVNet": {
    "addressSpace": { "addressPrefixes": [ "10.10.0.0/16" ] },
    "name": "vnet-tag4-mm",
    "provisioningState": "Succeeded",
    "subnets": [ { "addressPrefix": "10.10.1.0/24", "name": "snet-web", … } ]
  }
}
```

## Schritt 3
```bash
az network vnet subnet create --resource-group rg-tag4-mm --vnet-name vnet-tag4-mm --name snet-intern --address-prefixes 10.10.2.0/24
```

## Schritt 4
```text
Name         Bereich
-----------  ------------
snet-web     10.10.1.0/24
snet-intern  10.10.2.0/24
```

## Schritt 5
1. `10.10.1.128/25` → Fehlercode `NetcfgSubnetRangesOverlap`: Der Bereich überlappt mit `snet-web`.
2. `10.20.1.0/24` → Fehlercode `NetcfgSubnetRangeOutsideVnet`: Der Bereich liegt nicht im Adressraum (Address Space) `10.10.0.0/16`.

<!-- prüfen: genaue Fehlercodes und Text -->

## Schritt 6
Im Portal unter **Subnetze** (Subnets): `snet-web` und `snet-intern`, je **Verfügbare IPs** (Available IPs) `251`.

## Schritt 7
1. Azure reserviert in jedem Subnetz (Subnet) 5 Adressen (Netzadresse, Gateway, zwei für DNS, Broadcast): 256 − 5 = 251.
2. `10.10.3.0/29` funktioniert. `10.10.2.0/29` überlappt mit `snet-intern`, `10.11.0.0/29` liegt ausserhalb des Adressraums (Address Space).
3. 1. Befehl `NetcfgSubnetRangesOverlap` → überlappt. 2. Befehl `NetcfgSubnetRangeOutsideVnet` → nicht im Adressraum (Address Space).

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| `--subnet-prefixes` mit `/16` | Adressraum (Address Space) und Subnetz (Subnet) verwechselt | Subnetz (Subnet) löschen, neu mit `/24` |
| `snet-test` doch erstellt | Tippfehler im Bereich | `az network vnet subnet delete … --name snet-test` |
| VNet in falscher Region | Ressourcengruppe (Resource Group) in einer anderen Region erstellt | Ressourcengruppe (Resource Group) löschen, mit Kursregion neu |

## Hinweise für die Kursleitung
- VNets und Subnetze (Subnets) kosten nichts. Darum dürfen sie bis zum Ende von 4.5 stehen bleiben.
- Gute Gelegenheit, die Fehlermeldung gemeinsam zu lesen: Fehlermeldungen von Azure sind lang, das Wichtigste steht im Code in der Klammer.
- Neue Subnetze (Subnets) sind seit 2026 standardmässig privat (kein standardmässiger ausgehender Zugriff (Default Outbound Access)). Für 4.3 ist das kein Problem, weil `vm-web` eine öffentliche IP (Public IP) hat und `vm-intern` nicht ins Internet muss. <!-- prüfen -->
