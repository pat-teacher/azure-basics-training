# Lösung 4.4: Sicherheitsregeln – Web für alle, SSH nur von der Schule

Beispiel mit Kürzel `mm`, öffentlicher IP (Public IP) `20.208.51.90` und Schul-IP `198.51.100.23`.

## Schritt 1
```text
$ curl localhost
<h1>Webshop auf vm-web-mm</h1>
```

## Schritt 2
Zeitüberschreitung im Browser. Keine Sicherheitsregel (Security Rule) für Port 80, darum gilt `DenyAllInBound` (65500).

## Schritt 3
```bash
az network nsg rule create --resource-group rg-tag4-mm --nsg-name nsg-web --name allow-http --priority 200 --direction Inbound --access Allow --protocol Tcp --destination-port-ranges 80 --source-address-prefixes Internet
```
Website zeigt «Webshop auf vm-web-mm», auch beim Partner.

## Schritt 4
```text
$ echo $SSH_CLIENT
198.51.100.23 51234 22
```

## Schritt 5
```bash
az network nsg rule update --resource-group rg-tag4-mm --nsg-name nsg-web --name allow-ssh --source-address-prefixes 198.51.100.23/32
```
SSH klappt.

## Schritt 6
```bash
az network nsg rule update --resource-group rg-tag4-mm --nsg-name nsg-web --name allow-ssh --source-address-prefixes 203.0.113.10/32
```
```text
ssh: connect to host 20.208.51.90 port 22: Connection timed out
```
Website lädt weiter. Danach wieder `198.51.100.23/32`.

## Schritt 7
| Zustand | Website | Grund |
|---------|---------|-------|
| `deny-http` 150, `allow-http` 200 | lädt nicht | 150 wird zuerst geprüft, passt, Deny |
| `deny-http` 300, `allow-http` 200 | lädt | 200 wird zuerst geprüft, passt, Allow |

```bash
az network nsg rule create --resource-group rg-tag4-mm --nsg-name nsg-web --name deny-http --priority 150 --direction Inbound --access Deny --protocol Tcp --destination-port-ranges 80 --source-address-prefixes Internet
az network nsg rule update --resource-group rg-tag4-mm --nsg-name nsg-web --name deny-http --priority 300
az network nsg rule delete --resource-group rg-tag4-mm --nsg-name nsg-web --name deny-http
```

## Schritt 8

## Schritt 9
1. … `/32` genau **eine** Adresse bedeutet (alle 32 Bits sind fix).
2. Lädt nicht, weil 100 zuerst geprüft wird.
3. Zum Beispiel: «`Internet` heisst die ganze Welt. Dann kann jeder versuchen, sich anzumelden. Erlaube SSH nur von der Adresse, von der du arbeitest.»

## Typische Fehler

| Problem | Ursache | Lösung |
|---------|---------|--------|
| `echo $SSH_CLIENT` leer | in der Cloud Shell ausgeführt | in der SSH-Sitzung ausführen |
| eigene SSH-Sitzung bleibt in Schritt 6 offen | bestehende Verbindungen werden durch eine geänderte Sicherheitsregel (Security Rule) nicht sofort getrennt | vor dem Test `exit`, dann neu verbinden |
| Schul-IP in Schritt 5 falsch, Aussperrung | Tippfehler | mit richtiger IP wiederholen (Cloud Shell braucht kein SSH) |
| Schul-IP wechselt | Schule hat mehrere öffentliche IP-Adressen (Public IPs) | Bereich der Schule verwenden (Kursleitung) oder Schritt 4 wiederholen |
| `deny-http` mit Priorität (Priority) 200 | gleiche Priorität (Priority) wie `allow-http` | Fehler `SecurityRuleConflict`; andere Zahl |

## Hinweise für die Kursleitung
- Die Schul-IP vorab ermitteln (z. B. selbst `echo $SSH_CLIENT` auf einer Test-VM) und an die Wandtafel schreiben. Hat die Schule mehrere öffentliche Adressen, mit dem Bereich arbeiten, z. B. `/29`. <!-- prüfen -->
- Vorhersagen sind der Kern: Wer sie aufschreibt, merkt den Unterschied zwischen «geht» und «warum geht es». Kurz in der Klasse fragen: Wer lag bei Schritt 7 falsch?
- Das Exit-Ticket des Tages entspricht Frage 2.
- Wer das Handy im mobilen Netz hat, kann die Website auch von dort öffnen: «für alle» sichtbar machen.
