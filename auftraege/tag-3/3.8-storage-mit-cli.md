# Auftrag ⭐ 3.8: Speicherkonto ganz mit der CLI – hochladen, abfragen, retten, teilen

Zeit: ca. 60 Min. · Form: Einzelarbeit, freiwillig

> [!TIP]
> Anders als in den Aufträgen 3.4 bis 3.6 klickst du hier nicht im Portal. Du machst alles mit der Azure CLI in der Cloud Shell. Die meisten Befehle findest du selbst: mit `--help`, in den Links unter «Quellen» und in den Tipps zum Aufklappen. Öffne einen Tipp erst, wenn du nicht mehr weiterkommst.

## Ziel
- Du kannst mit der Azure CLI ein Speicherkonto (Storage Account) erstellen und mehrere Dateien auf einmal hochladen. (K3)
- Du kannst Blobs mit `--query` als eigene Tabelle anzeigen und ihre Zugriffsebene (Access Tier) ändern. (K3)
- Du kannst mit vorläufigem Löschen (Soft Delete) eine gelöschte Datei wiederherstellen. (K3)
- Du kannst mit der Azure CLI einen zeitlich begrenzten SAS-Link erstellen und testen. (K3)

## Voraussetzungen
- Aufträge 3.4 und 3.5 erledigt (du kennst Container, Blob und Zugriffsebene (Access Tier) aus dem Portal). ⭐ 3.6 (SAS im Portal) ist hilfreich, aber nicht nötig.
- Cloud Shell (Bash) wie in Auftrag 2.4, deine Kursregion aus Auftrag 2.2
- Lernjournal: Ordner `tag-3/3.8-storage-mit-cli`

## Ausgangslage
Die Velo Zürich AG legt jede Woche neue Preislisten ab. Im Portal ist das viel Klickarbeit. Du zeigst, dass es mit ein paar Befehlen geht. Und weil im Team schon einmal eine Preisliste aus Versehen gelöscht wurde, richtest du einen «Papierkorb» ein: das **vorläufige Löschen** (Soft Delete). Gelöschte Dateien bleiben dann ein paar Tage wiederherstellbar.

| Was | Name (Beispiel für `mm`) |
|-----|--------------------------|
| Ressourcengruppe (Resource Group) | `rg-tag3-st-mm` |
| Speicherkonto (Storage Account) | `sttag3climm` (nur Kleinbuchstaben und Ziffern) |
| Container | `preise` |

## Auftrag

### Schritt 1: Ressourcengruppe und Speicherkonto erstellen
Erstelle mit der Azure CLI die Ressourcengruppe (Resource Group) mit den Tags aus Auftrag 2.4 und darin das Speicherkonto (Storage Account). Es soll die gleichen Einstellungen haben wie in Auftrag 3.4: Leistung (Performance) **Standard**, Redundanz (Redundancy) **LRS**, Typ **StorageV2**.

<details>
<summary>Tipp 1</summary>

Die Ressourcengruppe (Resource Group) erstellst du wie in Auftrag 2.4. Für das Speicherkonto (Storage Account): `az storage account create --help`. Leistung und Redundanz (Redundancy) stecken zusammen in **einer** Option.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst:
```bash
az storage account create --resource-group … --name … --sku Standard_LRS --kind StorageV2
```
</details>

**Kontrolle:** In der Ausgabe steht `"provisioningState": "Succeeded"`. Meldet Azure, dass der Name vergeben ist, hängst du zwei Ziffern an.

### Schritt 2: Name und Schlüssel in Variablen speichern
Damit du nicht bei jedem Befehl den Namen und den Zugriffsschlüssel (Access Key) eintippen musst, speicherst du beides in Variablen:
```bash
ST=sttag3cli<kuerzel>
STKEY=$(az storage account keys list --resource-group rg-tag3-st-<kuerzel> --account-name $ST --query "[0].value" --output tsv)
echo ${#STKEY}
```
`keys list` zeigt die beiden Zugriffsschlüssel (Access Keys) des Speicherkontos (Storage Account). `$(…)` setzt die Ausgabe des Befehls in die Variable `STKEY`. `${#STKEY}` zeigt, wie viele Zeichen in der Variablen stehen.

**Kontrolle:** Die Ausgabe ist eine Zahl, meist `88`. Steht dort `0`, ist die Variable leer: Name oder Ressourcengruppe (Resource Group) prüfen.

> [!CAUTION]
> Der Zugriffsschlüssel (Access Key) ist wie ein Generalschlüssel für das ganze Speicherkonto (Storage Account). Gib ihn nie aus (`echo $STKEY`), und schreib ihn nie ins Lernjournal.

Ab jetzt hängst du an jeden Befehl für Container und Blobs `--account-name $ST --account-key $STKEY` an.

### Schritt 3: Drei Preislisten in einem Rutsch hochladen
Erstelle in der Cloud Shell einen Ordner mit drei Dateien:
```bash
mkdir preise
echo "Citybike: 890 CHF" > preise/citybike.txt
echo "E-Bike: 2990 CHF" > preise/ebike.txt
echo "Kindervelo: 290 CHF" > preise/kindervelo.txt
```
Erstelle jetzt den Container `preise` und lade den **ganzen Ordner mit einem Befehl** hoch.

<details>
<summary>Tipp 1</summary>

Container: `az storage container create --help`. Für viele Dateien gibt es bei `az storage blob` einen Befehl mit `batch` im Namen.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst:
```bash
az storage container create --name preise --account-name $ST --account-key $STKEY
az storage blob upload-batch --destination … --source … --account-name $ST --account-key $STKEY
```
</details>

**Kontrolle:** `az storage blob list --container-name preise --account-name $ST --account-key $STKEY --output table` zeigt die drei Dateien.

### Schritt 4: Eine eigene Tabelle
Zeige alle Blobs im Container als Tabelle mit drei Spalten: **Name**, **Bytes** (Grösse) und **Ebene** (Zugriffsebene (Access Tier)).

<details>
<summary>Tipp 1</summary>

Schau dir zuerst die volle Ausgabe von `az storage blob list … --output json` an. Grösse und Ebene stecken im Bereich `properties`.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst, aufgebaut wie `--query` in Auftrag 2.4, Schritt 3:
```bash
az storage blob list --container-name preise --account-name $ST --account-key $STKEY --query "[].{Name:name, Bytes:properties.contentLength, Ebene:properties.blobTier}" --output table
```
</details>

**Kontrolle:** Drei Zeilen. Bei allen steht die Ebene **Hot**.

### Schritt 5: Zugriffsebene ändern
Das E-Bike ist ein Auslaufmodell, die Preisliste wird kaum noch gelesen. Setze `ebike.txt` auf die Zugriffsebene (Access Tier) **Cool**, wie in Auftrag 3.4, Schritt 7, aber mit der CLI.

<details>
<summary>Tipp</summary>

Bei `az storage blob --help` gibt es einen Befehl mit `tier` im Namen.
</details>

**Kontrolle:** Die Tabelle aus Schritt 4 zeigt bei `ebike.txt` jetzt **Cool**, bei den anderen **Hot**.

### Schritt 6: Der Papierkorb – vorläufiges Löschen
1. Schalte das vorläufige Löschen (Soft Delete) für Blobs ein. Gelöschte Blobs sollen **7 Tage** wiederherstellbar sein.
2. Lösche danach `citybike.txt`.
3. Zeige die Blobs an: `citybike.txt` fehlt.
4. Zeige jetzt auch die gelöschten Blobs an.
5. Stelle `citybike.txt` wieder her.

<details>
<summary>Tipp 1 (einschalten)</summary>

Die Einstellung gehört zum Blob-Dienst des Speicherkontos (Storage Account): `az storage account blob-service-properties update --help`. Suche nach «delete retention».
</details>

<details>
<summary>Tipp 2 (gelöschte anzeigen, wiederherstellen)</summary>

`az storage blob list --help`: Mit `--include` zeigst du zusätzliche Blobs an. Ein Buchstabe steht für «deleted». Ob ein Blob gelöscht ist, siehst du mit diesem Anhang:
```bash
--query "[].{Name:name, Geloescht:deleted}" --output table
```
Zum Wiederherstellen gibt es bei `az storage blob` den Befehl `undelete`.
</details>

**Kontrolle:**
- Nach Punkt 3: zwei Zeilen, `citybike.txt` fehlt.
- Nach Punkt 4: drei Zeilen, bei `citybike.txt` steht in der Spalte `Geloescht` der Wert `True`.
- Nach Punkt 5: Die Tabelle aus Schritt 4 zeigt wieder drei Dateien.

### Schritt 7: SAS-Link mit der CLI
Erstelle für `citybike.txt` einen SAS-Link, der nur **lesen** darf und in **15 Minuten** abläuft, wie in Auftrag 3.6, aber mit der CLI. Teste ihn danach in der Cloud Shell mit `curl`.

Die Ablaufzeit muss in UTC angegeben werden. Diesen Teil bekommst du:
```bash
ABLAUF=$(date -u -d "+15 minutes" '+%Y-%m-%dT%H:%MZ')
echo $ABLAUF
```
`date` rechnet die Uhrzeit in 15 Minuten aus und gibt sie im Format aus, das Azure erwartet.

<details>
<summary>Tipp 1</summary>

`az storage blob generate-sas --help`. Du brauchst die Berechtigung (r = read), die Ablaufzeit und eine Option, die gleich die ganze Adresse (URL) ausgibt.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst:
```bash
URL=$(az storage blob generate-sas --container-name preise --name citybike.txt --permissions r --expiry $ABLAUF --full-uri --account-name $ST --account-key $STKEY --output tsv)
curl "$URL"
```
</details>

**Kontrolle:**
- `curl "$URL"` zeigt «Citybike: 890 CHF».
- Ohne Token, nur der Teil vor dem `?`, kommt eine Fehlermeldung in XML, z. B. `PublicAccessNotPermitted` oder `ResourceNotFound`. Teste das mit `curl "${URL%%\?*}"`. Der Ausdruck schneidet alles ab dem `?` ab.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `The specified account name is already taken` | Zwei Ziffern an den Namen hängen und Schritt 2 mit dem neuen Namen wiederholen. |
| Warnung `There are no credentials provided …` | `--account-name $ST --account-key $STKEY` vergessen. Der Befehl läuft trotzdem, weil die CLI den Schlüssel selbst holt. Hänge die Optionen trotzdem an. |
| `AuthenticationFailed` oder `AuthorizationFailure` bei Container oder Blob | `STKEY` ist leer oder falsch (`echo ${#STKEY}` zeigt `0`). Schritt 2 wiederholen. |
| Die Variablen sind weg | Die Cloud Shell hat die Verbindung getrennt (nach 20 Minuten ohne Eingabe). Schritt 2 wiederholen. |
| `upload-batch` meldet, dass der Ordner fehlt | Du bist nicht im Ordner, in dem `preise` liegt. Mit `ls` prüfen, sonst `cd ~`. |
| `undelete` hat keine Wirkung | Das vorläufige Löschen (Soft Delete) war beim Löschen noch nicht eingeschaltet. Dann ist die Datei endgültig weg: Neu hochladen und Punkt 2–5 wiederholen. |
| `curl` zeigt `AuthenticationFailed` | Ablaufzeit vorbei oder falsch geschrieben. `ABLAUF` neu setzen und den Link neu erstellen. |
