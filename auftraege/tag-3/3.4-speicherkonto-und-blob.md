# Auftrag 3.4: Speicherkonto und Blob-Container, Dateien hochladen

Zeit: 40 Min. · Form: Einzelarbeit

## Ziel
- Du kannst ein Speicherkonto (Storage Account) mit passender Redundanz (Redundancy) erstellen. (K3)
- Du kannst einen Container anlegen und Dateien als Blob hochladen. (K3)
- Du kannst erklären, warum eine Datei im Blob-Speicher (Blob Storage) nicht automatisch öffentlich ist. (K2)

## Voraussetzungen
- Input «Azure Storage» gehört
- Deine **Kursregion** aus Auftrag 2.2
- Cloud Shell (Bash) wie in Auftrag 2.4
- Theorie zum Nachlesen: [Kapitel 5 Azure Storage](../../theorie/05-azure-storage.md)
- Lernjournal: Ordner `tag-3/3.4-speicherkonto-und-blob`

## Ausgangslage
Die Velo Zürich AG will ihre Preisliste und Produktbilder in der Cloud ablegen. Dafür braucht es keine VM: Ein **Speicherkonto** (Storage Account) speichert Dateien direkt. Darin legst du einen **Container** an, das ist wie ein Ordner. Jede Datei darin heisst **Blob**.

| Was | Wert (Beispiel für `mm`) |
|-----|--------------------------|
| Ressourcengruppe (Resource Group) | `rg-tag3-storage-mm` |
| Speicherkonto (Storage Account) | `sttag3mm` |
| Container | `dateien` |

Der Name des Speicherkontos (Storage Account) muss **weltweit** eindeutig sein und darf nur Kleinbuchstaben und Ziffern enthalten (3–24 Zeichen). Er wird Teil einer Internetadresse.

## Auftrag

### Schritt 1: Ressourcengruppe erstellen (Cloud Shell)
Erstelle die Ressourcengruppe (Resource Group) wie in Auftrag 3.3, Schritt 1. `<region>` ist der kurze Name deiner Kursregion, z. B. `switzerlandnorth`.
```bash
az group create --name rg-tag3-storage-<kuerzel> --location <region> --tags kurs=azure-basics tag=3 owner=<kuerzel>
```
**Kontrolle:** In der Ausgabe steht `"provisioningState": "Succeeded"`.

### Schritt 2: Speicherkonto erstellen (Portal)
1. Tippe ins Suchfeld **Speicherkonten** (Storage Accounts) und öffne den Dienst. Klicke auf **+ Erstellen**.
2. Fülle im Reiter **Grundeinstellungen** (Basics) aus. Alle anderen Felder lässt du, wie sie sind.

| Feld | Wert |
|------|------|
| Abonnement (Subscription) | **Azure for Students** |
| Ressourcengruppe (Resource Group) | `rg-tag3-storage-<kuerzel>` |
| Speicherkontoname | `sttag3<kuerzel>` |
| Region | deine Kursregion |
| Leistung (Performance) | **Standard** |
| Redundanz (Redundancy) | **Lokal redundanter Speicher (LRS)** |

<!-- prüfen: Stand 08.11.2026 – Feldnamen im deutschen Portal -->

3. Klicke auf **Überprüfen + erstellen** und dann auf **Erstellen**.

**Kontrolle:** Nach etwa einer Minute steht «Ihre Bereitstellung wurde abgeschlossen». Klicke auf **Zu Ressource wechseln**.

> [!NOTE]
> Meldet das Feld «Speicherkontoname» einen Fehler wie «bereits vergeben»? Dann hat jemand auf der Welt diesen Namen schon. Hänge zwei Ziffern an, z. B. `sttag3mm07`, und verwende diesen Namen im ganzen Auftrag.

### Schritt 3: Die Adresse des Speicherkontos finden
Klicke links auf **Einstellungen** > **Endpunkte** (Endpoints).

**Kontrolle:** Bei «Blob-Dienst» steht `https://sttag3<kuerzel>.blob.core.windows.net/`. Der Name deines Speicherkontos (Storage Account) ist Teil der Adresse. Darum muss er weltweit eindeutig sein.
<!-- prüfen: Stand 08.11.2026 – Menüpfad «Endpunkte» -->

### Schritt 4: Container anlegen
1. Klicke links auf **Datenspeicher** > **Container**.
2. Klicke auf **+ Container**.
3. Name: `dateien`. Bei «Anonyme Zugriffsebene» steht **Privat**: Ohne Berechtigung kann niemand die Dateien lesen. Das lässt du so.
4. Klicke auf **Erstellen**.

**Kontrolle:** In der Liste steht der Container `dateien`, in der Spalte für den anonymen Zugriff (Anonymous Access) steht **Privat**.

### Schritt 5: Datei hochladen
1. Erstelle auf deinem Laptop im Editor (Notepad) eine Datei mit diesem Inhalt:
   ```text
   Velo Zuerich AG - Preisliste
   Citybike: 890 CHF
   E-Bike: 2990 CHF
   ```
   Speichere sie als `preisliste.txt`.
2. Öffne im Portal den Container `dateien` und klicke auf **Hochladen**.
3. Wähle die Datei `preisliste.txt` aus und klicke auf **Hochladen**.

**Kontrolle:** Im Container steht der Blob `preisliste.txt` mit Grösse und Zugriffsebene (Access Tier) **Hot**.

### Schritt 6: Ist die Datei öffentlich?
1. Klicke auf `preisliste.txt`. Kopiere rechts die **URL** mit dem Kopier-Symbol.
2. Öffne ein privates Browserfenster (`Ctrl` + `Shift` + `N` in Edge und Chrome). Füge die URL ein und drücke `Enter`.

**Kontrolle:** Du siehst **nicht** die Preisliste, sondern eine Fehlermeldung in XML, z. B. `PublicAccessNotPermitted` oder `ResourceNotFound`. Das ist **richtig so**: Der Container ist privat. Nur wer berechtigt ist, sieht die Datei.
<!-- prüfen: Stand 08.11.2026 – genauer Fehlercode bei einem neuen Speicherkonto -->

### Schritt 7: Zugriffsebene ändern
Die Preisliste wird selten gelesen. Darum verschiebst du sie in eine günstigere Zugriffsebene (Access Tier).

1. Klicke im Container `dateien` beim Blob `preisliste.txt` rechts auf **…** > **Ebene ändern**.
2. Wähle **Cool** und klicke auf **Speichern**.

**Kontrolle:** In der Liste steht bei `preisliste.txt` jetzt die Zugriffsebene (Access Tier) **Cool**.

### Schritt 8: Fragen
Beantworte im Lernjournal.

1. Ergänze: Bei LRS speichert Azure ______ Kopien meiner Daten in ______ Rechenzentrum.
2. Ordne jedem Fall die passende Zugriffsebene (Access Tier) zu: **Hot**, **Cool** oder **Archive**.

   | Fall | Zugriffsebene (Access Tier) |
   |------|------------------------------|
   | Bilder im Webshop, täglich tausendfach angezeigt | |
   | Backup vom letzten Monat, nur für den Notfall | |
   | Buchhaltung von 2019, muss 10 Jahre aufbewahrt werden | |

3. Kreuze an: Warum hat Schritt 6 eine Fehlermeldung gezeigt?
   - [ ] Die Datei ist beim Hochladen kaputtgegangen.
   - [ ] Der Container ist privat, nur Berechtigte dürfen lesen.
   - [ ] Speicherkonten (Storage Accounts) sind nur aus Azure erreichbar.

### Schritt 9: Weiter oder aufräumen?
Machst du gleich mit Auftrag 3.5 weiter? Dann lässt du das Speicherkonto (Storage Account) stehen. Du brauchst es dort wieder.

Sonst räumst du jetzt auf:
```bash
az group delete --name rg-tag3-storage-<kuerzel> --yes --no-wait
```
**Kontrolle:** Nach 1–2 Minuten zeigt `az group list --output table` die Gruppe nicht mehr.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| Speicherkontoname «ungültig» | Nur Kleinbuchstaben und Ziffern, keine Bindestriche, 3–24 Zeichen. |
| Speicherkontoname «bereits vergeben» | Zwei Ziffern anhängen, z. B. `sttag3mm07`. |
| Beim Öffnen des Containers: «Sie haben keine Berechtigung» | Oben auf **Zu Zugriffsschlüssel wechseln** klicken (Authentifizierungsmethode). Hilft das nicht: Kursleitung holen. |
| **Ebene ändern** fehlt | Auf den Blob klicken und oben **Ebene ändern** wählen. |
