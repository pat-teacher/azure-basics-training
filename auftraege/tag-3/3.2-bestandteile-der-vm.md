# Auftrag 3.2: Was gehört alles zur VM?

Zeit: 30 Min. · Form: Partnerarbeit

## Ziel
- Du kannst die Ressourcen nennen, die Azure für eine VM anlegt, und ihre Aufgabe zuordnen. (K2)
- Du kannst erklären, welcher Status einer VM was kostet. (K2)

## Voraussetzungen
- Auftrag 3.1 erledigt, deine VM `vm-portal-<kuerzel>` läuft
- Theorie zum Nachlesen: [Kapitel 4 Azure Compute](../../theorie/04-azure-compute.md), Abschnitte «Woraus besteht eine VM?» und «Status und Kosten»
- Lernjournal: Ordner `tag-3/3.2-bestandteile-der-vm`

## Ausgangslage
Du hast im Portal **eine** VM bestellt. In deiner Ressourcengruppe (Resource Group) liegen aber mehr Ressourcen. Die Geschäftsleitung der Velo Zürich AG fragt: «Was ist das alles, und was davon kostet?» Ihr findet es zu zweit heraus. Jede Person arbeitet in ihrem eigenen Portal, ihr vergleicht die Ergebnisse.

## Auftrag

### Schritt 1: Ressourcen auflisten
Öffne im Portal `rg-tag3-portal-<kuerzel>`.

**Kontrolle:** Unten in der Übersicht stehen sechs Ressourcen. Klicke auf **Ausgeblendete Typen anzeigen** (Show hidden types), falls es weniger sind.
<!-- prüfen: Stand 08.11.2026 – Anzahl Ressourcen und Bezeichnung des Schalters im Portal -->

### Schritt 2: Ressourcen zuordnen
Übertrage die Tabelle ins Lernjournal. Trage in der Spalte «Name in deiner Gruppe» den Namen aus dem Portal ein. Ordne danach jeder Zeile die passende Aufgabe aus der Liste A–F zu.

| Typ im Portal | Name in deiner Gruppe | Aufgabe (A–F) |
|---------------|-----------------------|---------------|
| Virtueller Computer (Virtual Machine) | | |
| Datenträger (Disk) | | |
| Netzwerkschnittstelle (Network Interface) | | |
| Virtuelles Netzwerk (Virtual Network) | | |
| Öffentliche IP-Adresse (Public IP) | | |
| Netzwerksicherheitsgruppe (Network Security Group) | | |

**Aufgaben:**
- **A** Firewall-Regeln: Was darf in die VM hinein, was hinaus?
- **B** CPU und Arbeitsspeicher (RAM), also die eigentliche Rechenleistung
- **C** Festplatte mit dem Betriebssystem Ubuntu
- **D** Adresse, über die die VM aus dem Internet erreichbar ist
- **E** «Netzwerkkarte» der VM, sie bekommt eine private IP-Adresse
- **F** privates Netz in Azure, in dem die VM hängt

**Kontrolle:** Jeder Buchstabe kommt genau einmal vor. Vergleicht eure Tabellen. Die Namen sind verschieden, die Zuordnung ist gleich.

### Schritt 3: Private und öffentliche IP
Öffne die Netzwerkschnittstelle (Network Interface) deiner VM.

**Kontrolle:** Auf der Übersicht stehen eine **private IP-Adresse**, z. B. `10.0.0.4`, und deine öffentliche IP (Public IP) aus Auftrag 3.1. Notiere beide.

Kreuze im Lernjournal an:

| Aussage | private IP | öffentliche IP (Public IP) |
|---------|:---:|:---:|
| Mit dieser Adresse hast du dich in 3.1 per SSH angemeldet. | | |
| Diese Adresse ist nur innerhalb des virtuellen Netzwerks (Virtual Network) erreichbar. | | |
| Bei deinem Partner kann es dieselbe Adresse sein. | | |

### Schritt 4: Die Regel für SSH finden
Öffne die Netzwerksicherheitsgruppe (Network Security Group) und klicke links auf **Eingangssicherheitsregeln** (Inbound Security Rules).

**Kontrolle:** Es gibt eine Regel mit Port `22` und der Aktion **Zulassen** (Allow). Notiere ihre **Priorität** (Priority) und die **Quelle** (Source).

### Schritt 5: VM beenden
Eine VM kostet Geld, solange die Hardware für sie reserviert ist. Du beendest sie jetzt im Portal und beobachtest den Status.

1. Öffne die VM `vm-portal-<kuerzel>` und klicke oben auf **Beenden** (Stop). Bestätige mit **OK**.
2. Warte etwa eine Minute und klicke auf **Aktualisieren** (Refresh).

**Kontrolle:** Der Status ist **Beendet (Zuordnung aufgehoben)** (Stopped (deallocated)). Die öffentliche IP (Public IP) ist immer noch dieselbe.

Kreuze im Lernjournal an: Was kostet in diesem Status noch Geld?

| Ressource | kostet noch | kostet nichts |
|-----------|:---:|:---:|
| Rechenleistung (CPU, RAM) | | |
| OS-Datenträger (OS Disk) | | |
| öffentliche IP (Public IP) | | |

Und ergänze: Fahre ich die VM mit `sudo poweroff` von innen herunter, dann kostet die Rechenleistung ______________, weil ______________.

### Schritt 6: Aufräumen
Du brauchst die VM nicht mehr. In Auftrag 3.3 erstellst du eine neue mit der Azure CLI.

1. Öffne `rg-tag3-portal-<kuerzel>` und klicke auf **Ressourcengruppe löschen** (Delete resource group).
2. Tippe den Namen `rg-tag3-portal-<kuerzel>` zur Bestätigung ein und klicke auf **Löschen** (Delete).

**Kontrolle:** Nach 2–5 Minuten erscheint «Ressourcengruppe gelöscht» (Deleted resource group). In der Liste **Ressourcengruppen** (Resource Groups) fehlt `rg-tag3-portal-<kuerzel>` (evtl. mit **Aktualisieren** (Refresh) neu laden).

> [!NOTE]
> Bleibt eine Ressourcengruppe (Resource Group) `NetworkWatcherRG` stehen, ist das in Ordnung. Azure legt sie automatisch an, sie kostet nichts.

## Erwartetes Ergebnis
Im Lernjournal:
- Tabelle aus Schritt 2 mit Namen und Aufgaben
- private und öffentliche IP (Public IP) und die Tabelle aus Schritt 3
- Priorität (Priority) und Quelle der SSH-Regel (Schritt 4)
- Tabelle und Lückentext aus Schritt 5
- Notiz: Ressourcengruppe (Resource Group) gelöscht (Schritt 6)

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| VM ist nicht mehr da | Hast du sie schon gelöscht? Arbeite mit deinem Partner in seinem Portal weiter. |
| Status bleibt **Wird beendet** (Stopping) | Etwas warten und **Aktualisieren** (Refresh) klicken. |
| Löschen dauert sehr lange | Normal bei VMs: bis zu 5 Minuten. Du kannst mit Auftrag 3.3 beginnen. |

## Zusatzaufgabe ⭐
Klicke vor dem Aufräumen in der Ressourcengruppe (Resource Group) links auf **Kostenanalyse** (Cost Analysis). Siehst du schon Kosten? Warum (nicht)? Antworte in einem Satz.
