# Auftrag 3.6 ⭐: Datei per SAS-Token zeitlich begrenzt teilen

Zeit: 20 Min. · Form: Einzelarbeit, freiwillig

## Ziel
- Du kannst für einen Blob einen Link mit SAS-Token erstellen, der nur kurz gültig ist. (K3)
- Du kannst erklären, warum man einen SAS-Link teilt und nicht den Zugriffsschlüssel (Access Key). (K2)

## Voraussetzungen
- Auftrag 3.4 erledigt: Im Container `dateien` liegt `preisliste.txt`, der Container ist **privat**
- Cloud Shell (Bash) für das Aufräumen
- Lernjournal: Ordner `tag-3/3.6-sas-token`

## Ausgangslage
Ein Velohändler soll die Preisliste der Velo Zürich AG lesen dürfen, aber nur heute und nur diese eine Datei. Den Container öffentlich machen geht nicht, sonst sieht jeder alles. Die Lösung ist ein **SAS-Token** (Shared Access Signature): ein Zusatz zur Adresse der Datei, der sagt, **was** erlaubt ist (z. B. nur lesen) und **bis wann**. Wer den Link hat, darf genau das, und nur bis zur Ablaufzeit.

## Auftrag

### Schritt 1: SAS-Link erstellen
1. Öffne im Portal dein Speicherkonto (Storage Account) `sttag3<kuerzel>` > **Container** > `dateien`.
2. Klicke beim Blob `preisliste.txt` rechts auf **…** > **SAS generieren**.
3. Fülle aus:
   - Berechtigungen: nur **Lesen**
   - Start: jetzt (vorgegeben)
   - Ablauf: **in 10 Minuten** (Uhrzeit von jetzt plus 10 Minuten eintragen)
4. Klicke auf **SAS-Token und -URL generieren**.

<!-- prüfen: Stand 08.11.2026 – Bezeichnungen im deutschen Portal -->

**Kontrolle:** Unten erscheinen zwei Felder: **Blob-SAS-Token** und **Blob-SAS-URL**. Notiere die Ablaufzeit.

### Schritt 2: Den Link anschauen
Kopiere die **Blob-SAS-URL** in dein Lernjournal. Sie besteht aus zwei Teilen:
- vor dem `?`: die normale Adresse der Datei, wie in Auftrag 3.4
- nach dem `?`: das SAS-Token

**Kontrolle:** Im Token findest du `sp=r` (Berechtigung: read, also lesen) und `se=` mit deiner Ablaufzeit (in UTC, also 1–2 Stunden früher als die Schweizer Zeit).

### Schritt 3: Link testen
Öffne die Blob-SAS-URL in einem privaten Browserfenster.

**Kontrolle:** Du siehst den Inhalt von `preisliste.txt`. Ohne Token (nur der Teil vor dem `?`) kommt weiterhin die Fehlermeldung aus Auftrag 3.4.

### Schritt 4: Nach Ablauf nochmals testen
Warte, bis die Ablaufzeit vorbei ist. Arbeite in der Zwischenzeit an Schritt 5. Lade dann die Blob-SAS-URL neu.

**Kontrolle:** Jetzt kommt eine Fehlermeldung in XML mit `AuthenticationFailed`. Der Link ist abgelaufen.

### Schritt 5: Fragen
Beantworte im Lernjournal.

1. Kreuze an: Was darf der Velohändler mit deinem SAS-Link?

   | Aktion | erlaubt | nicht erlaubt |
   |--------|:---:|:---:|
   | `preisliste.txt` lesen, bevor der Link abläuft | | |
   | `preisliste.txt` ändern | | |
   | andere Dateien im Container `dateien` lesen | | |
   | `preisliste.txt` lesen, nachdem der Link abgelaufen ist | | |

2. Der Zugriffsschlüssel (Access Key) gibt vollen Zugriff auf das ganze Speicherkonto (Storage Account), ohne Ablaufdatum. Warum schickst du dem Velohändler den SAS-Link und nicht den Zugriffsschlüssel (Access Key)? Antworte in 1–2 Sätzen.

## Aufräumen
Lösche die Ressourcengruppe (Resource Group) mit dem Speicherkonto (Storage Account) in der Cloud Shell:
```bash
az group delete --name rg-tag3-storage-<kuerzel> --yes --no-wait
```
**Kontrolle:** Nach 1–2 Minuten zeigt `az group list --output table` keine Gruppe `rg-tag3-…` mehr.

Im Lernjournal:
- Blob-SAS-URL aus Schritt 2 (sie ist abgelaufen, darum darfst du sie zeigen)
- Screenshots aus Schritt 3 und Schritt 4
- Antworten aus Schritt 5
- Kontrolle aus «Aufräumen»

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| **SAS generieren** fehlt im Menü | Auf den Blob klicken und oben den Reiter **SAS generieren** wählen. |
| Link zeigt sofort `AuthenticationFailed` | Startzeit liegt in der Zukunft oder Ablaufzeit ist schon vorbei. Neuen Link mit Start «jetzt» erstellen. |
| Link funktioniert auch nach Ablauf noch | Browser zeigt eine gespeicherte Version. Mit `Ctrl` + `F5` neu laden. |
