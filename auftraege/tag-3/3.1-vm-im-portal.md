# Auftrag 3.1: Linux-VM im Portal erstellen und per SSH verbinden

Zeit: 45 Min. · Form: Einzelarbeit

## Ziel
- Du kannst im Azure-Portal eine Linux-VM mit deinem SSH-Schlüssel erstellen. (K3)
- Du kannst dich von deinem Laptop aus per SSH an der VM anmelden. (K3)

## Voraussetzungen
- Deine **Kursregion** aus Auftrag 2.2
- Dein SSH-Schlüsselpaar (Key Pair) aus Auftrag 1.6 im Ordner `~\.ssh`
- Input «Virtuelle Maschinen (Virtual Machines) in Azure» gehört
- Theorie zum Nachlesen: [Kapitel 4 Azure Compute](../../theorie/04-azure-compute.md)
- Lernjournal: Ordner `tag-3/3.1-vm-im-portal`

## Ausgangslage
Die Velo Zürich AG braucht einen kleinen Linux-Server für Tests. An Tag 1 hast du eine VM auf deinem Laptop gebaut. Heute läuft die VM in einem Rechenzentrum von Microsoft. Du meldest dich genau gleich an wie an Tag 1: mit SSH und deinem Schlüssel.

| Was | Wert (Beispiel für `mm`) |
|-----|--------------------------|
| Ressourcengruppe (Resource Group) | `rg-tag3-portal-mm` |
| Name der VM | `vm-portal-mm` |
| Benutzername auf der VM | `azureuser` |

> [!IMPORTANT]
> Eine laufende VM kostet Guthaben (Credit). Du löschst sie am Ende von Auftrag 3.2. Lass sie nicht über Nacht laufen.

## Auftrag

### Schritt 1: Deinen öffentlichen Schlüssel kopieren
Öffne auf deinem Laptop PowerShell und zeige deinen öffentlichen Schlüssel (Public Key) an:
```powershell
Get-Content ~\.ssh\id_ed25519.pub
```
`Get-Content` zeigt den Inhalt einer Datei, wie in Auftrag 1.6.

**Kontrolle:** Eine lange Zeile, die mit `ssh-ed25519 AAAA` beginnt. Markiere die **ganze** Zeile und kopiere sie mit `Ctrl` + `C`. Lass PowerShell offen.

> [!WARNING]
> Kopiere nur die Datei mit der Endung `.pub`. Den privaten Schlüssel (Private Key) `id_ed25519` ohne Endung gibst du nie heraus.

### Schritt 2: Ressourcengruppe erstellen
Erstelle im Portal die Ressourcengruppe (Resource Group) wie in Auftrag 2.3:
- Name: `rg-tag3-portal-<kuerzel>`
- Region: deine Kursregion
- Tags: `kurs` = `azure-basics`, `tag` = `3`, `owner` = `<kuerzel>`

**Kontrolle:** In der Liste **Ressourcengruppen** (Resource Groups) steht `rg-tag3-portal-<kuerzel>`.

### Schritt 3: Den Assistenten für die VM öffnen
1. Tippe ins Suchfeld **Virtuelle Computer** und öffne den Dienst. So heisst die VM im deutschen Portal.
2. Klicke auf **+ Erstellen** > **Virtueller Azure-Computer**.

**Kontrolle:** Du siehst den Reiter **Grundeinstellungen** (Basics) mit vielen Feldern.

### Schritt 4: Grundeinstellungen ausfüllen
Der Reiter ist lang. Fülle nur die Felder aus den drei Tabellen aus. Alle anderen lässt du, wie sie sind.
<!-- prüfen: Stand 08.11.2026 – Feldnamen im deutschen Portal und Verfügbarkeit von Standard_B1s im Student-Abo -->

**4a) Die VM selbst**

| Feld | Wert |
|------|------|
| Abonnement (Subscription) | **Azure for Students** |
| Ressourcengruppe (Resource Group) | `rg-tag3-portal-<kuerzel>` |
| Name des virtuellen Computers | `vm-portal-<kuerzel>` |
| Region | deine Kursregion |
| Verfügbarkeitsoptionen | **Keine Infrastrukturredundanz erforderlich** |
| Image | **Ubuntu Server 24.04 LTS** |
| Grösse (Size) | **Standard_B1s** (über **Alle Grössen anzeigen** suchen) |

Das **Image** ist die Vorlage für das Betriebssystem, wie Ubuntu bei Multipass an Tag 1. Die **Grösse** (Size) legt fest, wie viele Prozessoren (vCPU) und wie viel Arbeitsspeicher (RAM) die VM bekommt. `Standard_B1s` hat 1 vCPU und 1 GiB RAM, genug für Übungen.

**Kontrolle:** Bei «Grösse» steht `Standard_B1s` und daneben ein Preis pro Monat.

**4b) Anmeldung mit deinem SSH-Schlüssel**

| Feld | Wert |
|------|------|
| Authentifizierungstyp | **Öffentlicher SSH-Schlüssel** |
| Benutzername | `azureuser` |
| Quelle des öffentlichen SSH-Schlüssels | **Vorhandenen öffentlichen Schlüssel verwenden** |
| Öffentlicher SSH-Schlüssel | deine Zeile aus Schritt 1 einfügen (`Ctrl` + `V`) |

Azure legt deinen öffentlichen Schlüssel (Public Key) auf der VM ab, wie du es in Auftrag 1.6 von Hand gemacht hast.

**Kontrolle:** Unter dem Feld mit dem Schlüssel steht keine rote Fehlermeldung.

**4c) Welche Ports sind aus dem Internet erreichbar?**

| Feld | Wert |
|------|------|
| Öffentliche Eingangsports | **Ausgewählte Ports zulassen** |
| Eingangsports auswählen | **SSH (22)** |

Ein **Port** ist eine Nummer für einen Dienst auf dem Server. SSH läuft über Port 22. Nur was du hier auswählst, lässt Azure aus dem Internet herein.

**Kontrolle:** Direkt unter dem Feld erscheint eine gelbe Warnung, dass Port 22 aus dem Internet erreichbar ist. Das ist für die Übung in Ordnung.

### Schritt 5: VM erstellen
1. Klicke unten auf **Überprüfen + erstellen**.
2. Azure prüft deine Angaben und zeigt oben den Preis pro Stunde. Notiere ihn.
3. Klicke auf **Erstellen**.

**Kontrolle:** Nach 1–3 Minuten steht «Ihre Bereitstellung wurde abgeschlossen». Klicke auf **Zu Ressource wechseln**.

### Schritt 6: Die öffentliche IP nachschauen
Auf der Übersicht der VM siehst du rechts die **öffentliche IP-Adresse** (Public IP). Über diese Adresse ist deine VM aus dem Internet erreichbar.

**Kontrolle:** Der Status der VM ist **Wird ausgeführt** (Running). Bei «Öffentliche IP-Adresse» steht eine Adresse, z. B. `20.208.45.17`. Notiere sie.

### Schritt 7: Mit SSH anmelden
Wechsle zu PowerShell auf deinem Laptop. Dort liegt dein privater Schlüssel (Private Key).
```powershell
ssh azureuser@<öffentliche-ip>
```
Ersetze `<öffentliche-ip>` durch die Adresse aus Schritt 6, ohne die Klammern. Beim ersten Verbinden fragt SSH, ob du dem Server vertraust. Tippe `yes` und drücke `Enter`.

**Kontrolle:** Du wirst **nicht** nach einem Passwort gefragt. Die Eingabezeile sieht so aus: `azureuser@vm-portal-<kuerzel>:~$`

### Schritt 8: Die VM mit Tag 1 vergleichen
Gib in der VM diese drei Befehle ein. Du kennst sie von Tag 1:
```bash
hostname
nproc
free -h
```
`hostname` zeigt den Namen der VM, `nproc` die Anzahl Prozessoren, `free -h` den Arbeitsspeicher (RAM).

**Kontrolle:** `hostname` zeigt `vm-portal-<kuerzel>`, `nproc` zeigt `1`, bei `free -h` steht in der Zeile `Mem:` in der Spalte `total` knapp 1 GiB (z. B. `907Mi`).

Fülle im Lernjournal aus:

| | vm1 an Tag 1 (Multipass) | vm-portal heute (Azure) |
|---|---|---|
| Wo läuft die VM? | | |
| Wer hat den Hypervisor in Betrieb? | | |
| Betriebssystem | | |
| Anzahl vCPU | | |
| Arbeitsspeicher (RAM) | | |
| Anmeldung | | |
| Erreichbar von … | | |

### Schritt 9: Verbindung beenden
```bash
exit
```
**Kontrolle:** Du bist zurück in PowerShell (`PS C:\Users\…>`).

> [!IMPORTANT]
> Lösche die VM jetzt **nicht**. Du brauchst sie in Auftrag 3.2.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| Grösse `Standard_B1s` nicht verfügbar oder ausgegraut | Wähle `Standard_B2ats_v2`. Hilft das nicht: Kursleitung holen. |
| Fehler mit «quota» oder «Kontingent» | Du hast schon eine andere VM. Lösche alte Ressourcengruppen (Resource Groups) mit VMs und versuche es nochmals. |
| Fehler beim Schlüssel: «ungültig» | Du hast nicht die ganze Zeile kopiert. Schritt 1 wiederholen und alles von `ssh-ed25519` bis zum Ende der Zeile kopieren. |
| `Permission denied (publickey)` | Falscher Benutzername oder anderer Schlüssel. Benutzername ist `azureuser`. Prüfe im Portal unter der VM > **Einstellungen** > **Verbinden**, ob der richtige Schlüssel hinterlegt ist. |
| `Connection timed out` | IP abgeschrieben? VM läuft? Port 22 freigegeben (Schritt 4)? Blockiert das Schulnetz SSH, Kursleitung holen. |
| SSH fragt nach einem Passwort | Mit `Ctrl` + `C` abbrechen. Benutzername und IP prüfen. |
| `ssh` wird nicht erkannt | OpenSSH-Client fehlt. Siehe Auftrag 1.6, «Wenn etwas nicht klappt». |
