# Auftrag 3.3: Dieselbe VM mit der Azure CLI, Webserver von Hand

Zeit: 45 Min. · Form: Einzelarbeit

## Ziel
- Du kannst mit der Azure CLI eine Linux-VM erstellen und wieder löschen. (K3)
- Du kannst auf der VM einen Webserver installieren und einen Port für das Internet öffnen. (K3)

## Voraussetzungen
- Auftrag 3.2 erledigt, `rg-tag3-portal-<kuerzel>` ist gelöscht
- Cloud Shell (Bash) wie in Auftrag 2.4
- Dein öffentlicher Schlüssel (Public Key) aus Auftrag 1.6
- Lernjournal: Ordner `tag-3/3.3-vm-mit-cli`

## Ausgangslage
Im Portal waren es viele Felder und Klicks. Die Velo Zürich AG will bald mehrere Testserver. Darum erstellst du die VM jetzt mit **einem** Befehl in der Azure CLI. Danach machst du daraus einen Webserver, ganz von Hand, wie in Auftrag 1.4 auf deinem Laptop.

| Was | Wert (Beispiel für `mm`) |
|-----|--------------------------|
| Ressourcengruppe (Resource Group) | `rg-tag3-cli-mm` |
| Name der VM | `vm-web-mm` |

> [!TIP]
> Du arbeitest heute in zwei Fenstern: **Cloud Shell** im Browser für die Azure CLI, **PowerShell** auf deinem Laptop für SSH. Bei jedem Befehl steht, wo er hingehört.

## Auftrag

### Schritt 1: Ressourcengruppe erstellen (Cloud Shell)
Öffne die Cloud Shell (Bash) und erstelle die Ressourcengruppe (Resource Group) wie in Auftrag 2.4:
```bash
az group create --name rg-tag3-cli-<kuerzel> --location <region> --tags kurs=azure-basics tag=3 owner=<kuerzel>
```
`<region>` ist der kurze Name deiner Kursregion, z. B. `switzerlandnorth`.

**Kontrolle:** In der Ausgabe steht `"provisioningState": "Succeeded"`.

### Schritt 2: Deinen öffentlichen Schlüssel in der Cloud Shell speichern
1. **PowerShell:** Zeige deinen öffentlichen Schlüssel (Public Key) an und kopiere die ganze Zeile:
   ```powershell
   Get-Content ~\.ssh\id_ed25519.pub
   ```
2. **Cloud Shell:** Speichere die Zeile in der Variablen `KEY`. Eine Variable ist ein Platzhalter für einen Wert, wie `$key` in Auftrag 1.6. So gehts:
   - Tippe `KEY="`
   - Füge die kopierte Zeile ein (`Ctrl` + `Shift` + `V` oder Rechtsklick > **Einfügen**).
   - Tippe `"` und drücke `Enter`.

   Fertig sieht die Zeile so aus: `KEY="ssh-ed25519 AAAA… dein-name@dein-laptop"`
3. **Cloud Shell:** Prüfe, was in der Variablen steht:
   ```bash
   echo $KEY
   ```

**Kontrolle:** Die Ausgabe beginnt mit `ssh-ed25519 AAAA` und ist eine einzige lange Zeile.

### Schritt 3: VM erstellen (Cloud Shell)
```bash
az vm create --resource-group rg-tag3-cli-<kuerzel> --name vm-web-<kuerzel> --image Ubuntu2404 --size Standard_B1s --admin-username azureuser --ssh-key-values "$KEY" --public-ip-sku Standard
```
`vm create` erstellt die VM mit allem, was dazugehört. Die Optionen entsprechen den Feldern im Portal:

| Option | Feld im Portal |
|--------|----------------|
| `--image Ubuntu2404` | Image: Ubuntu Server 24.04 LTS |
| `--size Standard_B1s` | Grösse (Size) |
| `--admin-username azureuser` | Benutzername |
| `--ssh-key-values "$KEY"` | Öffentlicher SSH-Schlüssel |
| `--public-ip-sku Standard` | Art der öffentlichen IP (Public IP) |

Die Region musst du nicht angeben: Die VM kommt in die Region der Ressourcengruppe (Resource Group). Das Erstellen dauert 1–3 Minuten.
<!-- prüfen: Stand 08.11.2026 – Image-Alias Ubuntu2404 und Grösse Standard_B1s im Student-Abo -->

**Kontrolle:** Die Ausgabe ist ein JSON-Block mit `"powerState": "VM running"`. Bei `"publicIpAddress"` steht eine Adresse. Notiere sie.

### Schritt 4: Was ist entstanden? (Cloud Shell)
```bash
az resource list --resource-group rg-tag3-cli-<kuerzel> --output table
```
`resource list` zeigt alle Ressourcen in der Ressourcengruppe (Resource Group).

**Kontrolle:** Es sind sechs Ressourcen, die gleichen Typen wie in Auftrag 3.2: VM, Datenträger, Netzwerkschnittstelle (Network Interface), virtuelles Netzwerk (Virtual Network), öffentliche IP (Public IP) und NSG.

### Schritt 5: An der VM anmelden (PowerShell)
```powershell
ssh azureuser@<öffentliche-ip>
```
Ersetze `<öffentliche-ip>` durch die Adresse aus Schritt 3. Tippe beim ersten Verbinden `yes`.

**Kontrolle:** Die Eingabezeile ist `azureuser@vm-web-<kuerzel>:~$`.

### Schritt 6: Webserver installieren (in der VM)
Ein **Webserver** liefert Webseiten an Browser aus. Du installierst den Webserver **nginx**, wie in Auftrag 1.4.
```bash
sudo apt update
sudo apt install -y nginx
```
`sudo` führt einen Befehl mit Administratorrechten aus. `apt update` lädt die aktuelle Liste der Programme, `apt install -y nginx` installiert nginx ohne Rückfrage. Das dauert etwa eine Minute.

**Kontrolle:** In den letzten Zeilen steht `Setting up nginx …`. Es gibt keine Zeile, die mit `E:` beginnt (E steht für Error).

### Schritt 7: Startseite ersetzen (in der VM)
```bash
echo "<h1>Hallo von $(hostname)</h1>" | sudo tee /var/www/html/index.html
```
`echo` erzeugt eine Zeile HTML. `$(hostname)` setzt dort den Namen der VM ein. `sudo tee` schreibt die Zeile in die Startseite von nginx.

**Kontrolle:** `tee` zeigt die geschriebene Zeile an: `<h1>Hallo von vm-web-<kuerzel></h1>`.

### Schritt 8: Webserver auf der VM testen (in der VM)
```bash
curl localhost
```
`curl` ruft eine Webseite auf und zeigt ihren Text. `localhost` ist die VM selbst.

**Kontrolle:** Die Ausgabe ist `<h1>Hallo von vm-web-<kuerzel></h1>`. Der Webserver läuft.

### Schritt 9: Webseite im Browser öffnen
Öffne auf deinem Laptop einen neuen Browser-Tab mit `http://<öffentliche-ip>` (mit `http`, nicht `https`).

**Kontrolle:** Der Browser lädt lange und meldet dann einen Fehler, z. B. «Die Website ist nicht erreichbar». Das ist **richtig so**.

Warum? Die NSG lässt bisher nur Port 22 (SSH) herein. Eine Webseite kommt über **Port 80** (HTTP).

### Schritt 10: Port 80 öffnen (Cloud Shell)
```bash
az vm open-port --resource-group rg-tag3-cli-<kuerzel> --name vm-web-<kuerzel> --port 80
```
`vm open-port` ergänzt in der NSG der VM eine Regel, die Port 80 aus dem Internet erlaubt.

**Kontrolle:** Lade den Browser-Tab aus Schritt 9 neu. Du siehst die Überschrift «Hallo von vm-web-<kuerzel>».

### Schritt 11: Fragen
Beantworte im Lernjournal.

1. Ordne zu: Wo hast du den Befehl ausgeführt? Schreibe **C** (Cloud Shell), **P** (PowerShell auf dem Laptop) oder **V** (in der VM).

   | Befehl | Wo? |
   |--------|-----|
   | `az vm create …` | |
   | `ssh azureuser@…` | |
   | `sudo apt install -y nginx` | |
   | `az vm open-port …` | |

2. Kreuze an: Warum hat die Webseite in Schritt 9 nicht funktioniert?
   - [ ] nginx war noch nicht installiert.
   - [ ] Die NSG hat Port 80 blockiert.
   - [ ] Die VM hatte keine öffentliche IP (Public IP).
3. Du hast den Webserver in Schritt 6 bis 8 von Hand eingerichtet, wie in Auftrag 1.4. Was müsstest du tun, wenn die Velo Zürich AG zehn solche Server will? Antworte in einem Satz.

### Schritt 12: Aufräumen
1. **In der VM:** Beende die Verbindung mit `exit`.
2. **Cloud Shell:** Lösche die Ressourcengruppe (Resource Group) mit allem, was darin ist:
   ```bash
   az group delete --name rg-tag3-cli-<kuerzel> --yes --no-wait
   ```
   `--no-wait` gibt die Eingabezeile sofort zurück. Azure löscht im Hintergrund weiter.
3. Warte 3–5 Minuten, dann:
   ```bash
   az group list --output table
   ```

**Kontrolle:** `rg-tag3-cli-<kuerzel>` steht nicht mehr in der Liste. Steht dort noch `Deleting`, warte etwas und prüfe nochmals.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `echo $KEY` zeigt nichts | Schritt 2 wiederholen. Nach dem Schliessen der Cloud Shell ist die Variable weg. |
| `az vm create` meldet `The value of parameter linuxConfiguration.ssh.publicKeys.keyData is invalid` | Schlüssel unvollständig kopiert. Schritt 2 wiederholen, `echo $KEY` prüfen. |
| `SkuNotAvailable` | Grösse in deiner Region nicht verfügbar. Ersetze `Standard_B1s` durch `Standard_B2ats_v2`. |
| Fehler mit `quota` oder `QuotaExceeded` | Es läuft noch eine andere VM. Prüfe mit `az vm list --output table` und lösche alte Ressourcengruppen (Resource Groups). |
| `Permission denied (publickey)` | Benutzername `azureuser`? Gleicher Schlüssel wie in Schritt 2? |
| `sudo apt install` meldet `Could not get lock` | Die VM installiert beim Start noch Updates. 1–2 Minuten warten und nochmals versuchen. |
| Browser zeigt nach Schritt 10 immer noch einen Fehler | Mit `http://` (nicht `https://`) öffnen. 1 Minute warten und neu laden. |
| Browser zeigt «Welcome to nginx!» | Schritt 7 hat nicht geklappt. Befehl nochmals in der VM ausführen. |
