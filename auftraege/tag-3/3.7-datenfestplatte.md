# Auftrag ⭐ 3.7: Daten überleben die VM – mit einer Datenfestplatte

Zeit: ca. 60 Min. · Form: Einzelarbeit, freiwillig

> [!TIP]
> Anders als in Auftrag 3.3 stehen die Befehle der Azure CLI hier nicht alle fertig da. Du findest sie selbst: mit `--help`, in den Links unter «Quellen» und in den Tipps zum Aufklappen. Öffne einen Tipp erst, wenn du nicht mehr weiterkommst. Die Linux-Befehle in der VM bekommst du vorgegeben.

## Ziel
- Du kannst einer VM mit der Azure CLI eine Datenfestplatte (Data Disk) hinzufügen und sie in Linux nutzen. (K3)
- Du kannst eine VM löschen, ohne ihre Daten zu verlieren, und die Daten an eine neue VM hängen. (K3)
- Du kannst zuordnen, welche Daten das Ersetzen einer VM überleben. (K2)

## Voraussetzungen
- Auftrag 3.3 erledigt, `rg-tag3-cli-<kuerzel>` ist gelöscht. Es läuft **keine** andere VM (nur eine VM gleichzeitig).
- Theorie: [Kapitel 4](../../theorie/04-azure-compute.md), Abschnitt «Speicher der VM», und [Kapitel 5](../../theorie/05-azure-storage.md), Abschnitt «Persistenz»
- Cloud Shell (Bash) und PowerShell auf deinem Laptop wie in Auftrag 3.3
- Lernjournal: Ordner `tag-3/3.7-datenfestplatte`

## Ausgangslage
Der Webshop der Velo Zürich AG speichert Bestellungen auf seiner VM. Der Informatiker will die VM regelmässig durch eine neue ersetzen, z. B. für ein neues Ubuntu. Die Chefin fragt: «Und die Bestellungen? Sind die dann weg?»

Du zeigst es ihr: Die Bestellungen kommen auf eine eigene **Datenfestplatte** (Data Disk). Die VM ersetzt du, die Festplatte hängst du einfach an die neue VM.

| Was | Name (Beispiel für `mm`) |
|-----|--------------------------|
| Ressourcengruppe (Resource Group) | `rg-tag3-disk-mm` |
| erste VM | `vm-a-mm` |
| zweite VM | `vm-b-mm` |
| Datenfestplatte (Data Disk) | `disk-daten-mm`, 4 GB, `Standard_LRS` |

## Auftrag

### Schritt 1: Erste VM erstellen (Cloud Shell)
Diese Befehle kennst du aus Auftrag 3.3. Speichere zuerst wieder deinen öffentlichen Schlüssel (Public Key) in der Variablen `KEY` (Auftrag 3.3, Schritt 2). Dann:
```bash
az group create --name rg-tag3-disk-<kuerzel> --location <region> --tags kurs=azure-basics tag=3 owner=<kuerzel>
az vm create --resource-group rg-tag3-disk-<kuerzel> --name vm-a-<kuerzel> --image Ubuntu2404 --size Standard_B1s --admin-username azureuser --ssh-key-values "$KEY" --public-ip-sku Standard
```

**Kontrolle:** In der Ausgabe steht `"powerState": "VM running"` und eine `"publicIpAddress"`. Notiere sie.

### Schritt 2: Datenfestplatte anhängen (Cloud Shell)
Hänge an `vm-a-<kuerzel>` eine **neue** Datenfestplatte (Data Disk) mit dem Namen `disk-daten-<kuerzel>`, 4 GB und der günstigen Art `Standard_LRS`.

<details>
<summary>Tipp 1</summary>

Datenträger (Disks) einer VM verwaltest du mit `az vm disk`. Schau in `az vm disk attach --help` nach. Achte auf die Option, mit der Azure den Datenträger neu erstellt.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst:
```bash
az vm disk attach --resource-group … --vm-name … --name … --new --size-gb … --sku …
```
</details>

**Kontrolle:**
```bash
az disk list --resource-group rg-tag3-disk-<kuerzel> --output table
```
`disk list` zeigt alle Datenträger (Disks) der Ressourcengruppe (Resource Group). Du siehst zwei: den OS-Datenträger (OS Disk) von `vm-a-<kuerzel>` und `disk-daten-<kuerzel>` mit `4` in der Spalte für die Grösse.

### Schritt 3: Festplatte in Linux einrichten und Daten speichern (PowerShell, dann in der VM)
**PowerShell:** Melde dich an der VM an:
```powershell
ssh azureuser@<öffentliche-ip>
```
**In der VM:** Die neue Festplatte ist für Linux noch leer, ohne Dateisystem. Suche sie zuerst:
```bash
lsblk
```
`lsblk` listet alle Festplatten der VM auf. Die neue erkennst du an der Grösse **4G** und daran, dass sie keinen Eintrag in der Spalte `MOUNTPOINTS` hat. Meist heisst sie `sdc`. Eine andere Festplatte kann ebenfalls etwa 4G gross sein, ist aber unter `/mnt` eingebunden: Das ist der temporäre Datenträger (Temporary Disk). Den nimmst du **nicht**.

> [!WARNING]
> Der nächste Befehl löscht alles auf der Festplatte. Prüfe genau, dass du die **4G**-Festplatte **ohne** Mountpoint nimmst: nicht die mit dem Betriebssystem und nicht die unter `/mnt` (temporärer Datenträger (Temporary Disk)).

Ersetze `<disk>` durch den Namen aus `lsblk`, z. B. `sdc`:
```bash
sudo mkfs.ext4 /dev/<disk>
sudo mkdir /daten
sudo mount /dev/<disk> /daten
```
`mkfs.ext4` legt ein Dateisystem an, wie «Formatieren» unter Windows. `mkdir` erstellt einen Ordner. `mount` hängt die Festplatte an diesen Ordner: Was du in `/daten` speicherst, landet auf der Datenfestplatte (Data Disk).

Jetzt speicherst du zwei Dateien, eine auf jeder Festplatte:
```bash
echo "Bestellung 1001: Citybike, 890 CHF" | sudo tee /daten/bestellungen.txt
echo "Notiz auf dem OS-Datenträger" > ~/notiz.txt
ls /daten
ls ~
```

**Kontrolle:** `ls /daten` zeigt `bestellungen.txt` und `lost+found` (diesen Ordner legt Linux beim Formatieren an). `ls ~` zeigt `notiz.txt`.

Hänge die Festplatte zum Schluss sauber ab, wie beim Auswerfen eines USB-Sticks, und verlasse die VM:
```bash
sudo umount /daten
exit
```

### Schritt 4: Die VM löschen, aber nur die VM (Cloud Shell)
Lösche `vm-a-<kuerzel>`. Lösche **nicht** die Ressourcengruppe (Resource Group), sonst ist auch die Datenfestplatte (Data Disk) weg.

<details>
<summary>Tipp</summary>

`az vm delete --help`. Du brauchst die Ressourcengruppe (Resource Group), den Namen der VM und `--yes`.
</details>

**Kontrolle:** `az vm list --resource-group rg-tag3-disk-<kuerzel> --output table` zeigt nichts mehr. Führe danach nochmals `az disk list` aus Schritt 2 aus und notiere, welche Datenträger (Disks) noch da sind.

### Schritt 5: Neue VM mit der alten Datenfestplatte (Cloud Shell)
Erstelle `vm-b-<kuerzel>` wie in Schritt 1. Diesmal soll Azure die **vorhandene** Datenfestplatte (Data Disk) `disk-daten-<kuerzel>` gleich beim Erstellen anhängen.

<details>
<summary>Tipp 1</summary>

`az vm create --help` und suche nach «data disk». Es gibt eine Option, die vorhandene Datenträger (Disks) anhängt.
</details>

<details>
<summary>Tipp 2</summary>

Nimm den Befehl aus Schritt 1, ändere den Namen der VM und ergänze am Schluss `--attach-data-disks …` mit dem Namen der Datenfestplatte (Data Disk).
</details>

**Kontrolle:** `"powerState": "VM running"` und eine neue `"publicIpAddress"`. Sie ist anders als in Schritt 1.

### Schritt 6: Sind die Daten noch da? (PowerShell, dann in der VM)
**PowerShell:** Melde dich an der **neuen** VM an. Sie hat eine neue IP-Adresse. Beim ersten Verbinden fragt SSH nach, ob du dem Server vertraust: `yes` eintippen.
```powershell
ssh azureuser@<neue-öffentliche-ip>
```
**In der VM:** Ersetze `<disk>` wie in Schritt 3 durch die 4G-Festplatte ohne Eintrag bei `MOUNTPOINTS`.
```bash
lsblk
sudo mkdir /daten
sudo mount /dev/<disk> /daten
cat /daten/bestellungen.txt
ls ~
```
Diesmal **nicht** `mkfs.ext4` ausführen: Das Dateisystem ist schon da, und mit `mkfs` würdest du die Bestellungen löschen.

**Kontrolle:** `cat` zeigt «Bestellung 1001: Citybike, 890 CHF». `ls ~` zeigt **keine** `notiz.txt`.

### Schritt 7: Fragen
Beantworte im Lernjournal.

1. Kreuze an:

   | Datei | überlebt | ist weg |
   |-------|:---:|:---:|
   | `notiz.txt` im Home-Ordner, auf dem OS-Datenträger (OS Disk) | | |
   | `bestellungen.txt` in `/daten`, auf der Datenfestplatte (Data Disk) | | |

2. Welche Datenträger (Disks) waren nach Schritt 4 noch da? Warum ist das für die Kosten wichtig? Antworte in ein bis zwei Sätzen.
3. Die Velo Zürich AG ersetzt ihre VM jeden Monat. Wo würdest du die Bestellungen speichern? Nenne zwei passende Orte aus Kapitel 4 und 5.

## Aufräumen
```bash
az group delete --name rg-tag3-disk-<kuerzel> --yes --no-wait
```
**Kontrolle:** Nach 2–3 Minuten zeigt `az group list --output table` die Gruppe nicht mehr. Damit sind auch alle Datenträger (Disks) gelöscht.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `QuotaExceeded` oder Fehler mit «cores» in Schritt 1 oder 5 | Es läuft noch eine andere VM. Mit `az vm list --output table` suchen und die alte Ressourcengruppe (Resource Group) löschen. |
| `mount: wrong fs type` in Schritt 6 | Falscher Name bei `<disk>`. Mit `lsblk` die 4G-Festplatte suchen. |
| `mkfs.ext4` fragt «contains a … file system, proceed anyway?» | Du bist an der falschen Festplatte oder führst `mkfs` ein zweites Mal aus. Mit `n` abbrechen. |
| `Permission denied` beim Schreiben in `/daten` | `sudo tee` verwenden wie im Befehl, nicht `>`. |
| `Disk … is already attached` in Schritt 5 | `vm-a-<kuerzel>` ist noch nicht ganz gelöscht. Eine Minute warten und nochmals. |
| `mkfs.ext4` meldet «is apparently in use by the system» | Du hast eine Festplatte erwischt, die schon eingebunden ist. Es ist nichts passiert. Mit `lsblk` die richtige suchen. |
| `SkuNotAvailable` in Schritt 1 oder 5 | Wie in Auftrag 3.3 `Standard_B2ats_v2` statt `Standard_B1s`. Diese Grösse hat keinen temporären Datenträger (Temporary Disk): Die Datenfestplatte (Data Disk) heisst dann meist `sdb`. |
| SSH warnt «REMOTE HOST IDENTIFICATION HAS CHANGED» | Die IP-Adresse gehörte vorher zu einer anderen VM. `ssh-keygen -R <öffentliche-ip>`, dann nochmals verbinden. |
