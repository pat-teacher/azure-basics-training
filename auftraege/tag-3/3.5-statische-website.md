# Auftrag 3.5: Statische Website im Speicherkonto

Zeit: 30 Min. · Form: Einzelarbeit

## Ziel
- Du kannst in einem Speicherkonto (Storage Account) eine statische Website (Static Website) einrichten und veröffentlichen. (K3)
- Du kannst Merkmale einer VM mit Webserver und einer statischen Website (Static Website) zuordnen. (K2)

## Voraussetzungen
- Auftrag 3.4 erledigt, dein Speicherkonto (Storage Account) `sttag3<kuerzel>` existiert noch
- Cloud Shell (Bash) für das Aufräumen
- Lernjournal: Ordner `tag-3/3.5-statische-website`

## Ausgangslage
Die Velo Zürich AG will eine einfache Infoseite: Text, ein paar Bilder, keine Anmeldung, kein Shop. In Auftrag 3.3 hast du dafür eine ganze VM mit nginx gebraucht. Es geht auch ohne VM: Ein Speicherkonto (Storage Account) kann Dateien direkt als **statische Website** (Static Website) ausliefern. «Statisch» heisst: Die Dateien werden so gezeigt, wie sie gespeichert sind. Es läuft kein Programm auf einem Server.

## Auftrag

### Schritt 1: Statische Website einschalten
1. Öffne im Portal dein Speicherkonto (Storage Account) `sttag3<kuerzel>`.
2. Klicke links auf **Datenverwaltung** > **Statische Website** (Static Website).
3. Stelle **Statische Website** (Static Website) auf **Aktiviert**.
4. Fülle aus:
   - Name des Indexdokuments: `index.html`
   - Pfad des Fehlerdokuments: `404.html`
5. Klicke auf **Speichern**.

<!-- prüfen: Stand 08.11.2026 – Menüpfad und Feldnamen im deutschen Portal -->

**Kontrolle:** Unter **Primärer Endpunkt** steht eine Adresse wie `https://sttag3<kuerzel>.z1.web.core.windows.net/`. Notiere sie. Die Zahl nach dem `z` kann anders sein.

### Schritt 2: Der Container `$web`
Klicke links auf **Datenspeicher** > **Container**.

**Kontrolle:** Neben `dateien` gibt es jetzt den Container `$web`. Azure hat ihn beim Einschalten angelegt. Alles, was darin liegt, ist über den Primären Endpunkt öffentlich erreichbar.

### Schritt 3: Zwei Webseiten erstellen
Erstelle auf deinem Laptop im Editor (Notepad) zwei Dateien. Ersetze `mm` durch dein Kürzel.

**Datei 1:** `index.html`
```html
<!DOCTYPE html>
<html lang="de">
<head><meta charset="utf-8"><title>Velo Zürich AG</title></head>
<body>
  <h1>Velo Zürich AG</h1>
  <p>Willkommen! Diese Seite liegt in einem Azure-Speicherkonto, ganz ohne Server.</p>
  <p>Erstellt von: mm</p>
</body>
</html>
```

**Datei 2:** `404.html`
```html
<!DOCTYPE html>
<html lang="de">
<head><meta charset="utf-8"><title>Nicht gefunden</title></head>
<body>
  <h1>Diese Seite gibt es nicht</h1>
  <p><a href="/">Zurück zur Startseite</a></p>
</body>
</html>
```

> [!WARNING]
> Wähle beim Speichern im Editor bei «Dateityp» **Alle Dateien (\*.\*)**. Sonst heisst die Datei `index.html.txt`.

**Kontrolle:** Im Explorer stehen `index.html` und `404.html`. Ein Doppelklick auf `index.html` öffnet die Seite im Browser, mit «Zürich» richtig geschrieben.

### Schritt 4: Dateien hochladen
1. Öffne im Portal den Container `$web` und klicke auf **Hochladen**.
2. Wähle **beide** Dateien aus und klicke auf **Hochladen**.

**Kontrolle:** Im Container `$web` stehen `index.html` und `404.html`.

### Schritt 5: Website öffnen
1. Öffne die Adresse des Primären Endpunkts aus Schritt 1 in einem privaten Browserfenster.
2. Hänge danach an die Adresse `/gibtsnicht` an und drücke `Enter`.

**Kontrolle:**
- Beim ersten Aufruf siehst du «Velo Zürich AG» und dein Kürzel. Anders als die Preisliste in Auftrag 3.4 ist diese Seite öffentlich.
- Beim zweiten Aufruf siehst du «Diese Seite gibt es nicht».

### Schritt 6: VM oder statische Website?
Kreuze im Lernjournal an. Vergleiche mit deiner VM aus Auftrag 3.3.

| Aussage | VM mit nginx (3.3) | statische Website (3.5) |
|---------|:---:|:---:|
| Ich muss ein Betriebssystem installieren und aktuell halten. | | |
| Ich muss einen Port in der NSG öffnen. | | |
| Es kostet jede Stunde Rechenleistung, auch wenn niemand die Seite besucht. | | |
| Ich kann ein Programm laufen lassen, z. B. einen Webshop mit Anmeldung. | | |

Und: Ist die statische Website (Static Website) eher IaaS oder eher PaaS? Begründe in einem Satz.

### Schritt 7: Weiter oder aufräumen?
Machst du die Zusatzaufgabe ⭐ 3.6? Dann lässt du das Speicherkonto (Storage Account) stehen.

Sonst räumst du jetzt auf (Cloud Shell):
```bash
az group delete --name rg-tag3-storage-<kuerzel> --yes --no-wait
```
**Kontrolle:** Nach 1–2 Minuten zeigt `az group list --output table` keine Gruppe `rg-tag3-…` mehr. Die Adresse aus Schritt 1 zeigt nur noch eine Fehlermeldung.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| Browser zeigt `The requested content does not exist` | `index.html` liegt nicht im Container `$web` oder heisst anders. Name genau prüfen (auch Gross-/Kleinschreibung). |
| Browser lädt die Datei herunter, statt sie anzuzeigen | Die Datei heisst `index.html.txt`. Im Editor mit «Alle Dateien» neu speichern und nochmals hochladen. |
| Umlaute erscheinen als `Ã¼` | Die Zeile `<meta charset="utf-8">` fehlt, oder die Datei ist nicht als UTF-8 gespeichert. Im Editor beim Speichern **Codierung: UTF-8** wählen. |
| Alte Version wird angezeigt | Browser zwischenspeichert. Mit `Ctrl` + `F5` neu laden. |
