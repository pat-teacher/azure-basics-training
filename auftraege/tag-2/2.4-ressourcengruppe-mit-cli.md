# Auftrag 2.4: Dieselbe Ressourcengruppe mit der Azure CLI

Zeit: 45 Min. · Form: Einzelarbeit

## Ziel
- Du kannst die Cloud Shell öffnen und Befehle der Azure CLI ausführen. (K3)
- Du kannst mit der Azure CLI eine Ressourcengruppe (Resource Group) mit Tags erstellen, anzeigen und löschen. (K3)
- Du kannst Vor- und Nachteile von Portal und Azure CLI zuordnen. (K2)

## Voraussetzungen
- Auftrag 2.3 erledigt, deine Ressourcengruppe (Resource Group) von dort ist gelöscht
- Deine **Kursregion** aus Auftrag 2.2
- Input «Cloud Shell und Azure CLI» gehört
- Theorie zum Nachlesen: [Kapitel 3 Aufbau von Azure](../../theorie/03-azure-aufbau.md), Abschnitt «Werkzeuge»
- Lernjournal: Ordner `tag-2/2.4-ressourcengruppe-mit-cli`

## Ausgangslage
Im Portal hast du sechs Mal geklickt, um eine Ressourcengruppe (Resource Group) zu erstellen. Die Velo Zürich AG braucht bald zehn davon – für jedes Projekt eine. Mit der **Azure CLI** schreibst du das als Befehl. Einen Befehl kann man kopieren, speichern und beliebig oft wiederholen.

Du arbeitest in der **Cloud Shell**: einem Terminal im Browser. Die Azure CLI ist dort schon installiert und mit deinem Konto angemeldet.

> [!TIP]
> Befehle kopierst du hier mit dem Kopier-Symbol. In der Cloud Shell fügst du mit `Ctrl` + `Shift` + `V` oder mit einem Rechtsklick > **Einfügen** (Paste) ein. Ersetze danach die Platzhalter in `< >`, auch die Klammern selbst.

## Auftrag

### Schritt 1: Cloud Shell öffnen
1. Klicke im Portal oben in der Leiste auf das Symbol **>_** (Cloud Shell).
2. Wähle **Bash**.
3. Beim ersten Start fragt Azure nach einem Speicherkonto (Storage Account). Wähle **Kein Speicherkonto erforderlich** (No storage account required) und als Abonnement (Subscription) **Azure for Students** und klicke auf **Anwenden** (Apply). <!-- prüfen: Stand 28.10.2026 – Dialog beim ersten Start der Cloud Shell -->

**Kontrolle:** Unten im Browser öffnet sich ein schwarzes Fenster. Die letzte Zeile endet mit `$`, z. B. `mia [ ~ ]$`.

> [!NOTE]
> Ohne Speicherkonto (Storage Account) gehen Dateien in der Cloud Shell verloren, wenn du sie schliesst. Das ist heute kein Problem: Du schreibst nur Befehle. Dafür kostet es nichts.

### Schritt 2: Mit welchem Konto bist du verbunden?
```bash
az account show --output table
```
`az` ist die Azure CLI. `account show` zeigt das Abonnement (Subscription), mit dem du gerade arbeitest. `--output table` macht aus der Ausgabe eine lesbare Tabelle.

**Kontrolle:** In der Spalte `Name` steht `Azure for Students`, in der Spalte `State` steht `Enabled`.

### Schritt 3: Den CLI-Namen deiner Kursregion finden
Im Portal heisst die Region z. B. «Switzerland North». Die Azure CLI braucht den kurzen Namen ohne Leerzeichen. Ersetze im Befehl `Switzerland North` durch den Anzeigenamen deiner Kursregion:
```bash
az account list-locations --query "[?displayName=='Switzerland North']" --output table
```
`account list-locations` zeigt die Regionen. `--query` filtert die Liste: Nur die Region mit diesem Anzeigenamen bleibt übrig.

**Kontrolle:** Du siehst genau eine Zeile. In der Spalte `Name` steht der kurze Name, z. B. `switzerlandnorth`. Notiere ihn.

### Schritt 4: Ressourcengruppe erstellen
```bash
az group create --name rg-tag2-<kuerzel> --location <region> --tags kurs=azure-basics tag=2 owner=<kuerzel>
```
`group create` erstellt eine Ressourcengruppe (Resource Group). `--name` ist ihr Name, `--location` die Region (kurzer Name aus Schritt 3), `--tags` die Etiketten im Format `name=wert`.

**Kontrolle:** Die Ausgabe ist ein Textblock in geschweiften Klammern (Format JSON). Darin steht `"provisioningState": "Succeeded"` und dein Name `rg-tag2-<kuerzel>`.

### Schritt 5: Ressourcengruppe anzeigen
```bash
az group list --output table
```
`group list` zeigt alle Ressourcengruppen (Resource Groups) in deinem Abonnement (Subscription).

**Kontrolle:** In der Liste steht `rg-tag2-<kuerzel>` mit deiner Region und `Succeeded`.

Jetzt nur die Tags deiner Ressourcengruppe (Resource Group):
```bash
az group show --name rg-tag2-<kuerzel> --query tags
```
`group show` zeigt eine einzelne Ressourcengruppe (Resource Group). `--query tags` zeigt davon nur das Feld `tags`.

**Kontrolle:**
```json
{
  "kurs": "azure-basics",
  "owner": "<kuerzel>",
  "tag": "2"
}
```

### Schritt 6: Im Portal nachschauen
Öffne im Portal die Liste **Ressourcengruppen** (Resource Groups) und klicke auf **Aktualisieren** (Refresh).

**Kontrolle:** `rg-tag2-<kuerzel>` steht in der Liste. Öffne sie: Region und Tags sind genau gleich wie in Auftrag 2.3.

## Zusatzaufgabe ⭐ Löschen löscht alles
Mach diese Aufgabe **vor** dem Aufräumen. Hast du schon aufgeräumt? Dann erstelle die Ressourcengruppe (Resource Group) zuerst neu mit dem Befehl aus Schritt 4.

Ein virtuelles Netzwerk (Virtual Network) kostet nichts. Erstelle eines in deiner Ressourcengruppe (Resource Group) und zeige alle Ressourcen darin an:
```bash
az network vnet create --resource-group rg-tag2-<kuerzel> --name vnet-tag2-<kuerzel> --address-prefixes 10.0.0.0/16
az resource list --resource-group rg-tag2-<kuerzel> --output table
```
**Kontrolle:** In der Liste steht `vnet-tag2-<kuerzel>`.

Räume danach wie unten beschrieben auf. Prüfe mit `az resource list --output table`: Ist auch das Netzwerk weg?

> [!NOTE]
> Beim ersten Netzwerk legt Azure automatisch die Ressourcengruppe (Resource Group) `NetworkWatcherRG` an. Sie kostet nichts und darf bleiben.

## Aufräumen
```bash
az group delete --name rg-tag2-<kuerzel> --yes
```
`group delete` löscht die Ressourcengruppe (Resource Group) mit allem, was darin ist. `--yes` beantwortet die Sicherheitsfrage automatisch mit Ja. Das Löschen dauert etwa eine Minute. Warte, bis die Eingabezeile wieder erscheint.

```bash
az group list --output table
```
**Kontrolle:** `rg-tag2-<kuerzel>` steht nicht mehr in der Liste. Ist die Liste leer, siehst du gar keine Ausgabe.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `RequestDisallowedByPolicy` oder `RequestDisallowedByAzure` | Region nicht erlaubt. Kurzen Namen einer erlaubten Region aus Auftrag 2.2 verwenden. |
| `bash: syntax error near unexpected token` oder `No such file or directory` | Du hast die Klammern `< >` nicht ersetzt. Befehl nochmals einfügen und `<kuerzel>` und `<region>` ganz ersetzen. |
| `unrecognized arguments: North` | Du hast den Anzeigenamen mit Leerzeichen eingegeben. Kurzen Namen aus Schritt 3 verwenden, z. B. `switzerlandnorth`. |
| `The provided location '…' is not available` | Region falsch geschrieben. Kurzen Namen aus Schritt 3 kopieren (klein, ohne Leerzeichen). |
| `az group show` meldet `ResourceGroupNotFound` | Name falsch geschrieben. Mit `az group list --output table` den genauen Namen nachschauen. |
| Cloud Shell verbindet nicht oder bricht ab | Cloud Shell schliessen und neu öffnen. Nach 20 Minuten ohne Eingabe trennt sie die Verbindung. |
