# Auftrag ⭐ 2.8: Drei Umgebungen, ein Befehl – Tags, Abfragen und Sperren

Zeit: ca. 45 Min. · Form: Einzelarbeit, freiwillig

> [!TIP]
> Anders als in Auftrag 2.4 stehen die Befehle hier nicht fertig da. Du findest sie selbst: in der Hilfe der Azure CLI (`az group --help`), in den Links unter «Quellen» und in den Tipps zum Aufklappen. Öffne einen Tipp erst, wenn du nicht mehr weiterkommst.

## Ziel
- Du kannst mit einer Schleife in der Bash mehrere Ressourcengruppen (Resource Groups) mit einem Befehl erstellen. (K3)
- Du kannst Ressourcengruppen (Resource Groups) mit Tags und `--query` gezielt finden und als eigene Tabelle anzeigen. (K3)
- Du kannst eine Ressourcengruppe (Resource Group) mit einer Sperre (Lock) vor dem Löschen schützen. (K3)
- Du kannst Tag, Sperre (Lock) und Richtlinie (Policy) passenden Situationen zuordnen. (K2)

## Voraussetzungen
- Auftrag 2.4 erledigt (Cloud Shell, `az group create`, `--query`)
- Deine **Kursregion** aus Auftrag 2.2 (kurzer Name, z. B. `switzerlandnorth`)
- Cloud Shell (Bash) geöffnet
- Lernjournal: Ordner `tag-2/2.8-umgebungen-tags-sperren`

## Ausgangslage
Die Velo Zürich AG entwickelt einen Onlineshop für Velozubehör. Wie viele Firmen arbeitet sie mit drei getrennten **Umgebungen**:

| Umgebung | Wofür? |
|----------|--------|
| `dev` | Entwicklung: Hier probiert das Entwicklungsteam Neues aus. |
| `test` | Test: Hier prüft das Team, ob alles funktioniert. |
| `prod` | Produktion: Hier kaufen echte Kundinnen und Kunden ein. |

Jede Umgebung bekommt eine eigene Ressourcengruppe (Resource Group). Die Chefin will drei Dinge:
1. Die Gruppen sollen alle gleich aufgebaut sein. Darum erstellst du sie mit **einem** Befehl, nicht dreimal von Hand.
2. Sie will jederzeit sehen, welche Gruppe zu welcher Umgebung gehört.
3. Niemand darf die Produktion aus Versehen löschen.

Ressourcengruppen (Resource Groups), Tags und Sperren (Locks) kosten nichts.

## Auftrag

### Schritt 1: Drei Gruppen mit einem Befehl
Erstelle die drei Ressourcengruppen (Resource Groups) `rg-tag2-dev-<kuerzel>`, `rg-tag2-test-<kuerzel>` und `rg-tag2-prod-<kuerzel>` in deiner Kursregion.

Jede Gruppe bekommt vier Tags: die drei aus Auftrag 2.4 (`kurs`, `tag`, `owner`) und zusätzlich `umgebung` mit dem Wert `dev`, `test` oder `prod`.

Die Bedingung: Du schickst nur **einen** Befehl ab. Dafür brauchst du eine **Schleife** (Loop): Die Bash wiederholt einen Befehl für jeden Wert in einer Liste.

So sieht eine Schleife aus. Probiere sie zuerst aus, sie erstellt noch nichts:
```bash
for umgebung in dev test prod; do echo "rg-tag2-$umgebung-<kuerzel>"; done
```
`for … in dev test prod` nimmt nacheinander jeden Wert. `$umgebung` ist eine Variable: Die Bash setzt dort den aktuellen Wert ein. `do … done` umschliesst den Befehl, der wiederholt wird. `;` trennt die Teile auf einer Zeile. `echo` gibt nur Text aus.

Ersetze jetzt `echo …` durch den passenden `az group create`-Befehl.

<details>
<summary>Tipp 1</summary>

Nimm den Befehl aus Auftrag 2.4, Schritt 4. Ersetze im Namen `tag2` durch `tag2-$umgebung` und ergänze bei `--tags` den vierten Tag `umgebung=$umgebung`.
</details>

<details>
<summary>Tipp 2</summary>

Mit `--output none` vermeidest du drei lange JSON-Ausgaben. Gerüst:
```bash
for umgebung in dev test prod; do az group create --name … --location … --tags … --output none; done
```
</details>

**Kontrolle:** `az group list --output table` zeigt die drei Gruppen mit deiner Region und `Succeeded`.

### Schritt 2: Nur die Produktion finden
In grossen Firmen gibt es Hunderte Ressourcengruppen (Resource Groups). Zeige mit `az group list` **nur** die Gruppen an, die den Tag `umgebung=prod` haben, als Tabelle (`--output table`).

<details>
<summary>Tipp 1</summary>

`az group list --help` zeigt alle Parameter. Einer davon filtert nach einem Tag.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst:
```bash
az group list --tag …=… --output table
```
</details>

**Kontrolle:** Die Tabelle hat genau eine Zeile: `rg-tag2-prod-<kuerzel>`.

### Schritt 3: Eine eigene Tabelle
Die Chefin will eine Übersicht mit zwei Spalten: **Name** und **Umgebung**. Nur Gruppen mit deinem Kürzel im Tag `owner` sollen erscheinen.

Du kennst `--query` aus Auftrag 2.4, Schritt 3: `[?…]` filtert eine Liste. Mit `{Spalte:feld, …}` wählst du aus, welche Felder als Spalten erscheinen.

<details>
<summary>Tipp 1</summary>

Die Tags einer Gruppe erreichst du mit `tags.<name>`, z. B. `tags.owner`. Schau dir die Ausgabe von `az group show --name rg-tag2-dev-<kuerzel>` an.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst (`…` ersetzen):
```bash
az group list --query "[?tags.owner=='<kuerzel>'].{Name:…, Umgebung:…}" --output table
```
</details>

**Kontrolle:** So sieht es mit dem Kürzel `mm` aus. Die Reihenfolge darf anders sein.
```text
Name             Umgebung
---------------  ----------
rg-tag2-dev-mm   dev
rg-tag2-prod-mm  prod
rg-tag2-test-mm  test
```

### Schritt 4: Achtung, Falle! Einen Tag ergänzen
Die Buchhaltung will auf der Testumgebung zusätzlich den Tag `kostenstelle=velo-it`. Führe diesen Befehl aus:
```bash
az group update --name rg-tag2-test-<kuerzel> --tags kostenstelle=velo-it
```
`group update` ändert eine bestehende Ressourcengruppe (Resource Group).

Schau dir danach die Tags der Gruppe an (Befehl aus Auftrag 2.4, Schritt 5).

**Kontrolle:** Du siehst, was mit den anderen Tags passiert ist. Beantworte im Lernjournal in einem Satz: Was macht `--tags` bei `az group update`?

Jetzt die eigentliche Aufgabe: Stelle `rg-tag2-test-<kuerzel>` mit allen **fünf** Tags wieder her (die vier alten plus `kostenstelle`). Ergänze danach auf `rg-tag2-prod-<kuerzel>` den Tag `kostenstelle=velo-it` so, dass die vier anderen Tags **bleiben**.

<details>
<summary>Tipp 1</summary>

Wiederherstellen: Gib bei `--tags` einfach alle Tags an, die die Gruppe haben soll.
</details>

<details>
<summary>Tipp 2</summary>

`az group update --help` zeigt den Parameter `--set`. Damit änderst du ein einzelnes Feld. Ein einzelner Tag heisst `tags.<name>`.
</details>

**Kontrolle:** Beide Gruppen haben fünf Tags: `kostenstelle`, `kurs`, `owner`, `tag` und `umgebung`. So sieht es bei der Produktion mit dem Kürzel `mm` aus:
```json
{
  "kostenstelle": "velo-it",
  "kurs": "azure-basics",
  "owner": "mm",
  "tag": "2",
  "umgebung": "prod"
}
```

### Schritt 5: Die Produktion schützen
Eine **Sperre** (Lock) schützt eine Ressource oder Ressourcengruppe (Resource Group). Es gibt zwei Arten:

| Art im Befehl | Im Portal | Was ist verboten? |
|---------------|-----------|-------------------|
| `CanNotDelete` | Löschen | Löschen. Ändern ist erlaubt. |
| `ReadOnly` | Schreibgeschützt | Löschen und Ändern. |

Setze auf `rg-tag2-prod-<kuerzel>` eine Sperre (Lock) vom Typ `CanNotDelete` mit dem Namen `nicht-loeschen`.

<details>
<summary>Tipp</summary>

Die Befehle für Sperren (Locks) beginnen mit `az lock`. Schau in `az lock create --help` nach: Du brauchst `--name`, `--lock-type` und `--resource-group`.
</details>

<details>
<summary>Tipp 2</summary>

Gerüst:
```bash
az lock create --name … --lock-type … --resource-group …
```
</details>

**Kontrolle:** `az lock list --resource-group rg-tag2-prod-<kuerzel> --output table` zeigt die Sperre (Lock) `nicht-loeschen` mit `CanNotDelete`.

Jetzt der Test. Versuche, die Produktion zu löschen:
```bash
az group delete --name rg-tag2-prod-<kuerzel> --yes
```

**Kontrolle:** Azure lehnt ab. In der Meldung steht `ScopeLocked` und `cannot perform delete operation because following scope(s) are locked`. Die Gruppe ist noch da.

Schau dir die Sperre (Lock) auch im Portal an: Ressourcengruppe (Resource Group) `rg-tag2-prod-<kuerzel>` öffnen > links **Einstellungen** > **Sperren** (Locks). <!-- prüfen: Menüpfad im deutschsprachigen Portal; Sperren setzen mit dem Konto für Azure for Students (Rolle Owner) -->


### Schritt 6: Tag, Sperre oder Richtlinie?
Du kennst jetzt drei Werkzeuge: Tags aus Schritt 1–4, Sperren (Locks) aus Schritt 5 und Richtlinien (Policies) aus Auftrag 2.2. Kreuze im Lernjournal an. Pro Zeile **ein** Kreuz.

| Situation bei der Velo Zürich AG | Tag | Sperre (Lock) | Richtlinie (Policy) |
|----------------------------------|:---:|:---:|:---:|
| Die Buchhaltung will wissen, welche Kosten zu welcher Abteilung gehören. | | | |
| Niemand soll die Datenbank des Onlineshops aus Versehen löschen. | | | |
| Ressourcen dürfen nur in Rechenzentren in der Schweiz entstehen. | | | |
| Ein Skript soll alle Testumgebungen auf einmal finden. | | | |
| Jede neue Ressourcengruppe (Resource Group) muss den Tag `owner` haben, sonst wird sie abgelehnt. | | | |

Und: Du bist Besitzer (Owner) deines Abonnements (Subscription) und darfst alles. Warum konntest du die Gruppe in Schritt 5 trotzdem nicht löschen? Antworte in ein bis zwei Sätzen.

## Aufräumen: Alles mit einem Befehl
Lösche alle Ressourcengruppen (Resource Groups) mit dem Tag `umgebung` mit **einem** Befehl. Eine davon ist gesperrt. Überlege zuerst, was du vorher tun musst.

> [!CAUTION]
> Lass dir zuerst nur die **Namen** anzeigen, die du löschen willst. Erst wenn die Liste stimmt, löschst du. Profis machen das immer so. Prüfe, dass nur deine drei `rg-tag2-…` in der Liste stehen.

<details>
<summary>Tipp 1</summary>

Die Sperre (Lock) entfernst du mit `az lock delete`. Dafür brauchst du denselben Namen und dieselbe Ressourcengruppe (Resource Group) wie beim Erstellen.
</details>

<details>
<summary>Tipp 2</summary>

Nur die Namen der Gruppen mit dem Tag `umgebung`, einer pro Zeile:
```bash
az group list --query "[?tags.umgebung].name" --output tsv
```
`--output tsv` gibt reinen Text ohne Tabellenrahmen aus. Diese Liste kannst du in einer Schleife verwenden: `for rg in $(…); do …; done`. Die Bash setzt bei `$(…)` die Ausgabe des Befehls in den Klammern ein.
</details>

<details>
<summary>Tipp 3</summary>

Gerüst für die zweite Zeile (zuerst die Sperre (Lock) entfernen):
```bash
for rg in $(az group list --query "[?tags.umgebung].name" --output tsv); do az group delete --name $rg --yes; done
```
Ohne `--no-wait` löscht die Schleife eine Gruppe nach der anderen. Das dauert einige Minuten.
</details>

**Kontrolle:** Sobald die Eingabezeile wieder erscheint, zeigt `az group list --output table` keine `rg-tag2-…` mehr und `az lock list --output table` zeigt nichts an. Mit `--no-wait` erscheint die Eingabezeile sofort. Dann dauert es etwa eine Minute, bis die Gruppen verschwinden.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| Schleife: `>` erscheint und nichts passiert | Es fehlt `; done` am Schluss oder ein Anführungszeichen. Mit `Ctrl` + `C` abbrechen und den Befehl prüfen. |
| Gruppe heisst `rg-tag2--<kuerzel>` | `$umgebung` falsch geschrieben, z. B. `$Umgebung`. Die Bash unterscheidet Gross- und Kleinschreibung. Falsche Gruppe löschen. |
| `--query` zeigt eine leere Tabelle | Einfache Anführungszeichen `'…'` um den Wert vergessen, oder `owner` hat einen anderen Wert. Mit `az group show` nachschauen. |
| `AuthorizationFailed` bei `az lock create` | Für Sperren (Locks) braucht es die Rolle (Role) Besitzer (Owner). Kursleitung fragen. |
| `ScopeLocked` beim Aufräumen | Die Sperre (Lock) ist noch aktiv. Zuerst entfernen, dann löschen. |
| `ScopeLocked`, obwohl du `az lock delete` ausgeführt hast | Das Entfernen braucht einige Sekunden. Kurz warten und nochmals löschen. |
