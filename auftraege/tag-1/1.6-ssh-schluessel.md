# Auftrag 1.6: SSH-Schlüssel für die Cloud vorbereiten

Zeit: 25 Min. · Form: Einzelarbeit

## Ziel
- Du kannst ein SSH-Schlüsselpaar erstellen und dich damit an einer VM anmelden. (K3)
- Du kannst erklären, welcher Schlüssel geheim bleibt und welcher auf den Server kommt. (K2)

## Voraussetzungen
- PowerShell
- OpenSSH-Client (bei Windows 10 und 11 vorinstalliert)
- vm1 aus Auftrag 1.2 läuft

## Ausgangslage
Ab Tag 3 meldest du dich an VMs in Azure an. Dafür verwendest du kein Passwort, sondern ein **SSH-Schlüsselpaar** (SSH Key Pair). **SSH** (Secure Shell) ist eine verschlüsselte Verbindung zu einem Server. Das Schlüsselpaar erstellst du heute und testest es gleich an deiner vm1.

Ein Schlüsselpaar besteht aus zwei Dateien:

| Datei | Vergleich | Wohin? |
|-------|-----------|--------|
| **privater** Schlüssel (Private Key) `id_ed25519` | dein Schlüssel | bleibt **nur** auf deinem Laptop – nie weitergeben |
| **öffentlicher** Schlüssel (Public Key) `id_ed25519.pub` | das passende Schloss | kommt auf den Server – darf jeder sehen |

## Auftrag

### Schritt 1: Schlüsselpaar erstellen
```powershell
ssh-keygen -t ed25519
```
`ssh-keygen` erstellt ein neues Schlüsselpaar. `-t ed25519` wählt ein modernes Verfahren.

Drücke bei allen drei Fragen einfach `Enter`.

> [!WARNING]
> Kommt die Meldung `already exists. Overwrite (y/n)?`, dann hast du schon einen Schlüssel. Tippe **n** und mach bei Schritt 2 weiter.

**Kontrolle:** Am Schluss erscheint ein Bild aus Zeichen (randomart) und `Your public key has been saved in …id_ed25519.pub`.

### Schritt 2: Den öffentlichen Schlüssel anzeigen
```powershell
Get-Content ~\.ssh\id_ed25519.pub
```
`Get-Content` zeigt den Inhalt einer Datei. `~` steht für deinen Benutzerordner.

**Kontrolle:** Eine lange Zeile, die mit `ssh-ed25519 AAAA` beginnt.

### Schritt 3: Anmeldung mit dem Schlüssel testen
Jetzt prüfst du, ob dein Schlüssel funktioniert. Dafür legst du das «Schloss» (den öffentlichen Schlüssel) in vm1 ab.

**a) Öffentlichen Schlüssel in vm1 hinterlegen**
```powershell
$key = Get-Content ~\.ssh\id_ed25519.pub
multipass exec vm1 -- bash -c "mkdir -p ~/.ssh && echo '$key' >> ~/.ssh/authorized_keys"
```
Die erste Zeile liest deinen öffentlichen Schlüssel und speichert ihn in der Variablen `$key`. Eine Variable ist ein Platzhalter für einen Wert. Die zweite Zeile führt mit `multipass exec vm1 --` Befehle in vm1 aus:
- `mkdir -p ~/.ssh` erstellt den Ordner `.ssh`, falls er noch fehlt.
- `echo '$key' >> ~/.ssh/authorized_keys` hängt deinen Schlüssel an die Datei `authorized_keys` an. In dieser Datei stehen alle Schlüssel, die sich am Server anmelden dürfen.

Gib die beiden Zeilen nacheinander ein, im selben PowerShell-Fenster.

**Kontrolle:**
```powershell
multipass exec vm1 -- tail -n 1 .ssh/authorized_keys
```
Die Zeile beginnt mit `ssh-ed25519 AAAA` – gleich wie in Schritt 2.

**b) IP-Adresse von vm1 nachschauen**
```powershell
multipass list
```
**Kontrolle:** In der Spalte `IPv4` steht bei vm1 eine Adresse, z. B. `172.27.112.45`.

**c) Mit SSH anmelden**
```powershell
ssh ubuntu@<IP-von-vm1>
```
`ssh` baut die verschlüsselte Verbindung auf. `ubuntu` ist der Benutzername in vm1, nach dem `@` folgt die Adresse des Servers. Ersetze `<IP-von-vm1>` durch die Adresse aus b), ohne die Klammern `< >`.

Beim ersten Verbinden fragt SSH: `Are you sure you want to continue connecting (yes/no/[fingerprint])?` Tippe `yes` und drücke `Enter`.

**Kontrolle:** Du wirst **nicht** nach einem Passwort gefragt. Die Eingabezeile sieht so aus: `ubuntu@vm1:~$`

**d) Verbindung beenden**
```bash
exit
```
**Kontrolle:** Du bist zurück in PowerShell (`PS C:\Users\…>`).

### Schritt 4: Fragen
Kreuze im Lernjournal an:

| Aussage | richtig | falsch |
|---------|:-------:|:------:|
| Den öffentlichen Schlüssel darf ich in Azure hochladen. | | |
| Den privaten Schlüssel schicke ich per Teams an die Kursleitung. | | |
| Wer meinen privaten Schlüssel hat, kann sich als ich anmelden. | | |
| Verliere ich den privaten Schlüssel, kann ich ihn aus dem öffentlichen zurückrechnen. | | |
| Bei der Anmeldung in Schritt 3 musste ich kein Passwort eingeben, weil vm1 meinen öffentlichen Schlüssel kennt. | | |

> [!IMPORTANT]
> Lösche den Ordner `~\.ssh` **nicht**. Du brauchst den Schlüssel an Tag 3.

### Schritt 5: Aufräumen
Erst wenn du fertig bist. Machst du danach den Zusatzauftrag 1.7 ⭐ **nicht**, löschst du vm1:
```powershell
multipass delete --purge vm1
multipass list
```
**Kontrolle:** `No instances found.` Den Ordner `~\.ssh` behältst du.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `Die Benennung "ssh-keygen" wurde nicht … erkannt` (englisch: `ssh-keygen : The term 'ssh-keygen' is not recognized`) | Der OpenSSH-Client fehlt auf deinem Laptop. Prüfe unter **Einstellungen > System > Optionale Features**, ob «OpenSSH-Client» in der Liste steht. Fehlt er: **Feature anzeigen** > «OpenSSH-Client» suchen > **Hinzufügen**. Dafür brauchst du Adminrechte – sonst Kursleitung holen. Danach PowerShell schliessen, neu öffnen und Schritt 1 wiederholen. |
| OpenSSH-Client ist installiert, aber `ssh-keygen` wird trotzdem nicht erkannt | PowerShell schliessen und neu öffnen. Hilft das nicht: Laptop neu starten. |
| Keine Adminrechte, OpenSSH-Client lässt sich nicht installieren | Erstelle den Schlüssel **nicht** auf einem anderen Laptop: Der private Schlüssel gehört nur auf deinen eigenen. Notiere im Lernjournal, dass der OpenSSH-Client fehlt, und sag es der Kursleitung. Sie klärt das bis Tag 3. |
| `Permission denied (publickey)` | Der Schlüssel ist nicht in vm1 angekommen. Schritt 3a wiederholen und die Kontrolle machen. |
| SSH fragt nach einem Passwort | Du hast dich bei der Adresse oder beim Benutzernamen vertippt. Mit `Ctrl+C` abbrechen und den Befehl mit `ubuntu@` und der IP aus `multipass list` nochmals eingeben. |
| `Connection timed out` oder lange keine Antwort | vm1 läuft nicht oder die IP stimmt nicht. Mit `multipass list` prüfen, ob vm1 `Running` ist, und die IP abschreiben. Ist vm1 `Stopped`: `multipass start vm1`. |
| `WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!` | Unter dieser IP lief früher eine andere VM. Alten Eintrag löschen mit `ssh-keygen -R <IP-von-vm1>`, dann nochmals verbinden. |
