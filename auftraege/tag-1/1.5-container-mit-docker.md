# Auftrag 1.5 ⭐: Container mit Docker

Stand: 19.10.2026 · Zeit: 45 Min. · Form: Einzelarbeit · Zusatzauftrag

## Ziel
Du kannst einen Container starten und den Unterschied zwischen VM und Container beschreiben. (K2/K3)

## Voraussetzungen
- Deine VM aus Auftrag 1.2 läuft, du bist per SSH verbunden

## Ausgangslage
Ein Entwickler der «Velo Zürich AG» sagt: «Für unsere Webseite brauchen wir keine eigene VM, ein Container reicht.» Du probierst aus, was er meint.

## Auftrag

### Schritt 1: Docker installieren
```bash
sudo apt update
sudo apt install -y docker.io
sudo usermod -aG docker $USER
exit
```
Melde dich neu per SSH an, damit die Gruppenänderung gilt.

> [!NOTE]
> Wer in der Gruppe `docker` ist, hat faktisch Root-Rechte auf dem System. Auf einer Test-VM ist das in Ordnung, auf einem echten Server nur für Admins.

**Kontrolle:** `docker version` zeigt Client und Server ohne Fehlermeldung.

### Schritt 2: Erster Container
```bash
docker run --rm hello-world
```
`--rm` löscht den Container automatisch, sobald er fertig ist.
Lies die Ausgabe genau: Welche vier Schritte hat Docker gemacht?

### Schritt 3: Webserver im Container
```bash
docker run -d --name web -p 8080:80 nginx
docker ps
curl http://localhost:8080
```
**Kontrolle:** `curl` zeigt «Welcome to nginx!».

### Schritt 4: Messen und vergleichen
1. Lade zuerst das Image herunter, damit der Download nicht mitgemessen wird. Miss dann, wie lange ein Container zum Starten braucht:
   ```bash
   docker pull alpine
   time docker run --rm alpine echo "Hallo aus dem Container"
   ```
2. Schau dir die Grösse der Images an: `docker images`
3. Vergleiche mit deiner VM und fülle aus:

   | | VM (`vm-lokal-<kuerzel>`) | Container (`nginx`) |
   |---|---|---|
   | Startzeit | | |
   | Grösse auf der Disk | | |
   | Eigener Kernel? | | |
   | Typischer Einsatz | | |

### Schritt 5: Aufräumen
```bash
docker rm -f web
docker image prune -a -f
```
