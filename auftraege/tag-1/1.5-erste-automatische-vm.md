# Auftrag 1.5: Deine erste automatische VM mit cloud-init

Zeit: 45 Min. · Form: Einzelarbeit

## Ziel
- Du kannst eine VM mit einer cloud-init-Datei erstellen. (K3)
- Du kannst prüfen, ob cloud-init die VM richtig eingerichtet hat. (K3)
- Du kannst beschreiben, was cloud-init gegenüber dem Einrichten von Hand spart. (K2)

## Voraussetzungen
- Auftrag 1.4 erledigt, die Tabelle mit deiner Zeit liegt im Lernjournal
- eine Stoppuhr (Handy oder Windows-App «Uhr»)

## Ausgangslage
In Auftrag 1.4 hast du einen Testserver der «Velo Zürich AG» von Hand eingerichtet. Die Firma braucht aber 10 davon. Von Hand wäre das viel Arbeit – und fehleranfällig.

**cloud-init** löst das Problem: Du schreibst in eine Textdatei, wie die VM eingerichtet werden soll. Beim **ersten Start** arbeitet die VM diese Datei automatisch ab. Genau so funktioniert es später auch in Azure.

## Auftrag

### Schritt 1: Einen Arbeitsordner anlegen
```powershell
mkdir -Force $HOME\azure-kurs
cd $HOME\azure-kurs
```
`mkdir` erstellt einen Ordner in deinem Benutzerordner, `cd` wechselt hinein. Alle Dateien des Kurses legst du hier ab.

**Kontrolle:** Die Eingabezeile endet mit `\azure-kurs>`.

### Schritt 2: Die cloud-init-Datei erstellen
Öffne die neue Datei direkt aus PowerShell im Editor:
```powershell
notepad cloud-init-tag1.yaml
```
Notepad fragt, ob es die Datei erstellen soll: **Ja**. Kopiere diesen Inhalt hinein und speichere mit `Ctrl` + `S`:

```yaml
#cloud-config
package_update: true
packages:
  - tree
  - htop
write_files:
  - path: /opt/willkommen.txt
    content: |
      Diese Datei hat cloud-init erstellt.
      Niemand hat sie von Hand angelegt.
runcmd:
  - echo "Fertig eingerichtet am $(date)" >> /opt/willkommen.txt
```

> [!WARNING]
> Die **Einrückung** ist wichtig: genau 2 Leerzeichen pro Stufe, keine Tabs. Kopiere den Inhalt darum genau so.

Was steht in der Datei?

| Zeile / Block | Bedeutung | In Auftrag 1.4 von Hand |
|---------------|-----------|-------------------------|
| `#cloud-config` | Kennzeichnung: Das ist eine cloud-init-Datei. Muss die erste Zeile sein. | – |
| `package_update: true` | Paketliste aktualisieren | `sudo apt update` |
| `packages:` | Diese Programme installieren: `tree` und `htop` | `sudo apt install -y tree htop` |
| `write_files:` | Diese Datei mit diesem Inhalt anlegen | `echo … \| sudo tee /opt/willkommen.txt` |
| `runcmd:` | Am Schluss diesen Befehl ausführen | `echo … \| sudo tee -a /opt/willkommen.txt` |

Die Datei enthält also genau deine Schritte aus Auftrag 1.4 – nur aufgeschrieben statt getippt.

**Kontrolle:** `dir` in PowerShell zeigt die Datei `cloud-init-tag1.yaml`.

### Schritt 3: Die VM mit cloud-init erstellen
Starte die Stoppuhr **jetzt**. Die Datei zählt nicht zur Zeit: Du schreibst sie einmal und verwendest sie für alle 10 Server.
```powershell
multipass launch --name auto --cloud-init cloud-init-tag1.yaml
```
`--cloud-init` gibt der VM die Datei für den ersten Start mit.

**Kontrolle:** `Launched: auto`. Das dauert etwas länger als `multipass launch --name hand` in Auftrag 1.4, weil die VM beim Start Programme installiert.

### Schritt 4: Hat cloud-init gearbeitet?
Prüfe drei Dinge – ohne dass du etwas von Hand installiert hast. Stoppe die Stoppuhr, wenn die drei Befehle eine Ausgabe gezeigt haben.

```powershell
multipass exec auto -- tree --version
multipass exec auto -- cat /opt/willkommen.txt
multipass exec auto -- tail -n 5 /var/log/cloud-init-output.log
```

| Befehl | Was du prüfst |
|--------|---------------|
| `tree --version` | Ist das Programm `tree` installiert? |
| `cat …/willkommen.txt` | Gibt es die Datei, und was steht drin? |
| `tail -n 5 …/cloud-init-output.log` | Die letzten 5 Zeilen des cloud-init-Protokolls |

**Kontrolle:** `tree` zeigt eine Versionsnummer. Die Datei hat drei Zeilen. Im Protokoll steht weiter unten `Cloud-init … finished`.

> [!TIP]
> Merke dir den Pfad `/var/log/cloud-init-output.log`. Wenn cloud-init einmal nicht funktioniert, steht dort, warum.

### Schritt 5: Fragen
Beantworte im Lernjournal:

2. Ergänze den Satz: «cloud-init läuft nur beim ________ Start der VM.»
3. Übertrage deine Werte aus Auftrag 1.4 in diese Tabelle und fülle die Spalte «cloud-init (1.5)» aus:

### Schritt 6: Aufräumen
```powershell
multipass delete --purge auto
```
**Kontrolle:** `multipass list` zeigt nur noch vm1.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `could not read cloud-init file` | Bist du im richtigen Ordner (`cd $HOME\azure-kurs`)? Zeigt `dir` die Datei `cloud-init-tag1.yaml` (und nicht `.yaml.txt`)? |
| `timed out waiting for initialization` | Die Installation dauert länger. Warten, dann `multipass list` prüfen. Beim nächsten Mal `--timeout 600` anhängen. |
| `tree` fehlt, Datei fehlt | Protokoll lesen: `multipass exec auto -- cat /var/log/cloud-init-output.log`. Häufig: Einrückung falsch (Leerzeichen, keine Tabs). |

## Zusatzaufgabe ⭐ Eigene Erweiterung
Erweitere die Datei um **ein weiteres Programm** (z. B. `cowsay`) und eine **zweite Datei** mit eigenem Inhalt. Erstelle damit eine neue VM `auto2` und weise beides nach. Lösche die VM danach.
