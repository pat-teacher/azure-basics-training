# Auftrag 1.7 ⭐: Container mit Docker

Zeit: 30 Min. · Form: Einzelarbeit · Zusatzauftrag

## Ziel
Du kannst einen Container starten und sagen, wie er sich von einer VM unterscheidet. (K2/K3)

## Voraussetzungen
- vm1 aus Auftrag 1.2 läuft

## Ausgangslage
Ein Entwickler der «Velo Zürich AG» sagt: «Für unsere Webseite brauchen wir keine eigene VM. Ein **Container** reicht.» Ein Container ist ein verpacktes Programm, das sich den Kern (Kernel) des Betriebssystems mit anderen Containern teilt. Du probierst es aus – in deiner vm1.

## Auftrag

### Schritt 1: In die VM wechseln und Docker installieren
```powershell
multipass shell vm1
```
In der VM:
```bash
sudo apt update
sudo apt install -y docker.io
```
`sudo` führt den Befehl mit Administratorrechten aus. `apt install` installiert ein Programm, hier Docker.

**Kontrolle:** `sudo docker version` zeigt die Abschnitte `Client` und `Server`.

### Schritt 2: Erster Container
```bash
sudo docker run --rm hello-world
```
`docker run` startet einen Container aus einem Image (einer Vorlage). `--rm` löscht ihn danach wieder.

**Kontrolle:** Die Ausgabe beginnt mit `Hello from Docker!`

### Schritt 3: Ein Webserver im Container
```bash
sudo docker run -d --name web -p 8080:80 nginx
curl http://localhost:8080
```
`-d` lässt den Container im Hintergrund laufen. `-p 8080:80` leitet Port 8080 der VM an Port 80 im Container weiter.

**Kontrolle:** `curl` zeigt HTML mit `Welcome to nginx!`

### Schritt 4: VM oder Container?
Kreuze an:

| | VM | Container |
|---|:--:|:--:|
| hat ein eigenes, vollständiges Betriebssystem | | |
| startet in weniger als einer Sekunde | | |
| ist meist nur wenige MB bis einige 100 MB gross | | |
| eignet sich, um ein anderes Betriebssystem zu testen | | |

### Schritt 5: Aufräumen
```bash
sudo docker rm -f web
exit
```
Zurück in PowerShell löschst du vm1:
```powershell
multipass delete --purge vm1
multipass list
```
**Kontrolle:** `No instances found.` Den Ordner `~\.ssh` behältst du.
