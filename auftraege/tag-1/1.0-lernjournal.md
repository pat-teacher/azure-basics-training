# Auftrag 1.0: Dein Lernjournal auf GitHub oder GitLab

Zeit: 25 Min. · Form: Einzelarbeit

## Ziel
- Du kannst ein privates Repository anlegen und eine Person als Mitglied hinzufügen. (K3)
- Du kannst eine Notiz in Markdown schreiben und in der richtigen Ordnerstruktur ablegen. (K3)

## Voraussetzungen
- Eine E-Mail-Adresse, mit der du dich registrieren kannst
- Hast du schon ein Konto bei GitHub oder GitLab, verwendest du dieses.

## Ausgangslage
In diesem Kurs hältst du fest, was du gemacht und gelernt hast: dein **Lernjournal**. Die Kurstage sind verteilt. Mit dem Lernjournal findest du am nächsten Kurstag schnell wieder hinein.

Du führst dein Lernjournal so, wie es ICT-Fachleute mit Dokumentation machen: als Textdateien in einem **Repository** (Ablage für Dateien mit Versionsverlauf) auf GitHub oder GitLab. Geschrieben wird in **Markdown**, einem einfachen Textformat. Die Kursleitung kann dein Lernjournal lesen und dir Rückmeldungen geben.

Du arbeitest heute nur im Browser. Du musst nichts installieren.

## Auftrag

### Schritt 1: Konto anlegen
Wähle **eine** Plattform: [github.com](https://github.com) oder [gitlab.com](https://gitlab.com). Erstelle ein Konto (Sign up) und bestätige deine E-Mail-Adresse.

> [!IMPORTANT]
> Wähle einen Benutzernamen ohne deinen vollen Namen, z. B. deine Initialen mit einer Zahl. Dein Benutzername ist öffentlich sichtbar.

**Kontrolle:** Du bist angemeldet und siehst oben rechts dein Profilbild.

### Schritt 2: Privates Repository erstellen
Erstelle ein neues Repository mit dem Namen `lernjournal-azure`:

| | GitHub | GitLab |
|---|---|---|
| Weg | oben rechts **+** > **New repository** | oben links **+** > **New project/repository** > **Create blank project** |
| Name | `lernjournal-azure` | `lernjournal-azure` |
| Sichtbarkeit | **Private** | **Private** |
| README | **Add a README file** ankreuzen | **Initialize repository with a README** ankreuzen |

Klicke auf **Create repository** bzw. **Create project**.

**Kontrolle:** Du siehst dein Repository mit der Datei `README.md`. Neben dem Namen steht **Private**.

### Schritt 3: Die Kursleitung als Mitglied hinzufügen
Damit die Kursleitung dein Lernjournal lesen kann, lädst du sie ein. Der Benutzername ist auf beiden Plattformen `pat-teacher`.

| GitHub | GitLab |
|---|---|
| **Settings** > **Collaborators** > **Add people** > `pat-teacher` > **Add to repository** | **Manage** > **Members** > **Invite members** > `pat-teacher`, Rolle **Reporter** > **Invite** |

**Kontrolle:** `pat-teacher` erscheint in der Liste, bei GitHub mit dem Hinweis «Pending Invite». Das ist richtig: Die Kursleitung nimmt die Einladung an.

### Schritt 4: Ordnerstruktur anlegen
Dein Lernjournal bekommt pro Kurstag einen Ordner. Darin liegt pro Auftrag ein Unterordner. So sieht das am Ende von Tag 1 aus:

```text
lernjournal-azure/
├── README.md                              ← Startseite: Kurs und deine Plattform
├── tag-1/
│   ├── README.md                          ← Notizen und Erkenntnisse des Tages, Exit-Ticket
│   ├── 1.0-lernjournal/
│   │   └── README.md
│   ├── 1.1-hypervisor-und-dein-laptop/
│   │   └── README.md                      ← dein Eintrag zum Auftrag, mit Screenshots
│   └── …
├── tag-2/
└── …
```

> [!TIP]
> **Ordnername = Dateiname des Auftrags ohne `.md`.** Auftrag `1.2-multipass-und-erste-vm.md` kommt also in den Ordner `1.2-multipass-und-erste-vm`.

Ordner legst du im Browser an, indem du eine Datei mit Pfad erstellst. Der Schrägstrich `/` macht daraus einen Ordner:

| GitHub | GitLab |
|---|---|
| **Add file** > **Create new file** | **+** (neben dem Repository-Namen) > **New file** |

Gib als Dateinamen `tag-1/README.md` ein und schreibe hinein:

```markdown
# Tag 1: Grundlagen Virtualisierung

## Notizen

## Erkenntnisse

## Exit-Ticket
```

Speichere mit **Commit changes**. Ein **Commit** ist eine gespeicherte Version, mit Datum und kurzer Beschreibung.

**Kontrolle:** Im Repository gibt es den Ordner `tag-1`, darin die Datei `README.md`.

### Schritt 5: Deinen ersten Eintrag schreiben
Erstelle die Datei `tag-1/1.0-lernjournal/README.md` mit diesem Inhalt und passe ihn an:

```markdown
# Auftrag 1.0: Dein Lernjournal

## Was ich gemacht habe
- Konto bei GitHub angelegt
- Repository `lernjournal-azure` erstellt (privat)
- pat-teacher eingeladen

## Nachweis
(Screenshot hier hineinziehen)

## Was nicht geklappt hat
- …
```

Mach einen Screenshot der Mitgliederliste aus Schritt 3 (`Windows` + `Shift` + `S`). Klicke im Bearbeitungsfeld bei «Nachweis» und füge ihn mit `Ctrl` + `V` ein. Die Plattform lädt das Bild hoch und setzt den Link selbst ein. Speichere mit **Commit changes**.

**Kontrolle:** Öffne den Ordner `1.0-lernjournal`. Unter der Dateiliste wird dein Eintrag mit Überschriften und Screenshot angezeigt.

### Schritt 6: Markdown in 5 Zeichen
Diese Zeichen brauchst du im ganzen Kurs:

| So schreibst du | So sieht es aus |
|-----------------|-----------------|
| `# Titel`, `## Untertitel` | Überschriften |
| `- Punkt` | Aufzählung |
| `**wichtig**` | **fett** |
| `` `multipass list` `` | Befehl im Text: `multipass list` |
| drei Backticks ```` ``` ```` vor und nach mehreren Zeilen | Block für Befehle und Ausgaben |

Weitere Zeichen findest du auf dem [Markdown Cheat Sheet](https://www.markdownguide.org/cheat-sheet/) (Spickzettel, englisch).

Ergänze in deinem Eintrag unter «Was ich gemacht habe» eine Zeile mit einem Befehl in Backticks, z. B. `` `multipass version` ``. Speichere.

**Kontrolle:** Der Befehl erscheint in Schreibmaschinenschrift mit grauem Hintergrund.

## Erwartetes Ergebnis
- Privates Repository `lernjournal-azure`, `pat-teacher` eingeladen
- Ordner `tag-1` mit `README.md` und dem Unterordner `1.0-lernjournal` mit deinem ersten Eintrag

**Ab jetzt gilt für jeden Auftrag:** Alles, was unter «Erwartetes Ergebnis» steht, kommt in den passenden Unterordner. Am Ende jedes Kurstages schreibst du deine Erkenntnisse und das Exit-Ticket in die `README.md` des Tages.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| Bestätigungs-Mail kommt nicht | Spam-Ordner prüfen. Nach 5 Minuten «Resend» wählen. |
| `pat-teacher` wird nicht gefunden | Schreibweise prüfen: klein, mit Bindestrich. Bei GitLab den Namen ohne `@` eingeben. |
| Ordner erscheint nicht | Der Dateiname muss den Schrägstrich enthalten: `tag-1/README.md`, nicht nur `tag-1`. Leere Ordner gibt es nicht. |
| Screenshot lässt sich nicht einfügen | Datei speichern und ins Bearbeitungsfeld ziehen. |
| Repository ist öffentlich | GitHub: **Settings** > **General** > ganz unten **Change visibility**. GitLab: **Settings** > **General** > **Visibility**. |

## Zusatzaufgabe ⭐ Mit git auf der Kommandozeile
Klone dein Repository auf deinen Laptop (`git clone <URL>`), lege lokal die Datei `tag-1/1.0-lernjournal/notiz.md` an und lade sie mit `git add`, `git commit` und `git push` hoch. Prüfe im Browser, ob die Datei angekommen ist.
