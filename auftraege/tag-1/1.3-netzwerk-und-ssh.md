# Auftrag 1.3: Netzwerk und SSH

Stand: 19.10.2026 · Zeit: 75 Min. · Form: Einzelarbeit, Teil C mit Partner

## Ziel
Du kannst die Netzwerkmodi NAT und Bridge vergleichen und dich mit einem SSH-Schlüssel an deiner VM anmelden. (K3/K4)

## Voraussetzungen
- Deine VM aus Auftrag 1.2 läuft
- OpenSSH-Server ist in der VM installiert

## Ausgangslage
In der VirtualBox-Konsole zu arbeiten ist unpraktisch: kein Kopieren, kein Einfügen. Admins verbinden sich per SSH. Genau so wirst du dich ab Tag 3 mit deinen VMs in Azure verbinden.

## Auftrag

### Teil A: NAT mit Portweiterleitung
1. Schau in der VM mit `ip a` nach der IP-Adresse. Notiere sie.
2. Öffne in VirtualBox **Ändern** > **Netzwerk** > **Adapter 1** > **Erweitert** > **Port-Weiterleitung** und lege eine Regel an:

   | Name | Protokoll | Host-IP | Host-Port | Gast-IP | Gast-Port |
   |------|-----------|---------|-----------|---------|-----------|
   | ssh | TCP | 127.0.0.1 | 2222 | *(leer)* | 22 |

3. Verbinde dich aus PowerShell mit der VM:
   ```powershell
   ssh -p 2222 <benutzer>@127.0.0.1
   ```
   Bestätige den Fingerabdruck mit `yes` und gib dein Passwort ein.

**Kontrolle:** Der Prompt zeigt `<benutzer>@vm-lokal-<kuerzel>`.

### Teil B: Anmelden mit SSH-Schlüssel
4. Erstelle in PowerShell (auf Windows, nicht in der VM) ein Schlüsselpaar. Drücke bei allen Fragen `Enter`:
   ```powershell
   ssh-keygen -t ed25519
   ```
   Falls schon ein Schlüssel existiert, überschreibe ihn **nicht**.
5. Kopiere den öffentlichen Schlüssel in die VM:
   ```powershell
   Get-Content $env:USERPROFILE\.ssh\id_ed25519.pub | ssh -p 2222 <benutzer>@127.0.0.1 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
   ```
6. Melde dich erneut an: `ssh -p 2222 <benutzer>@127.0.0.1`

**Kontrolle:** Du wirst nicht mehr nach dem Passwort gefragt.

> [!TIP]
> Merke dir, wo dein Schlüssel liegt. An Tag 3 hinterlegst du denselben öffentlichen Schlüssel in deiner Azure-VM und meldest dich vom Laptop aus an.

### Teil C: Netzwerkbrücke
7. Fahre die VM herunter (`sudo poweroff`). Stelle **Adapter 1** auf **Netzwerkbrücke** um und wähle deinen WLAN- oder LAN-Adapter.
8. Starte die VM und prüfe mit `ip a` die neue IP-Adresse.
9. Gib deiner Partnerin oder deinem Partner die IP. Sie oder er versucht von ihrem/seinem Laptop:
   ```powershell
   ping <ip-deiner-vm>
   ssh <benutzer>@<ip-deiner-vm>
   ```
10. Stelle danach wieder auf **NAT** zurück.

### Teil D: Vergleichen
11. Fülle die Tabelle aus:

    | Modus | IP-Bereich der VM | VM erreicht Internet? | Host erreicht VM? | Andere Laptops erreichen VM? |
    |-------|-------------------|-----------------------|-------------------|------------------------------|
    | NAT | | | | |
    | NAT + Portweiterleitung | | | | |
    | Netzwerkbrücke | | | | |

12. Welcher Modus ist sicherer für eine Test-VM in einem fremden WLAN? Begründe.

## Zusatzaufgabe ⭐
Verbiete in der VM die Anmeldung mit Passwort, damit nur noch Schlüssel funktionieren. Suche in `/etc/ssh/sshd_config` die passende Einstellung. Teste danach, ob du dich noch anmelden kannst, **bevor** du die Konsole schliesst.
