# Auftrag 1.5: SSH-Schlüssel für die Cloud vorbereiten

Stand: 19.10.2026 · Zeit: 20 Min. · Form: Einzelarbeit

## Ziel
- Du kannst ein SSH-Schlüsselpaar erstellen. (K3)
- Du kannst erklären, welcher Schlüssel geheim bleibt und welcher auf den Server kommt. (K2)

## Voraussetzungen
- PowerShell

## Ausgangslage
Ab Tag 3 meldest du dich an VMs in Azure an. Dafür verwendest du kein Passwort, sondern ein **SSH-Schlüsselpaar** (SSH Key Pair). **SSH** (Secure Shell) ist eine verschlüsselte Verbindung zu einem Server. Das Schlüsselpaar erstellst du heute.

Ein Schlüsselpaar besteht aus zwei Dateien:

| Datei | Vergleich | Wohin? |
|-------|-----------|--------|
| **privater** Schlüssel (Private Key) `id_ed25519` | dein Schlüssel | bleibt **nur** auf deinem Laptop – nie weitergeben |
| **öffentlicher** Schlüssel (Public Key) `id_ed25519.pub` | das passende Schloss | kommt auf den Server – darf jeder sehen |

## Auftrag

### Schritt 1: Schlüsselpaar erstellen
```powershell
ssh-keygen -t ed25519
```
`ssh-keygen` erstellt ein neues Schlüsselpaar. `-t ed25519` wählt ein modernes Verfahren.

Drücke bei allen drei Fragen einfach `Enter`.

> [!WARNING]
> Kommt die Meldung `already exists. Overwrite (y/n)?`, dann hast du schon einen Schlüssel. Tippe **n** und mach bei Schritt 2 weiter.

**Kontrolle:** Am Schluss erscheint ein Bild aus Zeichen (randomart) und `Your public key has been saved in …id_ed25519.pub`.

### Schritt 2: Den öffentlichen Schlüssel anzeigen
```powershell
Get-Content ~\.ssh\id_ed25519.pub
```
`Get-Content` zeigt den Inhalt einer Datei. `~` steht für deinen Benutzerordner.

**Kontrolle:** Eine lange Zeile, die mit `ssh-ed25519 AAAA` beginnt.

### Schritt 3: Fragen
Kreuze im Lernjournal an:

| Aussage | richtig | falsch |
|---------|:-------:|:------:|
| Den öffentlichen Schlüssel darf ich in Azure hochladen. | | |
| Den privaten Schlüssel schicke ich per Teams an die Kursleitung. | | |
| Wer meinen privaten Schlüssel hat, kann sich als ich anmelden. | | |
| Verliere ich den privaten Schlüssel, kann ich ihn aus dem öffentlichen zurückrechnen. | | |

> [!IMPORTANT]
> Lösche den Ordner `~\.ssh` **nicht**. Du brauchst den Schlüssel an Tag 3.

### Schritt 4: Aufräumen
Erst wenn du fertig bist – auch mit der Zusatzaufgabe unten. Machst du danach den Zusatzauftrag 1.6 ⭐ **nicht**, löschst du vm1:
```powershell
multipass delete --purge vm1
multipass list
```
**Kontrolle:** `No instances found.` Den Ordner `~\.ssh` behältst du.

## Zusatzaufgabe ⭐ Mit SSH in deine VM
Hinterlege deinen öffentlichen Schlüssel in vm1 und melde dich per SSH an:
```powershell
Get-Content ~\.ssh\id_ed25519.pub | multipass exec vm1 -- bash -c "cat >> ~/.ssh/authorized_keys"
multipass list
ssh ubuntu@<IP-von-vm1>
```
Die IP von vm1 steht in `multipass list`. Bestätige die Frage beim ersten Verbinden mit `yes`. Mit `exit` kommst du zurück.
