# Auftrag 4.4: Sicherheitsregeln – Web für alle, SSH nur von der Schule

Zeit: 45 Min. · Form: Partnerarbeit (jede Person in ihrem eigenen Abonnement (Subscription))

## Ziel
- Du kannst Sicherheitsregeln (Security Rules) einer NSG erstellen, ändern und löschen. (K3)
- Du kannst die Quelle (Source) einer Sicherheitsregel (Security Rule) auf eine IP-Adresse einschränken. (K3)
- Du kannst vorhersagen, welche Sicherheitsregel (Security Rule) wegen ihrer Priorität (Priority) gewinnt. (K3)

## Voraussetzungen
- Auftrag 4.3 erledigt, `vm-web-<kuerzel>` und `vm-intern-<kuerzel>` laufen
- Cloud Shell (Bash) und PowerShell auf dem Laptop
- Lernjournal: Ordner `tag-4/4.4-sicherheitsregeln`

## Ausgangslage
Der Webserver der Velo Zürich AG soll den Webshop für **alle** im Internet zeigen. Anmelden per SSH dürfen sich aber nur Leute aus dem Netz der Schule. Heute ist SSH noch für die ganze Welt offen (Auftrag 4.3, Schritt 2). Das änderst du jetzt.

| Sicherheitsregel (Security Rule) | Priorität (Priority) | Port | Quelle (Source) | Aktion |
|----------------------------------|---------------------:|-----:|-----------------|--------|
| `allow-http` (neu) | 200 | 80 | Internet | Allow |
| `allow-ssh` (anpassen) | 1000 | 22 | nur die Schule | Allow |

> [!TIP]
> **Vorhersage zuerst:** Vor jedem Test sagt dein Partner voraus, was passieren wird: «geht» oder «geht nicht», mit einem Grund. Notiert die Vorhersage. Dann testet ihr. Wechselt euch bei jedem Test ab.

## Auftrag

### Schritt 1: Webserver installieren (in vm-web)
Melde dich in der **PowerShell** an `vm-web` an und installiere nginx wie in Auftrag 3.3:
```powershell
ssh azureuser@<öffentliche-ip>
```
```bash
sudo apt update
sudo apt install -y nginx
echo "<h1>Webshop auf $(hostname)</h1>" | sudo tee /var/www/html/index.html
curl localhost
```

**Kontrolle:** `curl localhost` zeigt `<h1>Webshop auf vm-web-<kuerzel></h1>`.

Bleib in der VM angemeldet, du brauchst sie in Schritt 4.

### Schritt 2: Test im Browser
**Vorhersage:** Lädt `http://<öffentliche-ip>` im Browser?

Öffne auf dem Laptop `http://<öffentliche-ip>` (mit `http`, nicht `https`).

**Kontrolle:** Der Browser lädt lange und meldet dann einen Fehler. In `nsg-web` gibt es noch keine Sicherheitsregel (Security Rule) für Port 80. Darum greift die Standardsicherheitsregel (Default Security Rule) `DenyAllInBound`.

### Schritt 3: Port 80 für alle öffnen (Cloud Shell)
```bash
az network nsg rule create --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name allow-http --priority 200 --direction Inbound --access Allow --protocol Tcp --destination-port-ranges 80 --source-address-prefixes Internet
```
`Internet` ist ein Diensttag (Service Tag): ein Name, hinter dem Azure alle Adressen im Internet zusammenfasst. Du musst sie nicht selbst aufzählen.

**Kontrolle:** Lade den Browser-Tab neu (`Ctrl` + `F5`). Nach höchstens einer Minute siehst du «Webshop auf vm-web-<kuerzel>». Öffne auch die Website deines Partners: Sie geht bei dir genauso.

### Schritt 4: Die IP-Adresse der Schule herausfinden (in vm-web)
Die VM weiss, von welcher Adresse deine SSH-Verbindung kommt:
```bash
echo $SSH_CLIENT
```
`SSH_CLIENT` enthält drei Werte: die Adresse, von der du kommst, deinen Port und Port 22. Die erste Zahl ist die öffentliche IP (Public IP) der Schule.

**Kontrolle:** Die Ausgabe sieht so aus: `198.51.100.23 51234 22`. Dein Partner hat dieselbe erste Zahl, weil ihr im selben Schulnetz seid. Vergleicht auch mit der Adresse, die die Kursleitung angibt.

Notiere die erste Zahl als `<schul-ip>`. Beende die Verbindung mit `exit`.

### Schritt 5: SSH nur noch von der Schule (Cloud Shell)
```bash
az network nsg rule update --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name allow-ssh --source-address-prefixes <schul-ip>/32
```
`rule update` ändert eine bestehende Sicherheitsregel (Security Rule). `/32` heisst: genau **eine** Adresse (alle 32 Bits sind fix).

**Vorhersage:** Kannst du dich vom Laptop noch anmelden?

```powershell
ssh azureuser@<öffentliche-ip>
```

**Kontrolle:** Die Anmeldung klappt. Beende sie gleich wieder mit `exit`.

### Schritt 6: Gegenprobe – eine fremde Quelle (Cloud Shell)
Stimmt es wirklich, dass andere Adressen draussen bleiben? Dafür trägst du kurz eine fremde Adresse ein. `203.0.113.10` stammt aus einem Bereich, der nur für Beispiele reserviert ist. Sie gehört niemandem.
```bash
az network nsg rule update --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name allow-ssh --source-address-prefixes 203.0.113.10/32
```

**Vorhersage:** Geht SSH vom Laptop? Geht die Website?

```powershell
ssh -o ConnectTimeout=15 azureuser@<öffentliche-ip>
```
`-o ConnectTimeout=15` bricht nach 15 Sekunden ab, statt lange zu warten.

**Kontrolle:** SSH meldet `Connection timed out`. Die Website lädt im Browser weiterhin, denn `allow-http` ist nicht betroffen.

Stelle die Schul-IP wieder ein:
```bash
az network nsg rule update --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name allow-ssh --source-address-prefixes <schul-ip>/32
```

**Kontrolle:** `ssh azureuser@<öffentliche-ip>` klappt wieder. Beende mit `exit`.

### Schritt 7: Wer gewinnt? Die Priorität (Cloud Shell)
Du fügst eine Sicherheitsregel (Security Rule) hinzu, die Port 80 **verbietet**. Sie hat die Priorität (Priority) 150, `allow-http` hat 200.
```bash
az network nsg rule create --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name deny-http --priority 150 --direction Inbound --access Deny --protocol Tcp --destination-port-ranges 80 --source-address-prefixes Internet
```

**Vorhersage:** Lädt die Website noch?

**Kontrolle:** Öffne die Website in einem **privaten Fenster** (`Ctrl` + `Shift` + `N`). Nach höchstens einer Minute lädt sie nicht mehr. Ein normaler Tab kann noch eine Weile laden, weil der Browser eine offene Verbindung weiterverwendet. Azure prüft die kleinere Zahl zuerst: `deny-http` (150) passt und entscheidet. `allow-http` (200) kommt gar nicht mehr dran.

Jetzt gibst du `deny-http` eine grössere Zahl als `allow-http`:
```bash
az network nsg rule update --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name deny-http --priority 300
```

**Vorhersage:** Und jetzt?

**Kontrolle:** Die Website lädt wieder. Jetzt kommt `allow-http` (200) zuerst.

Lösche die Test-Sicherheitsregel:
```bash
az network nsg rule delete --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name deny-http
```

### Schritt 8: Alle Sicherheitsregeln anzeigen (Cloud Shell)
```bash
az network nsg rule list --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --output table
```
Mit `--include-default` siehst du zusätzlich die Standardsicherheitsregeln (Default Security Rules):
```bash
az network nsg rule list --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --include-default --output table
```

**Kontrolle:** Die erste Tabelle zeigt genau zwei Sicherheitsregeln (Security Rules): `allow-http` (200) und `allow-ssh` (1000) mit deiner Schul-IP. Die zweite zeigt zusätzlich sechs Standardsicherheitsregeln (Default Security Rules) mit 65000, 65001 und 65500.

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| Website lädt nach Schritt 3 nicht | 1 Minute warten, mit `http://` öffnen, `Ctrl` + `F5`. Läuft nginx? (`curl localhost` in der VM) |
| `echo $SSH_CLIENT` ist leer | Du bist in der Cloud Shell statt in der VM. Der Befehl gehört in die SSH-Sitzung auf `vm-web`. |
| Nach Schritt 5 geht SSH nicht mehr | Schul-IP falsch abgetippt. Schritt 6 «Stelle die Schul-IP wieder ein» mit der richtigen Adresse ausführen. Die Cloud Shell geht immer, sie braucht kein SSH. |
| `SecurityRuleConflict` oder Fehler zur Priorität (Priority) | Zwei Sicherheitsregeln (Security Rules) in derselben Richtung dürfen nicht dieselbe Priorität (Priority) haben. Andere Zahl wählen. |
| Website lädt in Schritt 7 trotz `deny-http` | Der Browser verwendet eine offene Verbindung oder eine gespeicherte Kopie. Neues privates Fenster öffnen oder 1–2 Minuten warten. |
