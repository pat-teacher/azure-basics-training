# Auftrag 4.1: Subnetting-Training für die «Velo Zürich AG»

Zeit: 45 Min. · Form: Partnerarbeit

## Ziel
- Du kannst zu einer CIDR-Angabe die Anzahl Adressen berechnen. (K3)
- Du kannst prüfen, ob eine IP-Adresse in einem Subnetz (Subnet) liegt. (K2)
- Du kannst für einen Bedarf eine passende Subnetzgrösse wählen. (K3)

## Voraussetzungen
- Input «VNet und Subnetze»
- Theorie zum Nachlesen: [Kapitel 6 Azure Networking](../../theorie/06-azure-networking.md), Abschnitt «CIDR in Kürze»
- Papier und Stift oder ein Editor. Du brauchst heute **kein** Azure.
- Lernjournal: Ordner `tag-4/4.1-subnetting`

## Ausgangslage
Die Velo Zürich AG baut ihr Netz in Azure auf. Sie bekommt den Adressraum (Address Space) `10.10.0.0/16`. Darin plant sie drei Subnetze (Subnets):
- **snet-web** für die Webserver des Webshops
- **snet-intern** für interne Server, z. B. Datenbank und Buchhaltung
- **snet-admin** für die Verwaltung

Bevor jemand etwas in Azure erstellt, rechnet ihr den Plan auf Papier durch.

> [!TIP]
> **Die Formel:** Anzahl Adressen = 2<sup>(32 − Zahl nach dem /)</sup>. Beispiel `/24`: 2<sup>8</sup> = 256.
> **In Azure nutzbar:** Azure reserviert in jedem Subnetz (Subnet) 5 Adressen. Nutzbar sind also immer 5 weniger.
>
> | 2<sup>3</sup> | 2<sup>4</sup> | 2<sup>5</sup> | 2<sup>6</sup> | 2<sup>7</sup> | 2<sup>8</sup> | 2<sup>16</sup> |
> |---|---|---|---|---|---|---|
> | 8 | 16 | 32 | 64 | 128 | 256 | 65 536 |

Löst jeden Schritt zuerst **allein**. Vergleicht danach mit eurem Partner. Wenn ihr verschiedene Resultate habt, rechnet gemeinsam nach.

## Auftrag

### Schritt 1: Wie gross ist das Netz?
Ergänze die Tabelle. Die Zeile `/24` ist als Beispiel ausgefüllt.

| CIDR | Adressen | in Azure nutzbar |
|------|----------|------------------|
| `/16` | | |
| `/24` | 256 | 251 |
| `/25` | | |
| `/26` | | |
| `/27` | | |
| `/28` | | |
| `/29` | | |

**Kontrolle:** Von oben nach unten halbiert sich die Anzahl Adressen bei jeder Zeile ab `/24`. `/29` ist das kleinste Subnetz (Subnet), das Azure erlaubt.

### Schritt 2: Von wo bis wo?
Ergänze für jedes Subnetz (Subnet) die erste und die letzte Adresse sowie die Adresse, die die erste VM bekommt.

| Subnetz (Subnet) | erste Adresse | letzte Adresse | erste VM bekommt |
|------------------|---------------|----------------|------------------|
| `10.10.1.0/24` | `10.10.1.0` | | |
| `10.10.3.0/27` | | | |
| `10.10.3.32/27` | | | |
| `10.10.4.0/28` | | | |

So gehst du vor: Erste Adresse + Anzahl Adressen − 1 = letzte Adresse. Die erste VM bekommt die **fünfte** Adresse, weil Azure die ersten vier reserviert.

**Kontrolle:** Die letzte Adresse von `10.10.3.0/27` und die erste von `10.10.3.32/27` folgen direkt aufeinander.

### Schritt 3: Liegt die Adresse im Subnetz?
Kreuze an.

| | IP-Adresse | Subnetz (Subnet) | ja | nein |
|---|------------|------------------|:--:|:----:|
| a | `10.10.1.200` | `10.10.1.0/24` | | |
| b | `10.10.2.5` | `10.10.1.0/24` | | |
| c | `10.10.3.20` | `10.10.3.0/27` | | |
| d | `10.10.3.40` | `10.10.3.0/27` | | |
| e | `10.10.4.20` | `10.10.4.0/28` | | |

**Kontrolle:** Benutze deine Tabelle aus Schritt 2. Zwei Antworten sind «ja».

### Schritt 4: Welche Grösse reicht?
Die Velo Zürich AG nennt ihren Bedarf. Wähle jeweils das **kleinste** Subnetz (Subnet), das reicht. Rechne mit den in Azure nutzbaren Adressen aus Schritt 1.

| Subnetz (Subnet) | Bedarf | `/24` | `/26` | `/27` | `/29` |
|------------------|--------|:-----:|:-----:|:-----:|:-----:|
| snet-web | 50 Webserver | | | | |
| snet-intern | 20 interne Server | | | | |
| snet-admin | 3 Server | | | | |

**Kontrolle:** Pro Zeile ist genau ein Kreuz gesetzt. Kein Subnetz (Subnet) ist zu klein.

### Schritt 5: Fehler im Plan finden
Ein Mitarbeiter hat diesen Plan gemacht:

| Subnetz (Subnet) | Bereich |
|------------------|---------|
| snet-web | `10.10.1.0/24` |
| snet-intern | `10.10.1.128/25` |
| snet-admin | `10.10.2.0/29` |

Azure lehnt den Plan ab, weil sich zwei Bereiche **überlappen**. Das heisst: Einige Adressen gehören zu beiden Subnetzen (Subnets).

1. Welche zwei Subnetze (Subnets) überlappen? Schreibe die Namen auf.
2. snet-intern bekommt einen neuen Bereich. Kreuze **alle** Bereiche an, die mit keinem anderen Subnetz (Subnet) überlappen und im Adressraum (Address Space) `10.10.0.0/16` liegen:
   - [ ] `10.10.2.0/25`
   - [ ] `10.10.3.0/25`
   - [ ] `10.10.2.128/25`
   - [ ] `10.11.1.0/25`

**Kontrolle:** Prüfe jeden Bereich wie in Schritt 2: Erste und letzte Adresse dürfen in keinem anderen Subnetz (Subnet) liegen. Zwei Bereiche passen.
