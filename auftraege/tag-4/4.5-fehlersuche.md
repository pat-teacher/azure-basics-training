# Auftrag 4.5: Fehlersuche – «Warum komme ich nicht auf meine VM?»

Zeit: 45 Min. (Fehlersuche) + 10 Min. (Netzplan, L8) · Form: Partnerarbeit

## Ziel
- Du kannst bei einem Verbindungsproblem mit einer Checkliste die Ursache finden. (K4)
- Du kannst den gefundenen Fehler beheben. (K3)

## Voraussetzungen
- Auftrag 4.4 erledigt: Die Website auf `vm-web-<kuerzel>` lädt, SSH von der Schule geht
- Cloud Shell (Bash) und PowerShell auf dem Laptop
- Theorie zum Nachlesen: [Kapitel 6 Azure Networking](../../theorie/06-azure-networking.md), Abschnitt «Der Weg einer Anfrage»
- Lernjournal: Ordner `tag-4/4.5-fehlersuche`

## Ausgangslage
Im Support der Velo Zürich AG kommt ein Ticket: «Der Webshop geht nicht!» Raten hilft nicht. Wer der Reihe nach prüft, findet den Fehler schneller.

Ihr spielt das zu zweit, in **vier Runden**:
- **Person «Störung»** baut in der **eigenen** Umgebung heimlich einen Fehler ein. Dafür wählt sie eine Fehlerkarte.
- **Person «Support»** sucht den Fehler auf dem Laptop der Störung mit der Checkliste und behebt ihn.

| Runde | Störung | Support | Fehlerkarten |
|-------|---------|---------|--------------|
| 1 | A | B | 1 oder 2 |
| 2 | B | A | 1 oder 2 |
| 3 | A | B | 3 oder 4 |
| 4 | B | A | 3 oder 4 |

> [!IMPORTANT]
> **Spielregeln für den Support:** Du liest die Fehlerkarten nicht. Du darfst nur die Befehle aus der Checkliste und dem Werkzeugkasten verwenden. Bevor du etwas reparierst, sagst du laut: «Station …, Befund …, Ursache …».

## Die Checkliste
Prüfe die Stationen **der Reihe nach**, wie in Kapitel 6. Ersetze `<kuerzel>` durch das Kürzel der Person «Störung».

| Station | So prüfst du | So sieht es aus, wenn alles stimmt |
|---------|--------------|------------------------------------|
| 0. Fehlerbild | Website im Browser öffnen (`Ctrl` + `F5`), `ssh -o ConnectTimeout=15 azureuser@<öffentliche-ip>` | Website lädt, SSH klappt |
| 1. Richtige IP? | `az vm list-ip-addresses --resource-group rg-tag4-<kuerzel> --output table` | Die öffentliche IP (Public IP) ist die, die du im Browser verwendest. |
| 2. NSG am Subnetz (Subnet) | `az network nsg rule list --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --output table` | `allow-http` mit Port 80 und `allow-ssh` mit Port 22. Keine Deny-Sicherheitsregel (Security Rule) mit kleinerer Zahl für denselben Port. |
| 3. NSG an der Netzwerkschnittstelle (Network Interface) | `az network nic show --resource-group rg-tag4-<kuerzel> --name vm-web-<kuerzel>VMNic --query networkSecurityGroup.id --output tsv` | keine Ausgabe (keine NSG an der Netzwerkschnittstelle (Network Interface)) |
| 4. Firewall in der VM | in der VM: `sudo ufw status` | `Status: inactive` |
| 5. Dienst | in der VM: `systemctl status nginx --no-pager` und `curl localhost` | `active (running)` und die Startseite |

> [!TIP]
> **Achte auf die Fehlermeldung im Browser:**
> - Der Browser lädt lange und meldet dann eine **Zeitüberschreitung** (z. B. `ERR_CONNECTION_TIMED_OUT`). Die Anfrage kommt nicht bis zur VM. Verdacht: NSG (Station 2 oder 3).
> - Der Browser meldet **sofort** «Verbindung abgelehnt» (z. B. `ERR_CONNECTION_REFUSED`). Die Anfrage kommt bei der VM an, aber niemand antwortet auf dem Port. Verdacht: Dienst (Station 5).
>
> Geht SSH nicht, kannst du die Stationen 4 und 5 nicht prüfen. Dann liegt der Fehler fast sicher vorher.

## Der Werkzeugkasten
Mit diesen Befehlen reparierst du. Welchen du brauchst, findest du selbst heraus.

```bash
# Eine Sicherheitsregel löschen
az network nsg rule delete --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name <regelname>
# Den Port einer Sicherheitsregel ändern
az network nsg rule update --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name <regelname> --destination-port-ranges <port>
# Die NSG von der Netzwerkschnittstelle entfernen
az network nic update --resource-group rg-tag4-<kuerzel> --name vm-web-<kuerzel>VMNic --remove networkSecurityGroup
```
```bash
# In der VM: einen Dienst starten
sudo systemctl start <dienst>
```

## Auftrag

### Schritt 1: Ausgangslage prüfen
Beide prüfen ihre eigene Umgebung: Website lädt, `ssh azureuser@<öffentliche-ip>` klappt.

**Kontrolle:** Bei beiden geht beides. Sonst zuerst Auftrag 4.4 abschliessen.

### Schritt 2: Runde 1 bis 4 spielen
Für jede Runde:
1. **Störung:** Der Support schaut weg. Wähle eine Fehlerkarte (siehe unten) und führe den Befehl aus. Warte 1 Minute.
2. **Störung:** Gib dem Support das Ticket von der Karte. Mehr nicht.
3. **Support:** Arbeite die Checkliste ab Station 0 durch. Notiere zu jeder Station den Befund.
4. **Support:** Sage Station, Befund und Ursache. Repariere mit dem Werkzeugkasten.
5. **Beide:** Website und SSH testen.

**Kontrolle:** Nach jeder Runde gehen Website und SSH wieder. Erst dann beginnt die nächste Runde.

Halte jede Runde im Lernjournal fest:

| Runde | Ticket | Station mit Befund | Befund | Ursache | Reparatur |
|-------|--------|--------------------|--------|---------|-----------|
| 1 | | | | | |

### Schritt 3: Fragen
Beantworte im Lernjournal.
1. Welche Fehlerkarte war am schwierigsten zu finden? Warum? Antworte in ein bis zwei Sätzen.
2. Kreuze an: Der Browser meldet sofort «Verbindung abgelehnt». Wo suchst du zuerst?
   - [ ] NSG am Subnetz (Subnet)
   - [ ] Dienst in der VM
   - [ ] öffentliche IP (Public IP)

### Schritt 4: Netzplan zeichnen
Zeichne deine Umgebung, bevor du sie löschst. Du kannst die Skizze aus Auftrag 4.3 abschreiben und ergänzen, von Hand zeichnen oder ein Programm wie draw.io verwenden. Schau die Werte mit diesen Befehlen nach:
```bash
az vm list-ip-addresses --resource-group rg-tag4-<kuerzel> --output table
az network nsg rule list --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --output table
```
Dein Netzplan zeigt:
- das VNet mit Adressraum (Address Space)
- die zwei Subnetze (Subnets) mit Bereich
- beide VMs mit privater IP, `vm-web` zusätzlich mit öffentlicher IP (Public IP)
- `nsg-web`: an welchem Subnetz (Subnet) sie hängt und ihre zwei Sicherheitsregeln (Security Rules) mit Priorität (Priority), Port und Quelle (Source)

**Kontrolle:** Dein Partner findet auf deinem Plan die Antwort auf die Frage: «Von wo darf man per SSH auf `vm-web`?»

## Die Fehlerkarten
**Nur für die Person «Störung».** Ersetze `<kuerzel>` durch dein eigenes Kürzel.

<details><summary>Fehlerkarte 1</summary>

**Ticket:** «Der Webshop lädt nicht. SSH geht.»

Cloud Shell:
```bash
az network nsg rule create --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name block-web --priority 120 --direction Inbound --access Deny --protocol Tcp --destination-port-ranges 80 --source-address-prefixes '*'
```
</details>

<details><summary>Fehlerkarte 2</summary>

**Ticket:** «Der Webshop lädt nicht. SSH geht.»

In `vm-web` (PowerShell: `ssh azureuser@<öffentliche-ip>`):
```bash
sudo systemctl stop nginx
exit
```
</details>

<details><summary>Fehlerkarte 3</summary>

**Ticket:** «Nichts geht mehr: weder Webshop noch SSH.»

Cloud Shell:
```bash
az network nsg create --resource-group rg-tag4-<kuerzel> --name nsg-falle
az network nic update --resource-group rg-tag4-<kuerzel> --name vm-web-<kuerzel>VMNic --network-security-group nsg-falle
```
</details>

<details><summary>Fehlerkarte 4</summary>

**Ticket:** «Der Webshop lädt nicht. SSH geht. Wir haben nur etwas an den Einstellungen aufgeräumt.»

Cloud Shell:
```bash
az network nsg rule update --resource-group rg-tag4-<kuerzel> --nsg-name nsg-web --name allow-http --destination-port-ranges 8080
```
</details>

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `ResourceNotFound` bei `vm-web-<kuerzel>VMNic` | Name der Netzwerkschnittstelle (Network Interface) nachschauen: `az network nic list --resource-group rg-tag4-<kuerzel> --output table` |
| Website lädt trotz Fehler weiter | Der Browser hält eine offene Verbindung. Privates Fenster öffnen oder 1–2 Minuten warten. |
| Nach der Reparatur geht es noch nicht | 1 Minute warten, `Ctrl` + `F5`. Dann Checkliste nochmals ab Station 0: Vielleicht gibt es zwei Fehler. |
| Ihr kommt nicht weiter | Die Störung zeigt die Karte. Geht gemeinsam die Checkliste durch: An welcher Station hätte man es sehen können? |

## Aufräumen
Lösche am Schluss deine Ressourcengruppe (Resource Group) mit allem, was darin ist. **Ausnahme:** Machst du noch ⭐ 4.6, räumst du erst danach auf.
```bash
az group delete --name rg-tag4-<kuerzel> --yes --no-wait
```
Warte 3–5 Minuten, dann:
```bash
az group list --output table
```

**Kontrolle:** `rg-tag4-<kuerzel>` steht nicht mehr in der Liste. Steht dort noch `Deleting`, warte und prüfe nochmals.
