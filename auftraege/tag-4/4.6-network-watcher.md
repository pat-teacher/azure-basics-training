# Auftrag 4.6 ⭐: Network Watcher – Azure fragen statt ausprobieren

Zeit: 30 Min. · Form: Einzelarbeit, freiwillig

## Ziel
- Du kannst mit der IP-Flussüberprüfung (IP Flow Verify) vorhersagen, ob eine Verbindung erlaubt ist und welche Sicherheitsregel (Security Rule) entscheidet. (K3)
- Du kannst im Portal die effektiven Sicherheitsregeln (Effective Security Rules) einer VM anzeigen. (K2)

## Voraussetzungen
- Auftrag 4.5 fertig, aber **noch nicht aufgeräumt**: `vm-web-<kuerzel>` läuft, Website und SSH gehen
- `<schul-ip>` aus Auftrag 4.4, Schritt 4
- Cloud Shell (Bash)
- Lernjournal: Ordner `tag-4/4.6-network-watcher`

## Ausgangslage
In Auftrag 4.5 hast du Fehler gesucht, indem du ausprobiert hast: Browser, SSH, Befehle. **Network Watcher** ist ein Dienst von Azure, der Netzwerkprobleme für dich untersucht. Die **IP-Flussüberprüfung** (IP Flow Verify) beantwortet eine Frage wie: «Darf ein Paket von Adresse X auf Port 22 meiner VM?» Azure antwortet mit **Allow** oder **Deny** und nennt die Sicherheitsregel (Security Rule), die entschieden hat. Du musst dafür nichts senden.

## Auftrag

### Schritt 1: Ist Network Watcher eingeschaltet?
```bash
az network watcher list --output table
```
Azure schaltet Network Watcher normalerweise automatisch ein, sobald es in einer Region ein VNet gibt.

**Kontrolle:** Es gibt eine Zeile `NetworkWatcher_<region>` für deine Kursregion. Fehlt sie, schalte Network Watcher ein. Der erste Befehl erstellt die Ressourcengruppe (Resource Group) dafür, falls es sie noch nicht gibt:
```bash
az group create --name NetworkWatcherRG --location <region>
az network watcher configure --resource-group NetworkWatcherRG --locations <region> --enabled true
```
<!-- prüfen: Network Watcher im Student-Abo automatisch aktiv, Ressourcengruppe NetworkWatcherRG -->

### Schritt 2: Die erste Frage an Azure
Darf deine Schule per SSH auf `vm-web`?
```bash
az network watcher test-ip-flow --resource-group rg-tag4-<kuerzel> --vm vm-web-<kuerzel> --direction Inbound --protocol TCP --local 10.10.1.4:22 --remote <schul-ip>:50000
```

| Option | Bedeutung |
|--------|-----------|
| `--direction Inbound` | Verkehr, der zur VM hereinkommt |
| `--local 10.10.1.4:22` | Adresse und Port **auf der VM** |
| `--remote <schul-ip>:50000` | Adresse und Port **auf der anderen Seite**. Die Portnummer auf der anderen Seite ist bei Anfragen zufällig, `50000` ist ein Beispiel. |

**Kontrolle:** Die Ausgabe enthält `"access": "Allow"` und bei `"ruleName"` den Namen `allow-ssh`. <!-- prüfen: Format von ruleName (z. B. UserRule_allow-ssh / DefaultRule_DenyAllInBound) -->

### Schritt 3: Vorhersagen und prüfen
Fülle zuerst die Spalte **Vorhersage** aus, dann führe die Tests aus. Verwende den Befehl aus Schritt 2 und ändere nur `--local`, `--remote` und eventuell `--direction`.

| | Frage | `--local` | `--remote` | Vorhersage: Allow/Deny, Sicherheitsregel (Security Rule) | Ergebnis |
|---|-------|-----------|------------|---------------------------------------------------------|----------|
| a | SSH von einer fremden Adresse | `10.10.1.4:22` | `203.0.113.10:50000` | | |
| b | Website von einer fremden Adresse | `10.10.1.4:80` | `203.0.113.10:50000` | | |
| c | Remotedesktop (RDP) von der Schule | `10.10.1.4:3389` | `<schul-ip>:50000` | | |
| d | VM ruft eine Website im Internet auf (`--direction Outbound`) | `10.10.1.4:50000` | `1.1.1.1:443` | | |

**Kontrolle:** Zwei Tests ergeben `Allow`, zwei `Deny`. Bei jedem `Deny` steht eine Standardsicherheitsregel (Default Security Rule).

### Schritt 4: Dasselbe im Portal
1. Suche im Portal oben nach **Network Watcher** und öffne ihn.
2. Klicke links unter **Netzwerkdiagnosetools** (Network diagnostic tools) auf **IP-Flussüberprüfung** (IP flow verify).
3. Wähle deine VM `vm-web-<kuerzel>` und wiederhole Test a aus Schritt 3.

**Kontrolle:** Das Portal zeigt dasselbe Ergebnis wie die CLI.

### Schritt 5: Effektive Sicherheitsregeln
Die **effektiven Sicherheitsregeln** (Effective Security Rules) zeigen alle Sicherheitsregeln (Security Rules), die für eine VM wirklich gelten: aus der NSG am Subnetz (Subnet) und aus der NSG an der Netzwerkschnittstelle (Network Interface) zusammen.

1. Öffne die VM `vm-web-<kuerzel>`.
2. Klicke links auf **Netzwerkeinstellungen** (Network settings).
3. Klicke auf **Effektive Sicherheitsregeln** (Effective security rules). <!-- prüfen: genaue Position der Schaltfläche im englischen Portal -->

**Kontrolle:** Du siehst `allow-http`, `allow-ssh` und die Standardsicherheitsregeln (Default Security Rules) aus `nsg-web`.

### Schritt 6: Frage
Beantworte im Lernjournal in ein bis zwei Sätzen: Bei welcher Station der Checkliste aus Auftrag 4.5 hätte dir die IP-Flussüberprüfung (IP Flow Verify) geholfen, und bei welcher nicht?

## Aufräumen
```bash
az group delete --name rg-tag4-<kuerzel> --yes --no-wait
```
Die Ressourcengruppe (Resource Group) `NetworkWatcherRG` darf bleiben. Azure hat sie angelegt, sie kostet nichts.

**Kontrolle:** Nach 3–5 Minuten fehlt `rg-tag4-<kuerzel>` in `az group list --output table`.
