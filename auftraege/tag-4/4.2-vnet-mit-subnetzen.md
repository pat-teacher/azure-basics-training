# Auftrag 4.2: VNet mit zwei Subnetzen

Zeit: 30 Min. · Form: Einzelarbeit

## Ziel
- Du kannst mit der Azure CLI ein VNet mit zwei Subnetzen (Subnets) erstellen. (K3)
- Du kannst eine Fehlermeldung zu überlappenden Bereichen lesen und erklären. (K2)

## Voraussetzungen
- Auftrag 4.1 erledigt
- Cloud Shell (Bash) wie in Auftrag 2.4
- Keine Ressourcengruppe (Resource Group) von Tag 3 mehr vorhanden
- Lernjournal: Ordner `tag-4/4.2-vnet-mit-subnetzen`

## Ausgangslage
Der Plan der Velo Zürich AG steht. Jetzt baust du das Netz in Azure. Du brauchst es heute den ganzen Tag: In Auftrag 4.3 stellst du VMs hinein, in Auftrag 4.4 schützt du sie.

| Was | Wert (Beispiel für `mm`) |
|-----|--------------------------|
| Ressourcengruppe (Resource Group) | `rg-tag4-mm` |
| VNet | `vnet-tag4-mm`, Adressraum (Address Space) `10.10.0.0/16` |
| Subnetz (Subnet) für Webserver | `snet-web`, `10.10.1.0/24` |
| Subnetz (Subnet) für interne Server | `snet-intern`, `10.10.2.0/24` |

Ein VNet und seine Subnetze (Subnets) kosten nichts.

## Auftrag

### Schritt 1: Ressourcengruppe erstellen
```bash
az group create --name rg-tag4-<kuerzel> --location <region> --tags kurs=azure-basics tag=4 owner=<kuerzel>
```
`<region>` ist der kurze Name deiner Kursregion, z. B. `switzerlandnorth`.

**Kontrolle:** In der Ausgabe steht `"provisioningState": "Succeeded"`.

### Schritt 2: VNet mit dem ersten Subnetz erstellen
```bash
az network vnet create --resource-group rg-tag4-<kuerzel> --name vnet-tag4-<kuerzel> --address-prefixes 10.10.0.0/16 --subnet-name snet-web --subnet-prefixes 10.10.1.0/24
```
`network vnet create` erstellt das VNet und gleich das erste Subnetz (Subnet) darin:

| Option | Bedeutung |
|--------|-----------|
| `--address-prefixes 10.10.0.0/16` | Adressraum (Address Space) des ganzen VNets |
| `--subnet-name snet-web` | Name des ersten Subnetzes (Subnet) |
| `--subnet-prefixes 10.10.1.0/24` | Bereich des ersten Subnetzes (Subnet) |

**Kontrolle:** In der Ausgabe stehen `"10.10.0.0/16"` und `"provisioningState": "Succeeded"`.

### Schritt 3: Zweites Subnetz erstellen
```bash
az network vnet subnet create --resource-group rg-tag4-<kuerzel> --vnet-name vnet-tag4-<kuerzel> --name snet-intern --address-prefixes 10.10.2.0/24
```
`network vnet subnet create` fügt einem bestehenden VNet ein Subnetz (Subnet) hinzu.

**Kontrolle:** In der Ausgabe stehen `"addressPrefix": "10.10.2.0/24"` und `"provisioningState": "Succeeded"`.

### Schritt 4: Subnetze anzeigen
```bash
az network vnet subnet list --resource-group rg-tag4-<kuerzel> --vnet-name vnet-tag4-<kuerzel> --query "[].{Name:name, Bereich:addressPrefix}" --output table
```
`--query` wählt nur Name und Bereich aus, wie in Auftrag 2.4.

**Kontrolle:**
```text
Name         Bereich
-----------  ------------
snet-web     10.10.1.0/24
snet-intern  10.10.2.0/24
```

### Schritt 5: Absichtlich Fehler machen
Azure prüft jeden neuen Bereich. Probiere zwei falsche Subnetze (Subnets) aus. Beide Befehle **sollen** scheitern.

1. Ein Bereich, der mit `snet-web` überlappt (wie in Auftrag 4.1, Schritt 5):
   ```bash
   az network vnet subnet create --resource-group rg-tag4-<kuerzel> --vnet-name vnet-tag4-<kuerzel> --name snet-test --address-prefixes 10.10.1.128/25
   ```
2. Ein Bereich ausserhalb des Adressraums (Address Space):
   ```bash
   az network vnet subnet create --resource-group rg-tag4-<kuerzel> --vnet-name vnet-tag4-<kuerzel> --name snet-test --address-prefixes 10.20.1.0/24
   ```

**Kontrolle:** Beide Male erscheint eine Fehlermeldung, die mit `(Netcfg…)` beginnt. Kopiere den Fehlercode (das Wort in der Klammer) ins Lernjournal. <!-- prüfen: Fehlercodes NetcfgSubnetRangesOverlap und NetcfgSubnetRangeOutsideVnet -->

### Schritt 6: Im Portal nachschauen
1. Öffne im Portal das VNet `vnet-tag4-<kuerzel>`.
2. Klicke links unter **Einstellungen** (Settings) auf **Subnetze** (Subnets).

**Kontrolle:** Du siehst `snet-web` und `snet-intern`, aber kein `snet-test`. In der Spalte **Verfügbare IPs** (Available IPs) steht bei beiden `251`.

### Schritt 7: Fragen
Beantworte im Lernjournal.
1. Warum stehen bei **Verfügbare IPs** (Available IPs) 251 und nicht 256? Antworte in einem Satz.
2. Kreuze an: Die Velo Zürich AG will ein drittes Subnetz (Subnet) `snet-admin`. Welcher Bereich funktioniert?
   - [ ] `10.10.2.0/29`
   - [ ] `10.10.3.0/29`
   - [ ] `10.11.0.0/29`
3. Ordne deine zwei Fehlercodes aus Schritt 5 zu:

   | Fehlercode | Der Bereich überlappt mit einem anderen Subnetz (Subnet). | Der Bereich liegt nicht im Adressraum (Address Space) des VNets. |

   | 1. Befehl: | | |
   | 2. Befehl: | | |

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `ResourceGroupNotFound` | Schritt 1 fehlt oder `<kuerzel>` ist nicht überall gleich. |
| `syntax error near unexpected token` | Platzhalter `<kuerzel>` nicht ersetzt. Die spitzen Klammern müssen weg. |
| In Schritt 5 klappt der Befehl doch | Du hast einen anderen Bereich getippt. Lösche das Subnetz (Subnet) wieder: `az network vnet subnet delete --resource-group rg-tag4-<kuerzel> --vnet-name vnet-tag4-<kuerzel> --name snet-test` |

## Aufräumen
**Noch nicht aufräumen.** Du brauchst das VNet in den Aufträgen 4.3 bis 4.5. Gelöscht wird am Ende von Auftrag 4.5.
