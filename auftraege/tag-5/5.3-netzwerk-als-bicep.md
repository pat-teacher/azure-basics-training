# Auftrag 5.3: Das Netzwerk von Tag 4 als Bicep

Zeit: 45 Min. · Form: Einzelarbeit

## Ziel
- Du kannst VNet, Subnetze (Subnets) und eine NSG mit Sicherheitsregeln (Security Rules) in Bicep beschreiben und bereitstellen. (K3)
- Du kannst eine Bicep-Datei erweitern und die Änderung mit `what-if` prüfen. (K3)
- Du kannst Ressourcengruppe (Resource Group) und Netzwerk mit einem Befehl `az deployment sub` bereitstellen. (K3)

## Voraussetzungen
- Auftrag 5.2 erledigt, du brauchst `main.bicep` aus 5.2, Schritt 9
- Die öffentliche IP (Public IP) der Schule (steht an der Wandtafel, wie an Tag 4)
- Theorie zum Nachlesen: [Kapitel 6 Azure Networking](../../theorie/06-azure-networking.md) und [Kapitel 7 Automatisierung](../../theorie/07-automatisierung.md)
- Lernjournal: Ordner `tag-5/5.3-netzwerk-als-bicep`

## Ausgangslage
An Tag 4 hast du das Netz der Velo Zürich AG mit sechs einzelnen Befehlen gebaut: VNet, zweites Subnetz (Subnet), NSG, zwei Sicherheitsregeln (Security Rules), Verknüpfung. Heute beschreibst du dasselbe Netz in **einer** Datei `network.bicep`. Wie in 5.2 kommt eine `main.bicep` dazu, die die Ressourcengruppe (Resource Group) erstellt. Du stellst alles mit **einem** Befehl `az deployment sub` bereit. Im Abschlussprojekt kommt dann die VM dazu.

## Auftrag

### Schritt 1: Netzwerk in Bicep beschreiben
Lege im Ordner `azure-tag5` einen Ordner `5.3` an und darin die Datei `network.bicep` mit diesem Inhalt:
```bicep
param location string = resourceGroup().location
param kuerzel string
param schulIp string

resource nsg 'Microsoft.Network/networkSecurityGroups@2023-09-01' = {
  name: 'nsg-web'
  location: location
  properties: {
    securityRules: [
      {
        name: 'allow-http'
        properties: {
          priority: 200
          direction: 'Inbound'
          access: 'Allow'
          protocol: 'Tcp'
          sourceAddressPrefix: 'Internet'
          sourcePortRange: '*'
          destinationAddressPrefix: '*'
          destinationPortRange: '80'
        }
      }
      {
        name: 'allow-ssh'
        properties: {
          priority: 1000
          direction: 'Inbound'
          access: 'Allow'
          protocol: 'Tcp'
          sourceAddressPrefix: '${schulIp}/32'
          sourcePortRange: '*'
          destinationAddressPrefix: '*'
          destinationPortRange: '22'
        }
      }
    ]
  }
}

resource vnet 'Microsoft.Network/virtualNetworks@2023-09-01' = {
  name: 'vnet-tag5-${kuerzel}'
  location: location
  properties: {
    addressSpace: {
      addressPrefixes: [
        '10.10.0.0/16'
      ]
    }
    subnets: [
      {
        name: 'snet-web'
        properties: {
          addressPrefix: '10.10.1.0/24'
          networkSecurityGroup: {
            id: nsg.id
          }
        }
      }
      {
        name: 'snet-intern'
        properties: {
          addressPrefix: '10.10.2.0/24'
        }
      }
    ]
  }
}

output vnetName string = vnet.name
```
Speichere und wechsle im Terminal in den Ordner:
```powershell
cd $HOME\azure-tag5\5.3
```

Vergleiche mit Tag 4:

| Tag 4 (Azure CLI, Auftrag 4.2 bis 4.4) | Hier in `network.bicep` |
|----------------------------------------|-------------------------|
| `az network nsg create … --name nsg-web` | `resource nsg …` |
| `az network nsg rule create … --name allow-http …` | Eintrag `allow-http` unter `securityRules` |
| `az network vnet create … --address-prefixes 10.10.0.0/16` | `resource vnet …` mit `addressPrefixes` |
| `az network vnet subnet create … --name snet-intern` | Eintrag `snet-intern` unter `subnets` |
| `az network vnet subnet update … --network-security-group nsg-web` | `networkSecurityGroup: { id: nsg.id }` |

Die Felder einer Sicherheitsregel (Security Rule) kennst du aus Kapitel 6:

| Feld in Bicep | Bedeutung |
|---------------|-----------|
| `priority`, `direction`, `access`, `protocol` | Priorität (Priority), Richtung, Allow/Deny, Protokoll |
| `sourceAddressPrefix` | Quelle (Source): `Internet` oder eine Adresse mit Präfix |
| `sourcePortRange: '*'` | Port auf der Seite der Quelle: beliebig. `*` heisst «alle». |
| `destinationAddressPrefix: '*'` | Ziel (Destination): alle Adressen im Subnetz (Subnet) |
| `destinationPortRange` | Zielport (Destination Port), z. B. `'80'` |

`nsg.id` verweist auf die NSG weiter oben. Daran erkennt Bicep, dass die NSG **vor** dem VNet entstehen muss. Die Reihenfolge musst du nicht selbst festlegen.

**Kontrolle:** Keine rote Wellenlinie in der Datei.

### Schritt 2: main.bicep für die Ressourcengruppe
Kopiere `main.bicep` aus dem Ordner `5.2` in den Ordner `5.3`. Ersetze den Inhalt durch diese Version:
```bicep
targetScope = 'subscription'

param location string = deployment().location
param kuerzel string
param schulIp string

resource rg 'Microsoft.Resources/resourceGroups@2022-09-01' = {
  name: 'rg-tag5-${kuerzel}'
  location: location
  tags: {
    kurs: 'azure-basics'
    tag: '5'
    owner: kuerzel
  }
}

module network 'network.bicep' = {
  name: 'network-${kuerzel}'
  scope: rg
  params: {
    location: location
    kuerzel: kuerzel
    schulIp: schulIp
  }
}

output vnetName string = network.outputs.vnetName
```

Gegenüber `main.bicep` aus 5.2 hat sich nur wenig geändert:

| Stelle | 5.2 | 5.3 |
|--------|-----|-----|
| aufgerufene Datei | `module storage 'storage.bicep'` | `module network 'network.bicep'` |
| Parameter | `kuerzel` | `kuerzel` und neu `schulIp` |
| `params: { … }` | `location`, `kuerzel` | dazu `schulIp: schulIp` |
| `output` | `blobUrl` | `vnetName` |

Jeder `param` in `network.bicep` ohne Standardwert muss in `main.bicep` unter `params` stehen. Darum gibt `main.bicep` `schulIp` weiter.

**Kontrolle:** Im Ordner `5.3` liegen `main.bicep` und `network.bicep`, beide ohne rote Wellenlinie.

### Schritt 3: Vorschau
Ersetze `<schul-ip>` durch die Adresse an der Wandtafel, z. B. `198.51.100.23` (ohne `/32`, das ergänzt die Datei).
```powershell
az deployment sub what-if --location <region> --template-file main.bicep --parameters kuerzel=<kuerzel> schulIp=<schul-ip>
```

**Kontrolle:** Zwei Zeilen mit `+`: `networkSecurityGroups/nsg-web` und `virtualNetworks/vnet-tag5-<kuerzel>`. Die Ressourcengruppe (Resource Group) `rg-tag5-<kuerzel>` erscheint mit `=` (bleibt gleich), wenn sie aus 5.2 noch existiert, sonst mit `+`. Das Speicherkonto (Storage Account) aus 5.2 erscheint mit `*` (Ignore): Es steht nicht in der Datei, darum lässt Azure es in Ruhe und löscht es nicht. <!-- prüfen: Darstellung von Ressourcengruppe und nicht beschriebenen Ressourcen in what-if auf Ebene Abonnement -->

### Schritt 4: Bereitstellen
```powershell
az deployment sub create --location <region> --template-file main.bicep --parameters kuerzel=<kuerzel> schulIp=<schul-ip> --query properties.provisioningState
```

**Kontrolle:** Die Ausgabe ist `"Succeeded"`.

### Schritt 5: Prüfen wie an Tag 4
```powershell
az network vnet subnet list --resource-group rg-tag5-<kuerzel> --vnet-name vnet-tag5-<kuerzel> --query "[].{Name:name, Bereich:addressPrefix}" --output table
az network nsg rule list --resource-group rg-tag5-<kuerzel> --nsg-name nsg-web --output table
```

**Kontrolle:** Zwei Subnetze (Subnets), `snet-web` mit `10.10.1.0/24` und `snet-intern` mit `10.10.2.0/24`. In der NSG `allow-http` (200) und `allow-ssh` (1000) mit deiner Schul-IP.

### Schritt 6: Ein drittes Subnetz
Die Velo Zürich AG braucht das Subnetz (Subnet) `snet-admin` mit `10.10.3.0/29` (aus Auftrag 4.2, Frage 2). Ergänze in `network.bicep` unter `subnets` nach dem Eintrag `snet-intern` einen dritten Eintrag. Er hat denselben Aufbau wie `snet-intern`: Name und `addressPrefix`.

<details><summary>Hilfe: So sieht der neue Eintrag aus</summary>

```bicep
      {
        name: 'snet-admin'
        properties: {
          addressPrefix: '10.10.3.0/29'
        }
      }
```
</details>

Prüfe zuerst mit `what-if` (Befehl aus Schritt 3), dann stelle bereit (Befehl aus Schritt 4). Du änderst nur `network.bicep`, der Befehl bleibt gleich.

**Kontrolle:** `what-if` zeigt `~ Microsoft.Network/virtualNetworks/vnet-tag5-<kuerzel>` und darin den neuen Eintrag `snet-admin`. Nach dem Bereitstellen zeigt der erste Befehl aus Schritt 5 drei Subnetze (Subnets).

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `InvalidTemplate` oder rote Wellenlinie | Klammer oder Einrückung falsch. In Bicep steht jedes Element einer Liste `[ … ]` auf einer eigenen Zeile, ohne Komma. |
| `SecurityRuleInvalidAddressPrefix` | `schulIp` mit `/32` angegeben, dann steht in der Datei `/32/32`. Nur die Adresse angeben. |
| `NetcfgSubnetRangesOverlap` | Bereich von `snet-admin` überlappt. Genau `10.10.3.0/29` verwenden. |
| `what-if` will etwas löschen (`-`) | Datei nicht gespeichert (`Ctrl` + `S`). Bicep löscht nichts, was nicht in der Datei steht. |
| Fehler, dass `schulIp` fehlt | `schulIp` fehlt in `main.bicep` oben als `param` oder unter `params`. |
| Fehler zu `targetScope` oder `resourceGroup()` | Falsche Datei im Befehl. Mit `az deployment sub` immer `--template-file main.bicep`. |
| `InvalidDeploymentLocation` | Bei `--location` eine andere Region als in 5.2 angegeben. Dieselbe Region verwenden. |

## Aufräumen
```powershell
az group delete --name rg-tag5-<kuerzel> --yes --no-wait
```
Damit sind auch das Speicherkonto (Storage Account) aus 5.2 und das Netz aus 5.3 weg. Deine Bicep-Dateien bleiben auf dem Laptop. Im Abschlussprojekt brauchst du `main.bicep` und `network.bicep` wieder.

**Kontrolle:** Nach 3–5 Minuten fehlt `rg-tag5-<kuerzel>` in `az group list --output table`.
