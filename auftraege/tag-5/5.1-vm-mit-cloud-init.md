# Auftrag 5.1: Ubuntu-VM mit cloud-init in Azure

Zeit: 45 Min. · Form: Partnerarbeit (jede Person in ihrem eigenen Abonnement (Subscription))

## Ziel
- Du kannst einer Azure-VM beim Erstellen eine cloud-init-Datei mitgeben. (K3)
- Du kannst mit `cloud-init status` prüfen, ob die Einrichtung geklappt hat. (K3)

## Voraussetzungen
- Auftrag 4.8 erledigt: Azure CLI und Visual Studio Code auf deinem Laptop, `az account show --output table` zeigt **Azure for Students**
- Dein SSH-Schlüssel aus Auftrag 1.6 (`~\.ssh\id_ed25519.pub`)
- Theorie zum Nachlesen: [Kapitel 7 Automatisierung](../../theorie/07-automatisierung.md), Abschnitt «cloud-init»
- Lernjournal: Ordner `tag-5/5.1-vm-mit-cloud-init`

## Ausgangslage
In Auftrag 3.3 hast du nginx von Hand auf eine VM installiert: anmelden, `apt update`, `apt install`, Startseite schreiben, Port öffnen. Die Velo Zürich AG will das nicht bei jedem Server wiederholen. Mit **cloud-init** richtet sich die VM beim ersten Start selbst ein. Das kennst du schon von Multipass (Auftrag 1.5). In Azure funktioniert es gleich.

Heute arbeitest du nicht in der Cloud Shell, sondern im **Terminal von Visual Studio Code** auf deinem Laptop. So bleiben deine Dateien gespeichert.

> [!TIP]
> **So arbeitet ihr zu zweit:** Jede Person baut im eigenen Abonnement (Subscription). Ihr sitzt nebeneinander, macht jeden Schritt gleichzeitig und vergleicht nach jeder **Kontrolle**.

## Auftrag

### Schritt 1: Arbeitsordner anlegen
1. Starte Visual Studio Code und öffne ein Terminal: Menü **Terminal** > **New Terminal**.
2. Lege den Ordner für den ganzen Tag an:
   ```powershell
   mkdir $HOME\azure-tag5\5.1
   ```
3. Öffne den Ordner in Visual Studio Code: Menü **File** > **Open Folder**, wähle `azure-tag5` in deinem Benutzerordner und klicke auf **Select Folder**. Bestätige die Frage nach dem Vertrauen mit **Yes, I trust the authors**.
4. Öffne wieder ein Terminal (**Terminal** > **New Terminal**) und wechsle in den Unterordner:
   ```powershell
   cd 5.1
   ```

**Kontrolle:** Links im Explorer siehst du `AZURE-TAG5` mit dem Unterordner `5.1`. Die Eingabezeile im Terminal endet mit `azure-tag5\5.1>`.

### Schritt 2: cloud-init-Datei schreiben
1. Klicke im Explorer mit der rechten Maustaste auf den Ordner `5.1` > **New File** und nenne die Datei `cloud-init.yaml`.
2. Kopiere diesen Inhalt hinein. Ersetze `<kuerzel>` durch dein Kürzel:
   ```yaml
   #cloud-config
   package_update: true
   packages:
     - nginx
   write_files:
     - path: /var/www/html/index.html
       content: |
         <meta charset="utf-8">
         <h1>Velo Zürich AG</h1>
         <p>Webserver von <kuerzel>, eingerichtet mit cloud-init</p>
   ```
3. Speichere mit `Ctrl` + `S`.

| Block | Bedeutung |
|-------|-----------|
| `#cloud-config` | muss die erste Zeile sein, sonst passiert gar nichts |
| `package_update`, `packages` | Paketliste aktualisieren und nginx installieren |
| `write_files` | die Startseite von nginx schreiben |

**Kontrolle:** Die erste Zeile ist genau `#cloud-config`. Die Zeilen sind mit **Leerzeichen** eingerückt, nicht mit Tabs. Unten rechts in Visual Studio Code steht `YAML`.

### Schritt 3: Ressourcengruppe erstellen (Terminal)
```powershell
az group create --name rg-tag5-ci-<kuerzel> --location <region> --tags kurs=azure-basics tag=5 owner=<kuerzel>
```

**Kontrolle:** In der Ausgabe steht `"provisioningState": "Succeeded"`.

### Schritt 4: VM mit cloud-init erstellen (Terminal)
```powershell
az vm create --resource-group rg-tag5-ci-<kuerzel> --name vm-web-<kuerzel> --image Ubuntu2404 --size Standard_B1s --admin-username azureuser --ssh-key-values $HOME\.ssh\id_ed25519.pub --public-ip-sku Standard --custom-data cloud-init.yaml
```
Den Befehl kennst du aus Auftrag 3.3. Neu ist:

| Option | Bedeutung |
|--------|-----------|
| `--ssh-key-values $HOME\.ssh\id_ed25519.pub` | Die Azure CLI liest deinen öffentlichen Schlüssel (Public Key) direkt aus der Datei auf deinem Laptop. |
| `--custom-data cloud-init.yaml` | Die Datei geht als benutzerdefinierte Daten (Custom Data) an die VM. cloud-init liest sie beim ersten Start. |

**Kontrolle:** Die Ausgabe enthält `"powerState": "VM running"` und eine `"publicIpAddress"`. Notiere die Adresse.

### Schritt 5: Port 80 öffnen (Terminal)
```powershell
az vm open-port --resource-group rg-tag5-ci-<kuerzel> --name vm-web-<kuerzel> --port 80
```

**Kontrolle:** Die Ausgabe enthält `"destinationPortRange": "80"`.

### Schritt 6: Website öffnen
Warte 2–3 Minuten. cloud-init installiert im Hintergrund noch nginx. Öffne dann im Browser `http://<öffentliche-ip>`.

**Kontrolle:** Du siehst «Velo Zürich AG» und deine Zeile mit deinem Kürzel. Lädt die Seite nicht oder meldet der Browser «Verbindung abgelehnt», ist cloud-init noch nicht fertig: 1 Minute warten und neu laden.

### Schritt 7: In der VM nachschauen
Melde dich an (im Terminal von Visual Studio Code):
```powershell
ssh azureuser@<öffentliche-ip>
```
In der VM:
```bash
cloud-init status --long
sudo tail -n 5 /var/log/cloud-init-output.log
exit
```
`cloud-init status --long` zeigt, ob cloud-init fertig ist. Das Log zeigt, was cloud-init gemacht hat.

**Kontrolle:** Bei `status` steht `done`. Die letzte Zeile im Log beginnt mit `Cloud-init v.` und endet mit `finished at …`.

### Schritt 8: Fragen
Beantworte im Lernjournal.
1. Wie viele Befehle hast du in Auftrag 3.3 **in der VM** getippt, um den Webserver einzurichten? Wie viele heute? Antworte in einem Satz.
2. Kreuze an: Du änderst `cloud-init.yaml` und startest die VM neu. Was passiert?
   - [ ] cloud-init richtet die VM mit der neuen Datei ein.
   - [ ] Nichts. cloud-init läuft nur beim ersten Start.
   - [ ] Die VM startet nicht mehr.
3. Kreuze an: Die VM läuft, aber die Website lädt auch nach 10 Minuten nicht. Was prüfst du zuerst?
   - [ ] die erste Zeile `#cloud-config` und die Einrückung
   - [ ] die Grösse der VM
   - [ ] die Region

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `az` wird nicht erkannt | Auftrag 4.8 nicht fertig. Visual Studio Code neu starten oder mit dem Partner arbeiten. |
| `Please run 'az login'` | `az login`, dann `az account show --output table` |
| `An RSA key file or key value must be supplied` oder Fehler beim Schlüssel | Pfad prüfen: `Get-Content $HOME\.ssh\id_ed25519.pub` muss eine Zeile zeigen. Sonst Auftrag 1.6 nachholen. |
| `QuotaExceeded` | Es läuft noch eine VM von Tag 4: `az vm list --output table`, alte Ressourcengruppe (Resource Group) löschen. |
| Website lädt auch nach 10 Minuten nicht | In der VM `cloud-init status --long` und `sudo cat /var/log/cloud-init-output.log`. Meist fehlt `#cloud-config` oder die Einrückung stimmt nicht. Datei korrigieren, Ressourcengruppe (Resource Group) löschen und neu beginnen: cloud-init läuft nur beim ersten Start. |
| Umlaute auf der Website falsch | Die Zeile `<meta charset="utf-8">` fehlt. |

## Aufräumen
```powershell
az group delete --name rg-tag5-ci-<kuerzel> --yes --no-wait
```

**Kontrolle:** Nach 3–5 Minuten fehlt `rg-tag5-ci-<kuerzel>` in `az group list --output table`.

## Zusatzaufgabe ⭐
Ergänze in `cloud-init.yaml` unter `packages` die Zeile `  - tree` und am Schluss einen Block `runcmd`, der das Datum in eine Datei schreibt:
```yaml
runcmd:
  - date > /opt/eingerichtet-am.txt
```
cloud-init läuft nur beim ersten Start. Lösche darum die Ressourcengruppe (Resource Group) wie unter «Aufräumen» und wiederhole nach 3–5 Minuten die Schritte 3 bis 5. Prüfe in der VM mit `cat /opt/eingerichtet-am.txt` und `tree --version`. Danach räumst du nochmals auf.
