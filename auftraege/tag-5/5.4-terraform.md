# Auftrag 5.4 ⭐: Herausforderung – dieselbe Idee mit Terraform

Zeit: ca. 60 Min. · Form: Einzelarbeit, freiwillig

## Ziel
- Du kannst Terraform installieren und eine einfache Konfiguration für Azure schreiben. (K3)
- Du kannst die Befehle `init`, `plan`, `apply` und `destroy` anwenden und ihre Ausgabe lesen. (K3)
- Du kannst zwei Unterschiede zwischen Terraform und Bicep nennen. (K1)

## Voraussetzungen
- Aufträge 5.2 und 5.3 erledigt: Du kennst `what-if`, `create` und Idempotenz.
- Azure CLI, angemeldet mit `az login` (Auftrag 4.8)
- Lernjournal: Ordner `tag-5/5.4-terraform`

> [!NOTE]
> Terraform gehört nicht zum Kursinhalt. Dieser Auftrag ist ein Ausblick für alle, die mehr wollen. Er kostet fast nichts, du erstellst nur eine Ressourcengruppe (Resource Group) und ein Speicherkonto (Storage Account).

## Kurze Einführung: Was ist Terraform?
**Terraform** ist ein Werkzeug für Infrastruktur als Code (Infrastructure as Code) der Firma HashiCorp. Wie Bicep ist es **deklarativ**: Du beschreibst den Zielzustand, Terraform findet den Weg. Anders als Bicep funktioniert Terraform nicht nur mit Azure, sondern auch mit AWS, Google Cloud und vielen weiteren Diensten. Für jede Plattform gibt es einen **Provider**, für Azure heisst er `azurerm`.

Die Dateien enden auf `.tf` und sind in **HCL** geschrieben (HashiCorp Configuration Language). Terraform merkt sich in einer **State-Datei** `terraform.tfstate`, was es erstellt hat.

| | Bicep | Terraform |
|---|-------|-----------|
| Hersteller | Microsoft | HashiCorp |
| Plattformen | nur Azure | Azure, AWS, Google Cloud und viele mehr |
| Sprache, Dateien | Bicep, `.bicep` | HCL, `.tf` |
| Vorschau | `az deployment group what-if` | `terraform plan` |
| Bereitstellen | `az deployment group create` | `terraform apply` |
| Alles löschen | `az group delete` | `terraform destroy` |
| Wer kennt den Zustand? | Azure selbst | die State-Datei `terraform.tfstate` |

So läuft die Arbeit mit Terraform ab:

![Ablauf: main.tf schreiben, terraform init lädt den Provider, terraform plan vergleicht mit dem State und zeigt Änderungen, terraform apply erstellt oder ändert in Azure, terraform destroy löscht alles.](bilder/tag5-terraform-ablauf.svg)

## Die wichtigsten Befehle

| Befehl | Was er macht |
|--------|--------------|
| `terraform init` | bereitet den Ordner vor und lädt den Provider herunter. Einmal pro Ordner. |
| `terraform fmt` | rückt deine Dateien einheitlich ein |
| `terraform validate` | prüft, ob die Dateien gültig sind |
| `terraform plan` | zeigt, was Terraform ändern würde: `+` erstellen, `~` ändern, `-` löschen. Ändert nichts. |
| `terraform apply` | zeigt den Plan, fragt nach und führt ihn aus |
| `terraform output` | zeigt die Ausgabewerte |
| `terraform state list` | listet alles, was Terraform verwaltet |
| `terraform destroy` | löscht alles, was in der State-Datei steht |

## Auftrag

### Schritt 1: Terraform installieren (PowerShell)
```powershell
winget install --exact --id Hashicorp.Terraform --accept-source-agreements --accept-package-agreements
code --install-extension hashicorp.terraform
```
Die erste Zeile installiert Terraform, die zweite die Erweiterung für Visual Studio Code. Schliesse danach **alle** Terminals und öffne ein neues (**Terminal** > **New Terminal**).
```powershell
terraform -version
```

**Kontrolle:** Die Ausgabe beginnt mit `Terraform v1.`. <!-- prüfen: winget-Paket Hashicorp.Terraform auf den Kurs-Laptops -->

### Schritt 2: Konfiguration schreiben
1. Lege im Ordner `azure-tag5` einen Ordner `5.4` an und darin die Datei `main.tf`:
   ```hcl
   terraform {
     required_providers {
       azurerm = {
         source  = "hashicorp/azurerm"
         version = "~> 4.0"
       }
     }
   }

   provider "azurerm" {
     features {}
     resource_provider_registrations = "none"
   }

   variable "kuerzel" {
     type = string
   }

   variable "region" {
     type    = string
     default = "switzerlandnorth"
   }

   resource "azurerm_resource_group" "rg" {
     name     = "rg-tag5-tf-${var.kuerzel}"
     location = var.region
     tags = {
       kurs  = "azure-basics"
       tag   = "5"
       owner = var.kuerzel
     }
   }

   resource "azurerm_storage_account" "st" {
     name                     = "sttag5tf${var.kuerzel}"
     resource_group_name      = azurerm_resource_group.rg.name
     location                 = azurerm_resource_group.rg.location
     account_tier             = "Standard"
     account_replication_type = "LRS"
   }

   output "blob_endpoint" {
     value = azurerm_storage_account.st.primary_blob_endpoint
   }
   ```
2. Ist deine Kursregion nicht `switzerlandnorth`, ändere den Standardwert bei `variable "region"`.
3. Wechsle im Terminal in den Ordner:
   ```powershell
   cd $HOME\azure-tag5\5.4
   ```

| Block | Bedeutung | In Bicep |
|-------|-----------|----------|
| `terraform { required_providers … }` | welcher Provider in welcher Version | – (Bicep kennt nur Azure) |
| `provider "azurerm"` | Einstellungen für Azure. `resource_provider_registrations = "none"` verhindert, dass Terraform im Abonnement (Subscription) Dienste anmelden will. | – |
| `variable "kuerzel"` | Eingabewert | `param kuerzel string` |
| `resource "azurerm_resource_group" "rg"` | Typ und Name in der Datei | `resource rg '…'` |
| `azurerm_resource_group.rg.name` | Verweis auf eine andere Ressource, legt die Reihenfolge fest | `rg.name` |
| `output` | Ausgabewert | `output` |

Anders als in Bicep erstellt Terraform hier auch die Ressourcengruppe (Resource Group) selbst.

**Kontrolle:** Die Datei ist farbig hervorgehoben (Erweiterung HashiCorp Terraform).

### Schritt 3: Terraform mit deinem Abonnement verbinden (PowerShell)
Terraform verwendet deine Anmeldung aus `az login`. Es braucht zusätzlich die ID deines Abonnements (Subscription). Du gibst sie als Umgebungsvariable mit, damit sie nicht in der Datei steht:
```powershell
$env:ARM_SUBSCRIPTION_ID = (az account show --query id --output tsv)
echo $env:ARM_SUBSCRIPTION_ID
```
Die Variable gilt nur in diesem Terminal. Öffnest du ein neues, wiederholst du diesen Schritt.

**Kontrolle:** Die Ausgabe ist eine lange ID mit Bindestrichen, z. B. `1a2b3c4d-…`.

### Schritt 4: init
```powershell
terraform init
```

**Kontrolle:** Grün steht `Terraform has been successfully initialized!`. Im Explorer erscheinen der Ordner `.terraform` und die Datei `.terraform.lock.hcl`.

### Schritt 5: fmt und validate
```powershell
terraform fmt
terraform validate
```

**Kontrolle:** `validate` meldet `Success! The configuration is valid.`

### Schritt 6: plan
```powershell
terraform plan -var="kuerzel=<kuerzel>"
```
`-var` übergibt den Wert für `variable "kuerzel"`. Das entspricht `--parameters kuerzel=…` bei Bicep.

**Kontrolle:** Zwei Blöcke beginnen mit `+`. Eine Zeile lautet `Plan: 2 to add, 0 to change, 0 to destroy.` Den Hinweis zur Option `-out` darunter kannst du ignorieren.

### Schritt 7: apply
```powershell
terraform apply -var="kuerzel=<kuerzel>"
```
Terraform zeigt den Plan nochmals und fragt `Enter a value:`. Tippe `yes` und drücke `Enter`.

**Kontrolle:** `Apply complete! Resources: 2 added, 0 changed, 0 destroyed.` Darunter steht `blob_endpoint = "https://sttag5tf<kuerzel>.blob.core.windows.net/"`.

### Schritt 8: Nachschauen
```powershell
terraform state list
terraform output
az group show --name rg-tag5-tf-<kuerzel> --query tags
```

**Kontrolle:** `state list` zeigt `azurerm_resource_group.rg` und `azurerm_storage_account.st`. Die Tags sind dieselben wie in `main.tf`. Im Explorer liegt jetzt `terraform.tfstate`.

> [!WARNING]
> `terraform.tfstate` enthält alle Eigenschaften deiner Ressourcen, auch geheime wie die Zugriffsschlüssel (Access Keys) des Speicherkontos (Storage Account). Kopiere sie **nie** ins Lernjournal oder in ein Git-Repository.

### Schritt 9: Eine Änderung
Ergänze in `main.tf` bei der Ressourcengruppe (Resource Group) unter `tags` die Zeile:
```hcl
       umgebung = "test"
```
Speichere und schau dir den Plan an:
```powershell
terraform plan -var="kuerzel=<kuerzel>"
```

**Kontrolle:** Ein Block beginnt mit `~` (update in-place), darin `+ "umgebung" = "test"`. Eine Zeile lautet `Plan: 0 to add, 1 to change, 0 to destroy.`

Führe die Änderung mit `terraform apply -var="kuerzel=<kuerzel>"` aus und bestätige mit `yes`. Führe danach `terraform plan -var="kuerzel=<kuerzel>"` nochmals aus.

**Kontrolle:** Der zweite Plan meldet `No changes. Your infrastructure matches the configuration.` Wie bei Bicep: idempotent.

### Schritt 10: destroy
```powershell
terraform destroy -var="kuerzel=<kuerzel>"
```
Tippe `yes`.

**Kontrolle:** `Destroy complete! Resources: 2 destroyed.` und `az group list --output table` zeigt `rg-tag5-tf-<kuerzel>` nicht mehr.

### Schritt 11: Fragen
Beantworte im Lernjournal.
1. Ordne zu: Welcher Terraform-Befehl entspricht welchem Bicep- bzw. CLI-Befehl?

   | Terraform | Bicep / Azure CLI |
   |-----------|-------------------|
   | `terraform plan` | |
   | `terraform apply` | |
   | `terraform destroy` | |

2. Kreuze an: Du löschst die Datei `terraform.tfstate` und führst `terraform plan` aus, obwohl die Ressourcen in Azure noch existieren. Was zeigt der Plan?
   - [ ] `No changes`, weil Terraform in Azure nachschaut.
   - [ ] `2 to add`, weil Terraform nicht mehr weiss, dass es die Ressourcen schon erstellt hat.
   - [ ] `2 to destroy`
3. Kreuze an: Die Velo Zürich AG nutzt Azure und zusätzlich AWS. Welches Werkzeug passt für beide?
   - [ ] Bicep, weil es von Microsoft ist
   - [ ] Terraform, weil es mit Providern für viele Plattformen arbeitet
   - [ ] keines, man braucht für jede Cloud ein eigenes Werkzeug

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `terraform` wird nicht erkannt | Alle Terminals schliessen, neues öffnen. Hilft das nicht: Visual Studio Code neu starten. |
| `subscription ID could not be determined` | Schritt 3 im aktuellen Terminal wiederholen. |
| `could not acquire access token` oder `Please run 'az login'` | `az login`, dann Schritt 3 wiederholen. |
| `StorageAccountAlreadyTaken` | Name vergeben. In `main.tf` beim Speicherkonto (Storage Account) zwei Ziffern anhängen: `"sttag5tf${var.kuerzel}07"`. |
| `RequestDisallowedByPolicy` | Region nicht erlaubt. Bei `variable "region"` deine Kursregion aus Auftrag 2.2 eintragen. |
| `Error acquiring the state lock` | Ein anderer Terraform-Befehl läuft noch oder wurde abgebrochen. Warten. Hilft das nicht, Kursleitung fragen. |
| `terraform destroy` vergessen, Ordner gelöscht | Ressourcengruppe (Resource Group) mit `az group delete --name rg-tag5-tf-<kuerzel> --yes` löschen. |
