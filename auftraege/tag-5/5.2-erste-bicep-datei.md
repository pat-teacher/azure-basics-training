# Auftrag 5.2: Erste Bicep-Datei – ein Speicherkonto

Zeit: 45 Min. · Form: Einzelarbeit

## Ziel
- Du kannst eine Bicep-Datei lesen und mit der Azure CLI bereitstellen. (K3)
- Du kannst mit `what-if` vorhersagen, was eine Bereitstellung (Deployment) ändert. (K3)
- Du kannst an einem Beispiel zeigen, dass Bicep idempotent ist und zu einem ARM-Template wird. (K2)

## Voraussetzungen
- Auftrag 5.1 erledigt, Ordner `azure-tag5` in Visual Studio Code geöffnet
- Bicep-Erweiterung aus Auftrag 4.8
- Theorie zum Nachlesen: [Kapitel 7 Automatisierung](../../theorie/07-automatisierung.md), Abschnitt «ARM-Templates und Bicep»
- Lernjournal: Ordner `tag-5/5.2-erste-bicep-datei`

## Ausgangslage
An Tag 3 hast du ein Speicherkonto (Storage Account) im Portal erstellt. Heute beschreibst du es in einer **Bicep-Datei**. Du schreibst nicht, **wie** Azure es erstellen soll. Du schreibst, **was** am Schluss da sein soll. Azure vergleicht das mit dem, was schon existiert, und macht nur, was fehlt.

## Auftrag

### Schritt 1: Bicep-Datei anlegen
1. Lege im Explorer von Visual Studio Code im Ordner `azure-tag5` einen Ordner `5.2` an (Rechtsklick > **New Folder**).
2. Lege darin die Datei `main.bicep` an und kopiere diesen Inhalt hinein:
   ```bicep
   param location string = resourceGroup().location
   param kuerzel string

   resource st 'Microsoft.Storage/storageAccounts@2023-05-01' = {
     name: 'sttag5bicep${kuerzel}'
     location: location
     sku: { name: 'Standard_LRS' }
     kind: 'StorageV2'
   }

   output blobUrl string = st.properties.primaryEndpoints.blob
   ```
3. Speichere mit `Ctrl` + `S`.
4. Wechsle im Terminal in den Ordner:
   ```powershell
   cd $HOME\azure-tag5\5.2
   ```

| Zeile | Bedeutung |
|-------|-----------|
| `param kuerzel string` | Eingabewert. Du gibst ihn beim Bereitstellen mit. |
| `param location … = resourceGroup().location` | Eingabewert mit Standardwert: die Region der Ressourcengruppe (Resource Group) |
| `resource st '…storageAccounts@2023-05-01'` | Diese Ressource soll existieren. `st` ist der Name in der Datei, `2023-05-01` die API-Version. |
| `'sttag5bicep${kuerzel}'` | `${…}` setzt den Wert von `kuerzel` in den Text ein. |
| `output blobUrl` | Wert, den Azure nach der Bereitstellung (Deployment) ausgibt |

**Kontrolle:** Die Datei ist farbig hervorgehoben, und es gibt keine rote Wellenlinie. Fährst du mit der Maus über `storageAccounts`, zeigt die Bicep-Erweiterung eine Erklärung.

### Schritt 2: Ressourcengruppe erstellen
```powershell
az group create --name rg-tag5-<kuerzel> --location <region> --tags kurs=azure-basics tag=5 owner=<kuerzel>
```

**Kontrolle:** `"provisioningState": "Succeeded"`.

### Schritt 3: Vorschau mit what-if
`what-if` zeigt, was passieren **würde**, ohne etwas zu ändern.
```powershell
az deployment group what-if --resource-group rg-tag5-<kuerzel> --template-file main.bicep --parameters kuerzel=<kuerzel>
```

**Kontrolle:** Die Ausgabe zeigt eine Zeile mit `+ Microsoft.Storage/storageAccounts/sttag5bicep<kuerzel>` und am Schluss `Resource changes: 1 to create.`

### Schritt 4: Bereitstellen
```powershell
az deployment group create --resource-group rg-tag5-<kuerzel> --template-file main.bicep --parameters kuerzel=<kuerzel> --query properties.outputs
```
`--query properties.outputs` zeigt nur die Ausgabewerte statt des ganzen JSON.

**Kontrolle:** Die Ausgabe zeigt `blobUrl` mit dem Wert `https://sttag5bicep<kuerzel>.blob.core.windows.net/`.

### Schritt 5: Nochmals ausführen
Führe **genau denselben** Befehl wie in Schritt 4 nochmals aus. Ein Skript mit vielen einzelnen CLI-Befehlen müsstest du dafür so schreiben, dass es mit schon vorhandenen Ressourcen umgehen kann. Bicep macht das von selbst.

**Kontrolle:** Kein Fehler, dieselbe Ausgabe. Azure hat nichts geändert, weil der Zielzustand schon erreicht ist. Diese Eigenschaft heisst **Idempotenz**.

### Schritt 6: Etwas ändern
Die Velo Zürich AG will ihre Daten in zwei Regionen sichern (Input 5, Redundanz (Redundancy)). Ändere in `main.bicep` die Zeile mit `sku` auf:
```bicep
  sku: { name: 'Standard_GRS' }
```
Speichere und schau dir zuerst die Vorschau an:
```powershell
az deployment group what-if --resource-group rg-tag5-<kuerzel> --template-file main.bicep --parameters kuerzel=<kuerzel>
```

**Kontrolle:** Die Ausgabe zeigt `~ Microsoft.Storage/storageAccounts/…` und darunter `sku.name: "Standard_LRS" => "Standard_GRS"`. Am Schluss steht `1 to modify`.

Stelle jetzt bereit (Befehl aus Schritt 4) und prüfe:
```powershell
az storage account show --resource-group rg-tag5-<kuerzel> --name sttag5bicep<kuerzel> --query sku.name --output tsv
```

**Kontrolle:** Die Ausgabe ist `Standard_GRS`.

### Schritt 7: Das ARM-Template dahinter
Azure versteht Bicep nicht direkt. Die Azure CLI übersetzt die Datei vorher in ein **ARM-Template** (JSON).
```powershell
az bicep build --file main.bicep
(Get-Content main.bicep).Count
(Get-Content main.json).Count
```
`az bicep build` schreibt die Übersetzung in `main.json`. `(Get-Content …).Count` zählt die Zeilen einer Datei.

**Kontrolle:** Im Explorer erscheint `main.json`. Sie hat ein Vielfaches an Zeilen. Öffne sie und such die Zeile `"type": "Microsoft.Storage/storageAccounts"`.

### Schritt 8: Fragen
Beantworte im Lernjournal.
1. Ordne die Zeichen aus der what-if-Ausgabe zu: `+`, `~`, `-`, `=`

   | Zeichen | Bedeutung |
   |---------|-----------|
   | | wird geändert |
   | | wird erstellt |
   | | bleibt gleich |
   | | wird gelöscht |

2. Kreuze an: Was bedeutet «Idempotenz»?
   - [ ] Die Datei läuft nur einmal.
   - [ ] Mehrmals ausführen ergibt dasselbe Ergebnis wie einmal ausführen.
   - [ ] Azure löscht vor jeder Bereitstellung (Deployment) alles.
3. Wie viele Zeilen hatten `main.bicep` und `main.json`? Warum schreibt man lieber Bicep? Antworte in einem Satz.

## Erwartetes Ergebnis
Im Lernjournal:

## Wenn etwas nicht klappt

| Problem | Lösung |
|---------|--------|
| `StorageAccountAlreadyTaken` | Name schon vergeben. In `main.bicep` zwei Ziffern anhängen, z. B. `'sttag5bicep${kuerzel}07'`. |
| `AccountNameInvalid` | Kürzel mit Grossbuchstaben oder Bindestrich. Nur Kleinbuchstaben und Ziffern. |
| `The system cannot find the file main.bicep` | Falscher Ordner: `cd $HOME\azure-tag5\5.2` |
| rote Wellenlinie im Editor | Tippfehler. Fahr mit der Maus darüber, die Erweiterung erklärt den Fehler. |
| `az bicep build` meldet, Bicep fehle | `az bicep install` |

## Aufräumen
**Noch nicht aufräumen**, wenn du direkt mit Auftrag 5.3 weitermachst: Das Netzwerk kommt in dieselbe Ressourcengruppe (Resource Group). Gelöscht wird am Ende von Auftrag 5.3.

Machst du jetzt eine längere Pause, lösche die Ressourcengruppe (Resource Group). Vor Auftrag 5.3 erstellst du sie dann mit Schritt 2 neu.
```powershell
az group delete --name rg-tag5-<kuerzel> --yes --no-wait
```
